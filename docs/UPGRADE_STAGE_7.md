## 1. 一条命令生成验收包

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_upgrade_acceptance --include-sdk --verify
```

不加 `--include-sdk` 时执行前四组，SDK 组明确记为 `not_run`。命令每次新建 `artifacts/acceptance/acceptance-<UTC时间>-<ID>/`，不会复用既有演示数据库。任一检查异常均记录失败，命令返回非零退出码；报告只记录异常类型，不落原始错误正文。

| 检查 | 实际验证范围 |
| --- | --- |
| retrieval | 18 条合成文本，dev 12/test 6，同一数据摘要；调用既有检索对照工具 |
| queue | 独立 SQLite 的队列故障模拟，确认过期租约拒绝及旧结果不能覆盖新结果 |
| tools | 20 个脚本场景，核对回合预留与实际脚本调用一致；固定输出对照一致 |
| shadow_api | 独立演示数据库；未登录拒绝、7 个合成任务、AI 原文引用、重试 CSRF 和原候选人详情保留 |
| sdk_loopback | 真实 SDK 对临时本地假 HTTP 服务；16 次请求、16 次预留、16 条回执一致 |

`manifest.json` 保存每组状态、报告相对路径与实际落盘字节的 SHA-256，以及已有源码版本摘要和两个验收/演示入口的文件摘要。源码摘要用于追溯，不是代码签名或防篡改证明。Windows 换行也参与报告摘要，复制报告后可重新计算核对。

每组 `report.json` 的 `quality_claim_allowed` 必须为 false；总清单固定记录 `real_model_calls=0`、`release_approved=false`。SDK 使用的是本地夹具响应，工具使用的是脚本回复，页面使用的是预计算结果，三者均不构成真实模型推理或准确率证据。

## 5. 第二轮：独立复核与 CI 验收接入

新增 `scripts.verify_upgrade_acceptance`，可在不重跑业务场景的情况下复核已有验收包：

```powershell
.\.venv\Scripts\python.exe -m scripts.verify_upgrade_acceptance artifacts/acceptance/acceptance-20261105T061415Z-e2b7e9c5/manifest.json --require-sdk --check-source
```

新生成命令支持 `--verify`，写完同一次验收清单后立即复核。`--require-sdk` 要求五组全部通过；省略时只允许 SDK 以规定理由跳过，其余四组必须通过。`--check-source` 对比本机入口字节摘要与实现源码树摘要；省略时只检查归档本身，适用于源码已经修改后的历史报告。

复核检查固定的五组名称、状态、报告路径、实际字节 SHA-256、质量/发布声明、真实调用数和未覆盖范围。缺失/重复检查、报告缺失/改动、重复 JSON 字段、非法 JSON 常量、越界路径或来源不一致均使命令非零退出。仅打开约定的报告路径，并检查解析后的路径仍在包内；读取每个 JSON 的上限为 5 MB，诊断只输出固定错误码，不打印输入正文。

本轮清单升级为 schema 2，入口摘要新增复核器自身；schema 1 的旧验收包仍能复核，但只拥有原来的两个入口摘要。`--check-source` 不要求 dirty diff 与运行时相同，因为文档更新也会改变 diff；它检查明确列出的入口和 eval/src/apps/config 的既有源码摘要范围，不覆盖整个仓库。哈希只能核对文件一致性，不能识别攻击者同时改写报告和清单，也不能证明业务判断正确；通过复核不等于重新运行验收或允许发布。

CI 后端任务在 pytest 后执行 `python -m scripts.run_upgrade_acceptance --include-sdk --verify`。验收步骤运行后，即使失败也尝试留存清单和各组报告，保留 7 天；没有产物则上传步骤报错。上传通配符仅匹配 `manifest.json` 与一层检查目录的 `report.json`，不包含 SQLite、输入夹具、截图、回执明细或 `.env`。参数依据 [GitHub 官方 upload-artifact v4 定义](https://github.com/actions/upload-artifact/blob/v4/action.yml)；本轮只修改本地工作流，没有推送、触发或上传远程产物。

本轮实际验收包：[`acceptance-20261105T061415Z-e2b7e9c5/manifest.json`](../artifacts/acceptance/acceptance-20261105T061415Z-e2b7e9c5/manifest.json)。五组合成检查及随后的严格源码复核通过；上一轮 schema 1 包也通过不比较当前源码的归档复核。全量后端 **502 个用例通过**，定向测试 **27 个通过**，其中新增复核测试 25 个；两条既有 Python 依赖弃用警告仍在；工作流 YAML 与报告上传范围已在本地检查。前端未改，本轮未重跑前端或浏览器；前面的 38 个前端测试和构建结果属于上一轮记录。新机器/远程 CI/真实环境验收仍未完成。
