# 配招逐项核对开发场景

运行前固定在 `plan.json`：3条新编写功能题，各运行2次，分别检查四招和特性逐项匹配、参考不一致、草稿缺项。它们不是用户反馈、独立保留集或新增正式入集题；正式36题与原标注保持不变，人工验收待完成。

请求保留原始字段与null，检查结束不把默认配置写回表单或队伍。单条学习记录存在不证明四招共同可得、学习等级相容、遗传/回忆操作、道具效果或赛事合法性。

```powershell
node tools/campus/build-check-scenario.mjs http://127.0.0.1:18167/api artifacts/campus/build-check/NEW_OUTPUT_DIRECTORY
```

需先启动独立local,evaluation实例，启用本地账号、参考缓存与READ_ONLY_TOOLS。采集器新建专用账号及一支测试队伍，检查前后回读队伍；不访问日常8123/3000。输出目录必须不存在，采集失败也保留计划分母和原始事件。公开Pokemon/species快照来自既有离线包，模型仍真实联网；账号密码、Cookie和模型Key不写入证据。

工程检查分别绑定实际工具入参、报告摘要、每行状态、正文限制、历史/用量，并按调用ID去重终态通知；原始null在工具参数中可省略，但输出必须还原同一原配置，任何默认值补填均不能通过报告摘要核对。HTTP前后各核对3个报告，并验证未知版本400和数字字符串400。

`build-check-observations.test.mjs`覆盖错误配置/成员、冲突终态、缺少实际输入和显示行、审批或内部ID泄露。字段存在、摘要一致与重复运行通过不替代中文策略或组合合法性的人工审核。

实现与实际记录见[配招逐项核对与草稿检查](../../../document/秋招升级/S3/配招逐项核对与草稿检查_2026-10-27.md)。
