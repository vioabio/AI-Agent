# 标注与计分规范 v1

## 来源与标注

每条验收项具有稳定 criterionId、具体要求与 sourceIds。允许多种合理表达，不以某句固定措辞作为策略正确答案。首版是根据已有项目场景编写的种子集，尚待人类审阅代表性、标准答案和来源范围；不得包装成独立真实流量抽样。

事实值来自已捕获的公开图鉴字段；项目输入边界来自代码；攻略只代表项目原创笔记；伤害参考来自固定版本本地引擎。项目实现与自身参考的一致性不证明外部机制正确，尚需独立权威事实复核。当前日期、赛制合法性、当前使用率未获来源支持时应判定缺资料，不能靠常识补出“最强阵容”。

复核应分别判断：

1. **结果**：是否满足实际请求，而非只承诺下一步或无必要地追问。
2. **事实**：数字、属性、性格等是否与来源和保存配置相符；没有工具证据的机制不得标为已验证。
3. **建议**：条件是否明确，是否区分事实与推测，是否把简化计算扩大成胜率、最优性或合法性。
4. **引用**：原文、标题、作者、日期是否真实；被引用片段是否直接支持对应结论。带一个真实链接不等于整段回答有依据。
5. **流程与副作用**：归属、预览、确认、取消和回读是否正确。写入成功与建议正确独立判断。

## 四种结果

- `FAIL`：已出现确定性失败，或任一人工条目失败。
- `PENDING_REVIEW`：结构检查通过，但仍缺完整人工核对或有 unknown。
- `PASS`：必要结构检查和所有绑定的人类复核条目均通过。
- `NOT_RUN`：原始观测中的未执行状态，汇总时计入所选计划分母的失败项，保留原因，不静默删除。

每个案例与轮次在发请求前预分配一条观测。超时、空答案、接口/工具依赖失败、采集失败和未执行都在原分母内。评测器缺陷必须单列说明并保留旧报告；修复后重新生成独立报告，不能删除错误记录后宣称模型提升。

结构通过率、完整任务通过率、必要工具调用覆盖分别报告。必要工具必须有实际成功结果，只有 started 不算；权限拒绝类案例允许工具被拒绝或模型直接拒绝，不把越权读取成功列为必要工具目标。工具重试不扩大问题分母，重复事件按治理调用标识去重。

首版只自动检查约束、已知错误模式和有限数值必要条件，不做通用语义判官。未确认不变更存储是硬约束；预览测试不代替确认保存任务。正式任务成功率需对完整结果进行人工复核。问题组内的不同措辞与同一问题的重复运行都要注明，不视为独立样本。

## 复核记录

reviewerType 必须如实记录。仅人类实际填写的 `human` 复核可纳入完整人工通过数；AI 建议、辅助判断、合成测试记录不得标作真实人类验收。每条复核必须有时间、总说明、条目判定 pass/fail/unknown、理由与标注中允许的来源。观测摘要变化后旧复核失效。

reviewerType 是复核者自述，脚本只校验格式与绑定关系，不提供真人身份认证。测试用的合成 human 记录只验证解析逻辑，不作为任何真实评测成绩。

先记录失败的最小证据，再改实现。开发集用于修改与回归；保留集用于固定版本验收，发现问题后不得把原保留集的通过率当作改进版本的无偏结果。

## 性能、费用与对照

耗时采用固定案例重复运行的原始测量，失败耗时仍保留；P50/P95 使用 nearest-rank，小样本不推断生产分布。首段 answer.delta 是轮询观测上界，含网络、缓冲和证据检查，不能当供应商 TTFT。

没有真实 usage 时为 unknown，不是零 Token、零成本。费用需要实际模型、价格版本、usage 与缓存计价来源；S4 前不虚构估算账单。没有逐片段排名与相关性标注时不报 Recall@5；未逐条核验关联结论时不报引用正确率。

纯模型问答、工具增强、检索＋工具的对照必须锁定案例范围、模型参数、版本与运行条件。业务写入不与没有写能力的纯模型混算成功率。当前只实现工具增强采集，未执行的对照没有“提升百分比”。
