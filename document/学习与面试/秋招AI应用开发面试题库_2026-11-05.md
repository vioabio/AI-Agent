## 一、项目定位与讲解

### Q01【必会】请用一分钟介绍你的项目。

**回答要点**：这是本地运行的宝可梦网页 Agent，提供问答、图鉴、攻略检索、队伍配置和伤害计算。Java/Spring AI 对接模型，Vue 展示正文和任务状态，SQLite 保存本机业务数据。模型负责部分理解和工具规划，程序负责授权、确定性计算、来源核对及确认写入。重点讲一个解决过的问题，例如模型工具成功但回答仍有错误，因此需要执行、结果与内容分开校验。

**项目定位**：[README](../../README.md)、[已有讲解稿](../秋招升级/最终交付/面试与项目讲解.md)。

**追问**：最复杂的一个模块是什么？你具体改了哪段代码，如何确认修复有效？

### Q02【必会】它与“接一个大模型聊天 API”有什么区别？

**回答要点**：聊天 API 主要返回文本；本项目还需要任务身份、生命周期、实际工具执行、输入/结果记录、事件补读和受控业务写入。例如修改队伍必须读取当前配置、生成差异、等待确认、校验旧快照并保存回读。工具也不是越多越好，公开入口只暴露允许的能力。普通问候可直接回答，不需要强行走完整工具循环。

**项目定位**：[RunService](../../src/main/java/com/vio/vioaiagent/run/PokemonAgentRunService.java)、[队伍工作流](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)。

**追问**：如果去掉 Agent，只用确定性流程，哪些任务仍能完成？

### Q03【必会】为什么选择宝可梦领域，而不是通用助手？

**回答要点**：领域中同时存在结构化事实、非结构化攻略、规则条件和确定性计算，能构造可核对的业务闭环。编号、属性、种族值可用接口验证，策略问题需要来源与限制，保存配置需要确认。范围集中便于做失败分析。但宝可梦问题的通过不能推广为所有领域能力，资料和素材也有外部来源及使用边界。

**项目定位**：[资料说明](../../src/main/resources/pokemon-strategy/README.md)、[架构取舍](../秋招升级/最终交付/架构与设计取舍.md)。

**追问**：换成企业内部知识助手，哪些组件可以复用，哪些规则必须重写？

### Q04【必会】介绍整体架构，以及一次请求怎样走完整链路。

**回答要点**：前端创建 Run；Controller 规范化身份与上下文；RunService 负责幂等、状态、调度、预算和事件；DefaultRunExecutor 选择实际执行分支；Agent 请求模型规划，通过治理网关调用工具；程序核对实际结果，生成或发布公开正文；前端按游标补读并更新消息。涉及审批时暂停，由用户确认触发后续校验保存。不同任务可在部分节点提前结束。

**项目定位**：[Controller](../../src/main/java/com/vio/vioaiagent/controller/AgentRunController.java)、[执行器](../../src/main/java/com/vio/vioaiagent/run/DefaultRunExecutor.java)、[学习路线主图](项目系统学习路线_2026-11-05.md)。

**追问**：哪个组件应当持有业务权限？为什么 Controller 不直接调用模型并写数据库？

### Q05【进阶】项目算企业级 Agent 或多 Agent 系统吗？

**回答要点**：当前验收对象是单机本地网页应用，包含工具治理、幂等、审批、预算和观测等工程实践。仓库也有 OIDC、生产持久化、Redis、MCP 和多 Agent 专题代码，但不能由“存在这些类”推出本地主链默认启用、已部署或经过生产高可用验收。没有证据的 QPS、可用性、任意重启恢复不应承诺。

**项目定位**：[默认使用范围](../../README.md#数据与配置)、[恢复策略](../../src/main/java/com/vio/vioaiagent/run/RunRecoveryPolicy.java)。

**追问**：如果要多实例运行，身份、幂等、状态、审批和外部副作用分别需要解决什么？

### Q06【必会】哪些工作是你的贡献？使用 AI 辅助开发如何说明？

**回答要点**：按真实经历说明自己负责的需求拆分、源码理解、适配、边界设计、问题复现与验证，指出一个可打开的改动和对应测试。Spring AI 提供模型/工具抽象，PokéAPI 提供资料，Smogon 提供计算，不声称自研这些能力。可以如实说使用 AI 协助编写或审查，但必须独立解释实现、失败原因和取舍；不能将整个仓库历史都算个人独立完成。

**项目定位**：[面试与项目讲解](../秋招升级/最终交付/面试与项目讲解.md)、自己实际参与的 Git diff 和测试记录。

**追问**：现场删掉一段保护逻辑，你能判断会出现什么问题并写出验证用例吗？

## 二、LLM 与 Agent

### Q07【必会】LLM、RAG、Agent 和工作流有什么区别？

**回答要点**：LLM 是生成和理解组件；RAG 是先检索资料再支持回答的方法；Agent 在约束内选择工具并根据结果继续推进；工作流规定状态和步骤。项目将这些组合使用：模型可规划工具，Run 管状态，队伍保存走确定性确认流程，本地攻略提供检索来源。固定路由或事实表属于程序能力，不应算作模型自主规划成功。

**项目定位**：[ToolCallAgent](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)、[本地攻略](../../src/main/java/com/vio/vioaiagent/pokemon/guides/LocalGuideSearch.java)、[TeamWorkflowService](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)。

**追问**：什么时候应减少模型自由度，改用确定性流程？

### Q08【必会】ReAct 在项目中怎样实现？

**回答要点**：`BaseAgent` 管基本循环与状态，`ReActAgent.step()` 执行 think/act，`ToolCallAgent` 负责模型工具选择、真实调用和结果回填。模型看到结果后再决定下一步，证据足够就输出最终答案。实际实现还有预算、步数和错误边界，不是无限循环；某些明确请求会先走程序路由。这里的“思考”是内部规划，不应直接发布给用户。

**项目定位**：[BaseAgent](../../src/main/java/com/vio/vioaiagent/agent/BaseAgent.java)、[ReActAgent](../../src/main/java/com/vio/vioaiagent/agent/ReActAgent.java)、[ToolCallAgent](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)。

**追问**：模型一直调用类型图或重复搜索时，提示词和程序分别能做什么？

### Q09【必会】Tool Calling 的模型与程序各负责什么？

**回答要点**：模型产生工具名、调用 ID 和结构化参数；程序解析、授权、校验并执行回调，再将真实结果以对应工具消息返回。模型没有直接访问数据库或 API 的权限。项目关闭模型适配层的内部自动工具执行，由受控链路处理，避免工具绕过治理或重复执行。调用 ID 还用于把结果绑定到实际请求。

**项目定位**：[DeepSeekModelConfiguration](../../src/main/java/com/vio/vioaiagent/config/DeepSeekModelConfiguration.java)、[ToolCallAgent.act](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)、[治理回调](../../src/main/java/com/vio/vioaiagent/tools/governance/GovernedToolCallback.java)。

**追问**：同时打开框架自动执行和应用手工执行，会有什么风险？

### Q10【必会】为什么每次请求创建新的 Agent，不能当单例？

**回答要点**：Agent 持有消息列表、当前状态、步数、工具响应和最终正文等可变状态。并发复用会导致问题、用户资料、计数和结果串线。项目复用无会话状态或明确受控的基础设施，每次 Run 创建新的 `VioManus`。线程安全的底层客户端不代表包装它的有状态 Agent 也能共享。

**项目定位**：[DefaultRunExecutor](../../src/main/java/com/vio/vioaiagent/run/DefaultRunExecutor.java)、[VioManus](../../src/main/java/com/vio/vioaiagent/agent/VioManus.java)。

**追问**：哪些对象可以共享，哪些缓存必须带用户或版本范围？

### Q11【必会】为什么出现过“让我开始给最终回答”却没有实际内容？

**回答要点**：规划文本与最终答案混用时，模型可能把准备动作或过程描述当作交付结果。项目将工具规划内容与公开正文分开，`summarizeAnswer` 负责最终回答及证据核对；用户请求约束要求在当前轮实际作答。模型未生成正文、只有工具结果或中途失败时，不能把“已完成”当作内容成功。

**项目定位**：[ToolCallAgent 的 think/summarizeAnswer](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)、[公开呈现规则](../../src/main/java/com/vio/vioaiagent/agent/AnswerPresentation.java)。

**追问**：如果模型把规划放在普通 content 而不是 reasoning 字段，如何避免展示？

### Q12【进阶】换 OpenAI、DeepSeek 或其他模型是否只要换 Key？

**回答要点**：模型抽象能减少业务耦合，但还需验证协议、模型名称、工具 Schema 支持、流式字段、超时与错误类型、usage/缓存计量以及安全配置。当前 DeepSeek 使用兼容客户端和自定义编解码/账单流读取，不等于所有兼容服务可直接无差别替换。应通过本地 HTTP 协议夹具和隔离真实请求验证，再做质量对照。

**项目定位**：[模型配置](../../src/main/java/com/vio/vioaiagent/config/DeepSeekModelConfiguration.java)、[请求编解码](../../src/main/java/com/vio/vioaiagent/config/DeepSeekRequestCodec.java)、[账单流读取](../../src/main/java/com/vio/vioaiagent/config/DeepSeekBillingSseReader.java)。

**追问**：模型供应商新增字段后，为什么历史 usage 解析也可能受影响？

## 三、工具 Schema 与治理

### Q13【必会】为什么有工具函数还需要 JSON Schema？

**回答要点**：模型需要机器可读的字段、类型、枚举和必填约束；后端也需要在执行前拒绝错误结构。Schema 只解决结构及部分值域问题，不能证明物种属于指定版本、队伍归当前用户或计算条件完整。项目在注册和执行阶段分别处理定义与实参，再交给领域校验。

**项目定位**：[ToolRegistration](../../src/main/java/com/vio/vioaiagent/tools/ToolRegistration.java)、[ToolSchemaReferences](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolSchemaReferences.java)、[ToolExecutionGateway](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolExecutionGateway.java)。

**追问**：`additionalProperties`、可选字段和显式 null 的处理有什么区别？

### Q14【进阶】为什么嵌套 DTO 的 Schema 错误会让“你好”也失败？

**回答要点**：供应商可能在选择工具之前验证整组工具定义。局部 `$defs` 与根相对 `$ref` 不一致，即使本轮不需要该工具也会拒绝请求。项目有受限引用展开和校验，保留原字段约束与回调；缺失、外部或循环引用应拒绝，而不是删除所有约束。此类错误应先检查请求定义，换 Key 或重复请求没有解决结构问题。

**项目定位**：[ToolSchemaReferences](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolSchemaReferences.java)、[对应测试](../../src/test/java/com/vio/vioaiagent/tools/governance/ToolSchemaReferencesTest.java)。

**追问**：如何保证“修复 Schema”没有扩大原接口的参数权限？

### Q15【必会】工具网关要校验哪些内容？

**回答要点**：身份和 Run、登记工具及角色、Schema、路径/命令/网络策略、必要审批、幂等、副作用和时间预算，最后记录脱敏审计与事件。工具未登记就拒绝，不让模型自由构造可执行函数。检查应在真正调用前完成；成功回调之后仍要处理审计或结果保存失败带来的不确定状态。

**项目定位**：[ToolExecutionGateway](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolExecutionGateway.java)、[ToolCapabilityCatalog](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolCapabilityCatalog.java)、[网关测试](../../src/test/java/com/vio/vioaiagent/tools/governance/ToolExecutionGatewayTest.java)。

**追问**：工具返回成功但审计写入失败，是否还能直接向用户承诺已可靠完成？

### Q16【必会】为什么不能给所有工具加相同的重试策略？

**回答要点**：读取失败可能适合有限重试，写入超时却可能已经成功，直接重试会重复副作用。认证或额度错误换查询词也不会修复凭据。已经发布部分正文后重跑生成还可能重复内容和计费。项目按工具及失败条件限制执行，未知写入结果保留为不确定，不能为了“最终成功”无条件重放。

**项目定位**：[治理网关](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolExecutionGateway.java)、[ToolCallAgent](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)、[WebSearchTool](../../src/main/java/com/vio/vioaiagent/tools/WebSearchTool.java)。

**追问**：支付或邮件工具返回超时后，应当先做什么？

### Q17【进阶】5 秒工具超时是否只指 HTTP 请求用了 5 秒？

**回答要点**：还要看计时边界，项目的工具执行预算包含排队等待，不能等进入线程才开始计时。任务 deadline、网关超时和底层网络超时是不同层。提高超时会延长资源占用，应先区分排队、连接、响应体读取和服务端处理。当前搜索与统计有各自预算，不能沿用早期 5000ms 的报错推断所有工具配置。

**项目定位**：[BoundedToolExecutor](../../src/main/java/com/vio/vioaiagent/tools/governance/BoundedToolExecutor.java)、[ToolAttemptTiming](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolAttemptTiming.java)、[耗时测试](../../src/test/java/com/vio/vioaiagent/tools/governance/ToolGatewayTimingTest.java)。

**追问**：线程池满、底层不响应中断时，怎样避免继续堆积请求？

### Q18【必会】提示词里写“不要越权”，为什么还要程序权限检查？

**回答要点**：提示词是模型行为约束，不能建立可信身份，也无法阻止恶意或错误参数进入工具。真正读取和保存必须从后端认证上下文取得用户，按归属查询，再应用角色和工具范围。就算模型选错工具或被来源中的指令干扰，执行层也应拒绝。确定性程序路由同样要经过网关，不能成为绕行入口。

**项目定位**：[AgentRunController](../../src/main/java/com/vio/vioaiagent/controller/AgentRunController.java)、[ToolExecutionGateway](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolExecutionGateway.java)、[RunToolScope](../../src/main/java/com/vio/vioaiagent/pokemon/reference/RunToolScope.java)。

**追问**：如何用 Mock 验证权限拒绝时工具根本没有执行？

## 四、攻略检索与 RAG

### Q19【必会】当前知识库怎样存储？用了向量数据库吗？

**回答要点**：默认本地攻略源是带来源和适用范围的项目笔记 JSON；加载后校验、分块和构建词项，在 SQLite 的文档、片段、词项、索引元信息表持久化。检索用倒排候选和程序 BM25，不依赖默认 embedding。仓库有 PGVector 和另一套版本化知识模块，它们是独立范围；不能把默认本地链说成向量库或 SQLite FTS5。

**项目定位**：[LocalGuideSearch](../../src/main/java/com/vio/vioaiagent/pokemon/guides/LocalGuideSearch.java)、[SqliteGuideKnowledgeRetriever](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[资料集](../../src/main/resources/pokemon-strategy/README.md)。

**追问**：来源文件、索引数据、聊天历史和模型参数分别保存在哪里？

### Q20【必会】为什么先用 BM25？它怎样计算相关性？

**回答要点**：当前语料小、名称和领域关键词明确，希望低依赖、可解释且便于核对来源。BM25 综合查询词的逆文档频率、词频饱和与片段长度归一化。实现按合格候选计算统计，`k1=1.2`、`b=0.75`；标题和关键词也影响词项频率。最终还先考虑已登记的物种适用范围，因此并不是所有文档只按一个分数全局排序。

**项目定位**：[BM25 实现](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[分词与分块](../../src/main/java/com/vio/vioaiagent/pokemon/guides/GuideChunks.java)。

**追问**：同义表达、错别字和长自然语言问题为什么可能检索不好？

### Q21【必会】如何分块，为什么需要片段身份和版本？

**回答要点**：分块控制检索和上下文粒度，让来源可以定位到具体段落。项目保留片段序号、原文位置、内容摘要及文档版本，引用再绑定相应片段。块太小容易失去条件，太大占上下文且主题混杂；改内容或元数据后版本可能改变。不能静默修改冻结片段，然后继续复用原来的审核和引用结论。

**项目定位**：[GuideChunks](../../src/main/java/com/vio/vioaiagent/pokemon/guides/GuideChunks.java)、[GuideProvenance](../../src/main/java/com/vio/vioaiagent/pokemon/guides/GuideProvenance.java)、[本地索引测试](../../src/test/java/com/vio/vioaiagent/pokemon/LocalGuideIndexTest.java)。

**追问**：更新资料后，旧对话中的引用应该怎样表达有效性？

### Q22【必会】为什么先过滤版本、赛制和物种，再排序？

**回答要点**：文本相似不表示适用。旧规则、其他语言、其他物种或过期资料可能包含相同词，却不能支持本次答案。项目先检查游戏、语言、赛制、规则、有效期和声明范围，再形成候选；特定物种笔记在相关候选中优先。过滤过严也可能减少召回，应记录无结果的真实原因，不能临时放宽到错误来源而不说明。

**项目定位**：[GuideApplicability](../../src/main/java/com/vio/vioaiagent/pokemon/guides/GuideApplicability.java)、[检索器](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[物种检索测试](../../src/test/java/com/vio/vioaiagent/pokemon/SpeciesGuideRetrievalTest.java)。

**追问**：如何区分“词法没匹配”“版本不允许”和“根本没有该资料”？

### Q23【必会】有引用链接为什么还可能是幻觉？

**回答要点**：链接存在、原文存在、原文支持结论、适用于当前问题是不同条件。模型可能引用真实笔记，却增加原文没有的招式、机制或热门程度。项目绑定真实来源片段，并用证据处理限制部分扩写；仍需评价相关性和语义支持。不能认为显示了来源就已经全面消除幻觉，原始来源本身也可能有错误或时效限制。

**项目定位**：[GuideAnswerEvidence](../../src/main/java/com/vio/vioaiagent/agent/GuideAnswerEvidence.java)、[引用审核说明](../../evaluation/campus/reviews/README.md)。

**追问**：原文正确但没有回答用户问题，应判“事实正确”还是“回答合格”？

### Q24【进阶】如果要升级为向量或混合检索，你会怎么做？

**回答要点**：先收集当前检索失败样本，区分缺资料、过滤错误与同义表达问题。固定来源及查询集，对照 BM25、向量和混合方案的 Recall@K、排序指标、引用支持和最终任务结果，同时记录延迟、成本和部署负担。候选融合或重排也必须保留版本与身份过滤。只有改善被验证后才切默认，不因技术更复杂就宣称更准确。

**项目定位**：[现有检索抽象](../../src/main/java/com/vio/vioaiagent/rag/retrieval)、[本地基线](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[评测目录](../../evaluation/campus)。

**追问**：没有可信相关性标注时，怎么构造一个可用的小型对照实验？

## 五、图鉴与在线资料

### Q25【必会】PokéAPI 的 JSON 怎样变成系统中的领域事实？

**回答要点**：适配器读取固定资源接口，核对资源身份和物种关系，将属性、六项种族值、名称等投影为 `PokemonFact`，同时保留来源、摘要和参考数据版本。领域代码不直接把整个上游 JSON 当作可信结论。物种存在、某招有记录与当前赛事可用是不同事实，参考资料也不表示某一历史补丁的冻结状态。

**项目定位**：[PokeApiClient](../../src/main/java/com/vio/vioaiagent/pokemon/reference/PokeApiClient.java)、[LocalPokeApiRepository](../../src/main/java/com/vio/vioaiagent/pokemon/reference/LocalPokeApiRepository.java)。

**追问**：如果上游返回了 200，但请求 25 号却得到 7 号，应该怎样处理？

### Q26【必会】本地缓存为什么要记录摘要、时间与来源？

**回答要点**：摘要用于与预期内容核对，来源用于追溯，抓取时间说明快照时间。项目校验缓存身份、来源和内容，再通过临时文件与原子替换减少半写入结果。哈希不是签名，不证明外部来源真实，也不证明资料最新；来源和内容若被一起恶意替换，单纯重新计算哈希不足以识别。读取缓存与刷新策略也要分开说明。

**项目定位**：[PokeApiClient](../../src/main/java/com/vio/vioaiagent/pokemon/reference/PokeApiClient.java)、[缓存损坏测试](../../src/test/java/com/vio/vioaiagent/pokemon/PokeApiReferenceTest.java)。

**追问**：断网时有有效缓存、无缓存、损坏缓存应分别给用户什么结果？

### Q27【必会】名称搜索和“查看图鉴”联动怎样避免串物种？

**回答要点**：使用经过来源与摘要校验的名称身份索引，将中英文名称及编号映射到物种；前端只从对应消息里提取候选，并处理英文词边界和嵌套名称。点击卡片后由工作台发起实际查询，新主输入不能被上次高级编号条件限制。“已在右侧打开”以本次成功返回且图鉴正在显示为依据，不在发请求时提前宣告。

**项目定位**：[PokemonNameIndex](../../src/main/java/com/vio/vioaiagent/pokemon/reference/PokemonNameIndex.java)、[pokemon-navigation.js](../../vio-ai-agent-frontend/src/api/pokemon-navigation.js)、[PokemonWorkbench](../../vio-ai-agent-frontend/src/views/PokemonWorkbench.vue)。

**追问**：为什么“仙子伊布”不能同时被识别成普通“伊布”？形态名如何处理？

### Q28【必会】“当前热门队伍”为什么不能只查本地知识库？

**回答要点**：本地资料有范围和时间边界，图鉴与原创攻略并不提供当前竞技排名。先确定游戏、赛制和日期，再查询合适来源。当前支持指定 Showdown 赛制的最新已发布月度使用率，另可用独立搜索服务找赛事资料入口；不能把休闲单打或 VGC 自动当成 OU，也不能在查询失败时凭模型记忆补造“当前阵容”。

**项目定位**：[CompetitiveTrendsRequest](../../src/main/java/com/vio/vioaiagent/agent/CompetitiveTrendsRequest.java)、[CompetitiveTrendsTool](../../src/main/java/com/vio/vioaiagent/tools/CompetitiveTrendsTool.java)。

**追问**：用户只说“热门队伍”时，为什么澄清比直接返回一份榜单更合适？

### Q29【必会】使用率、胜率和热门队伍有什么区别？

**回答要点**：月度使用率描述该统计范围中单只宝可梦出现的比例，不是该成员胜率，也不是完整六人组合的出现率。项目保留统计月份、赛制、分段、对战样本和来源，支持 `gen9ou`、`gen9doublesou`、`gen9monotype`。不能把前六名拼成被验证的队伍，也不能把该来源称为官方 VGC 统计或分钟级实时信息。

**项目定位**：[统计快照与解析](../../src/main/java/com/vio/vioaiagent/tools/CompetitiveTrendsTool.java)、[在线环境回答](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)。

**追问**：如何证明某支队伍在某场赛事取得了成绩？需要哪些额外字段和来源？

### Q30【进阶】接入外部搜索时，你会如何处理时效、安全和失败？

**回答要点**：验证请求目标、限制来源与响应大小、明确超时和失败类别，搜索凭据不放 URL 或日志。区分无结果、未配置、认证拒绝和网络故障，保留实际来源日期及抓取范围。搜索摘要只是入口，不代表已阅读完整队表。当前独立 SearchAPI Key 与模型 Key 分开；统计缓存过期后查询失败，也不把旧内容伪装成刚取得的最新资料。

**项目定位**：[WebSearchTool](../../src/main/java/com/vio/vioaiagent/tools/WebSearchTool.java)、[CompetitiveTrendsTool](../../src/main/java/com/vio/vioaiagent/tools/CompetitiveTrendsTool.java)、[联网范围说明](../秋招升级/最终交付/图鉴跳转名称索引与在线环境参考_2026-11-04.md)。

**追问**：如果将来允许任意 URL 抓取，如何防止重定向、DNS 变化和私网访问？

## 六、确定性计算

### Q31【必会】为什么不让大模型直接算伤害？

**回答要点**：伤害受输入配置和机制约束，模型可能遗漏条件、算错数值或编造效果。项目把计算交给本地固定版本 Smogon 引擎，模型用于理解与解释；程序保留实际输入、伤害范围、HP、百分比及假设。类型克制倍率不是伤害结果，已算出一个范围也不证明实战胜率或整队优劣。

**项目定位**：[LocalDamageEngine](../../src/main/java/com/vio/vioaiagent/pokemon/engine/LocalDamageEngine.java)、[DamageAnswerEvidence](../../src/main/java/com/vio/vioaiagent/agent/DamageAnswerEvidence.java)。

**追问**：用户只给了物种和招式，却没给等级、培养条件，你怎样回答？

### Q32【必会】Java 怎样调用 Node 引擎，为什么不用拼 shell？

**回答要点**：通过 `ProcessBuilder` 启动固定 Node 程序和固定脚本路径，JSON 从标准输入传入，结果从标准输出读取，不把用户参数拼成 shell 命令。限制请求与响应大小、执行时间，核对退出码，异常时结束残余进程。默认公开配置使用 v2 脚本，不额外起网络服务。这是一种适合本地范围的桥接，不等于高并发服务方案。

**项目定位**：[LocalDamageEngine](../../src/main/java/com/vio/vioaiagent/pokemon/engine/LocalDamageEngine.java)、[calculate-v2.cjs](../../tools/pokemon-engine/calculate-v2.cjs)、[桥接说明](../../tools/pokemon-engine/README.md)。

**追问**：请求很多时每次拉起进程有什么代价？改成常驻进程后如何做隔离和回收？

### Q33【必会】如何防止图鉴快照和计算引擎使用了不同资料？

**回答要点**：校验请求世代和数据版本，先取得双方的参考事实，再将规范化物种与培养配置送入引擎；返回后核对引擎标识、版本、世代、数据版本和双方六项种族值。不能为了调用成功临时换一个数据版本。匹配这些有限字段也不证明所有机制、招式与赛事规则都完全一致，仍需说明核验范围。

**项目定位**：[LocalDamageEngine.calculate/verifyStats](../../src/main/java/com/vio/vioaiagent/pokemon/engine/LocalDamageEngine.java)、[LocalDamageEngineTest](../../src/test/java/com/vio/vioaiagent/pokemon/LocalDamageEngineTest.java)。

**追问**：如果种族值一致但招式机制有版本差异，现有核对能发现吗？

### Q34【必会】工具成功了，为什么回答里的计算仍可能错误？

**回答要点**：模型可能转写了错误参数，或在解释阶段交换双方、改写数值、添加未计算的机制结论。必须把用户条件、实际工具输入、实际输出与正文分别核对。项目保留调用输入与结果证据，对有限断言进行检查，必要时展示程序核对的结果。不能把固定解释的正确当成模型策略判断已全面正确。

**项目定位**：[ToolInputEvidence](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolInputEvidence.java)、[DamageResultEvidence](../../src/main/java/com/vio/vioaiagent/tools/governance/DamageResultEvidence.java)、[DamageAnswerEvidence](../../src/main/java/com/vio/vioaiagent/agent/DamageAnswerEvidence.java)。

**追问**：计算返回正确数值，但用户要求比较两种天气，只算了一种，是否算完成？

### Q35【进阶】“数值正确”和“机制建议正确”怎样分开评价？

**回答要点**：数值检查绑定本次明确输入；机制建议还涉及对照条件、适用招式、特性和环境。一个区间正确，不能证明“换道具一定更强”等附加结论。项目增加有限建议断言约束并保留未验证边界；要证明比较结论，应保持其他条件一致，实际计算两组输入，或提供独立可靠机制来源。仍不由一次比较推出整队胜率。

**项目定位**：[DamageAdvicePolicy](../../src/main/java/com/vio/vioaiagent/agent/DamageAdvicePolicy.java)、[机制证据](../../src/main/java/com/vio/vioaiagent/agent/MechanicAnswerEvidence.java)、[已知问题复盘](../秋招升级/最终交付/面试与项目讲解.md)。

**追问**：你会怎样设计一个能抓出“计算对、解释错”的测试？

### Q36【进阶】零伤害为什么曾导致失败，为什么保留 v1 脚本？

**回答要点**：某些零伤害输入在 SDK 的描述器环节会抛错，计算出的零值与描述生成是不同阶段。v2 对已计算的 0–0 直接给出描述，正伤害维持兼容。v1 为冻结引用、历史证据和兼容核验保留，不静默替换旧源码摘要。该修复不是重写公式，也不意味着所有 SDK 边界情况已经覆盖。

**项目定位**：[桥接说明](../../tools/pokemon-engine/README.md)、[v2](../../tools/pokemon-engine/calculate-v2.cjs)、[真实 SDK 测试](../../tools/pokemon-engine/calculate.test.cjs)。

**追问**：依赖升级后怎样区分预期数值变化、协议变化和回归缺陷？

## 七、Run 与可靠性

### Q37【必会】为什么要有 Run？HTTP 请求不是已经表示一次执行吗？

**回答要点**：模型与工具任务持续时间长，浏览器连接可能关闭，还可能等待审批、取消或失败。Run 把业务任务从单次连接中分离，统一身份、冻结上下文、状态、deadline、事件和结果。创建返回 202 后再读快照与事件。会话包含多次 Run，消息历史也不等于全部运行状态。

**项目定位**：[CreateRunCommand](../../src/main/java/com/vio/vioaiagent/run/CreateRunCommand.java)、[AgentRun](../../src/main/java/com/vio/vioaiagent/run/AgentRun.java)、[Controller](../../src/main/java/com/vio/vioaiagent/controller/AgentRunController.java)。

**追问**：页面关闭、浏览器刷新、后端重启分别影响哪些状态？

### Q38【必会】Run 状态机如何设计？

**回答要点**：后端有 CREATED、RUNNING、WAITING_APPROVAL 以及完成、失败、取消、超时等终态，允许的转换由代码约束。终态不能重新进入运行态，旧 worker 也不能把取消任务改成成功。前端 CREATING/RECONNECTING 是额外的页面或传输状态，不应反向当作服务端事实。状态持久化与提交还需要版本及并发保护。

**项目定位**：[AgentRunStatus](../../src/main/java/com/vio/vioaiagent/run/AgentRunStatus.java)、[RunService](../../src/main/java/com/vio/vioaiagent/run/PokemonAgentRunService.java)、[前端状态](../../vio-ai-agent-frontend/src/api/run-contract.js)。

**追问**：取消和执行完成同时发生时，如何避免出现两个相互冲突的最终状态？

### Q39【必会】请求幂等与前端禁止重复点击有什么区别？

**回答要点**：前端 single-flight 减少重复发送，但刷新、网络重试或其他客户端仍可能重复请求。服务端幂等 Key 必须绑定调用范围和请求内容，相同请求可关联同一执行，不同内容复用 Key 应冲突；处理中也不能再启动一份。幂等记录与实际创建之间还存在并发窗口，不能只做一次 `get` 再 `put`。

**项目定位**：[幂等仓储](../../src/main/java/com/vio/vioaiagent/run/IdempotencyStore.java)、[幂等测试](../../src/test/java/com/vio/vioaiagent/run/PokemonAgentRunServiceIdempotencyTest.java)、[前端预占](../../vio-ai-agent-frontend/src/composables/useRunStream.js)。

**追问**：Key 应在每次 HTTP 重试时更新吗？相同 Key 的不同 prompt 怎样处理？

### Q40【必会】调用 Future.cancel(true) 为什么还不够？

**回答要点**：中断是协作机制，底层网络、SDK 或工具可能忽略中断，旧 worker 之后仍会返回。项目还撤销执行租约并在关键提交/变更边界检查有效性，阻止失去权限的任务写答案或资源。逻辑取消不代表外部动作已经撤销，底层资源还需要超时、清理和适当的状态核对。

**项目定位**：[RunService 的 ManagedRunTask/ExecutionLease](../../src/main/java/com/vio/vioaiagent/run/PokemonAgentRunService.java)、[RunMutationBoundary](../../src/main/java/com/vio/vioaiagent/run/RunMutationBoundary.java)、[隔离测试](../../src/test/java/com/vio/vioaiagent/run/PokemonAgentRunServiceLeaseFencingTest.java)。

**追问**：如何写一个明确忽略中断、但最后不得写入的测试？

### Q41【进阶】租约和 fencing 解决什么问题？

**回答要点**：租约表示某个执行者在有效窗口内的执行资格；fencing 在真正写入时检查资格，阻止过期或被撤销执行者提交。只在开始前检查一次不够，执行期间可能失去资格。当前代码包含内存与持久化适配，但本地 JVM 内的保护不能直接证明多实例正确性；数据库约束、事务及真实多进程验证仍要分别确认。

**项目定位**：[RunLease](../../src/main/java/com/vio/vioaiagent/run/RunLease.java)、[RunService](../../src/main/java/com/vio/vioaiagent/run/PokemonAgentRunService.java)、[RunLeaseFenceTest](../../src/test/java/com/vio/vioaiagent/run/RunLeaseFenceTest.java)。

**追问**：线程暂停超过租约，再恢复执行时，为什么不能继续保存？

### Q42【必会】有 Checkpoint 和历史消息，就能断点续跑吗？

**回答要点**：不能。Checkpoint 可能只保存位置，没有完整模型响应、授权有效性或外部副作用结果。当前策略只允许初始 dispatch 安全重提，execute-answer、commit-answer 和未知步骤拒绝自动重放。步骤 artifact 有助于保存结果，但不自动解决恢复授权及副作用核对；默认本地 Run/事件在内存，也不能把历史 SQLite 落盘说成持久工作流。

**项目定位**：[RunRecoveryPolicy](../../src/main/java/com/vio/vioaiagent/run/RunRecoveryPolicy.java)、[RunStepOutput](../../src/main/java/com/vio/vioaiagent/run/RunStepOutput.java)、[SqliteLocalHistoryRepository](../../src/main/java/com/vio/vioaiagent/run/SqliteLocalHistoryRepository.java)。

## 八、队伍修改与确认

### Q43【必会】为什么要“读 → 预览 → 确认 → 保存回读”？

**回答要点**：聊天里的配置不一定是当前保存值，先读才能知道真实成员与缺项；预览固定差异，让用户知道将改什么；确认表达本次具体授权；保存前再次检查身份、原快照、版本和有效期，回读确认实际结果。模型不能跳过该闭环直接宣布保存成功，用户仍可以取消或拒绝。

**项目定位**：[TeamWorkflowService](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)、[TeamWorkflowTest](../../src/test/java/com/vio/vioaiagent/pokemon/TeamWorkflowTest.java)。

**追问**：为什么确认之前不先写进去，再用“撤销”恢复？

### Q44【必会】用户在聊天中说“同意”是否就等于确认保存？

**回答要点**：不等于。确认必须绑定登录用户、当前 Run、具体动作、参数摘要和有效预览，由后端审批状态决定。文字可能被引用、转述或来自旧对话，模型也可能误识别；页面点击本次确认之后仍要服务端验证。项目在恢复 worker 的 `finishIfPending` 校验审批，不让模型自行生成或替换审批事实。

**项目定位**：[HitlManager](../../src/main/java/com/vio/vioaiagent/security/HitlManager.java)、[TeamWorkflowService.finishIfPending](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)、[HitlController](../../src/main/java/com/vio/vioaiagent/controller/HitlController.java)。

**追问**：用户确认后模型又提出另一组修改，能复用刚才的审批吗？

### Q45【必会】预览期间队伍被其他操作修改，怎么办？

**回答要点**：保存时按读取的快照做 compare-and-set，而不是覆盖当前行。原数据已经变化或被删除就报告冲突，要求重新读取和确认；不能把确认后的旧建议自动合并成新写入。CAS 的实际原子性必须由仓储实现和事务保证，单独在 Java 里先查后改仍有竞争窗口。

**项目定位**：[SavedTeamRepository](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SavedTeamRepository.java)、[SqliteSavedTeamRepository](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SqliteSavedTeamRepository.java)、[TeamWorkflowService](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)。

**追问**：在 SQL 中怎样用原版本和影响行数表示冲突？当前仓储具体比较什么？

### Q46【必会】为什么局部修改要区分缺省、null 和清空？

**回答要点**：未请求修改的字段应保留原值，否则模型漏传道具、特性或努力值就可能覆盖用户配置。当前变更结构中 null 通常表示保留旧字段，而具体集合或值才表达变更；能否清空要按该字段契约明确处理。不要用通用“合并 JSON”猜语义，应先生成可读差异，并验证槽位、范围和配置约束。

**项目定位**：[BuildChange/merge/pick](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)、[TeamBuild](../../src/main/java/com/vio/vioaiagent/pokemon/domain/TeamBuild.java)。

**追问**：PATCH 中空字符串、空数组和缺失字段各应该意味着什么？

### Q47【进阶】数据库可能写成功了，但回读失败，怎样回复和重试？

**回答要点**：这是结果不确定，不能说一定失败，也不能再次无条件写入。项目记录 UNKNOWN 并提示回读核对，当前任务不自动重放可能已提交的写操作。即使底层有事务，也要区分事务未提交、提交成功但响应丢失，以及后续读取失败。更完整的恢复需持久操作 ID、结果账本及可查询的业务状态。

**项目定位**：[TeamWorkflowService.finishIfPending](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)、[EffectLedgerRepository](../../src/main/java/com/vio/vioaiagent/run/EffectLedgerRepository.java)。

**追问**：为什么不能简单 catch 异常然后把任务重新放进队列？

### Q48【进阶】已经有数据库事务，为什么还需要审批、幂等与回读？

**回答要点**：事务处理数据库内的原子性和隔离，不能代替用户授权，也不能自动去重重复请求或确认客户端收到了结果。审批绑定允许的变更，幂等约束执行意图，原快照保护并发更新，回读核对实际持久结果。外部 API 与数据库之间还没有天然的共同事务；不能从一次提交成功推导整个任务具有 exactly-once 保证。

**项目定位**：[队伍工作流](../../src/main/java/com/vio/vioaiagent/pokemon/team/TeamWorkflowService.java)、[SQLite 队伍仓储](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SqliteSavedTeamRepository.java)、[幂等抽象](../../src/main/java/com/vio/vioaiagent/run/IdempotencyStore.java)。

## 九、账户与应用安全

### Q49【必会】本地应用为什么还需要登录和账户隔离？

**回答要点**：一台电脑也可能有多个账号，浏览器可以构造任意资源 ID，不能只靠界面隐藏。账号用于建立身份，再按该身份读取历史、队伍、收藏和 Run。身份认证回答“是谁”，资源授权回答“能访问什么”。当前账户是本机账户体系，不等于企业统一身份、跨设备同步或文件本身已加密。

**项目定位**：[LocalAccountService](../../src/main/java/com/vio/vioaiagent/security/LocalAccountService.java)、[LocalAccountController](../../src/main/java/com/vio/vioaiagent/controller/LocalAccountController.java)、[归属测试](../../src/test/java/com/vio/vioaiagent/security/LocalAccountDataTest.java)。

**追问**：A 用户在请求体或 Header 中改成 B 用户 ID，为什么不能切换身份？

### Q50【必会】为什么密码不能明文存，也不能直接用 SHA-256？

**回答要点**：密码需要抵抗离线猜测，应使用带盐、可调成本的密码哈希，而不是快速摘要。项目使用 BCrypt，并处理输入限制、登录失败节流和账户版本。摘要用于资料完整性与密码哈希用途不同。密码哈希也不是万能保护，登录接口、恢复凭据、会话失效和数据库访问权限仍需要分别设计。

**项目定位**：[LocalAccountService](../../src/main/java/com/vio/vioaiagent/security/LocalAccountService.java)、[账户测试](../../src/test/java/com/vio/vioaiagent/security/LocalAccountServiceTest.java)。

**追问**：修改密码后怎样让旧会话失效？用户名不存在时如何减少可观察差异？

### Q51【必会】用了 Session 和 Cookie，为什么需要 CSRF？

**回答要点**：浏览器会自动携带符合条件的 Cookie，其他页面可能诱导它向目标站发请求。CSRF Token 用于校验敏感操作的请求来源上下文，不能用“已经登录”替代。项目通过 `CSRF-TOKEN` Cookie 和 `X-CSRF-TOKEN` 请求头处理 SPA 请求，登录后也要正确获取或刷新 Token。SameSite 和 CORS 有帮助，但不应被当作全部替代。

**项目定位**：[LocalAccountSecurityConfiguration](../../src/main/java/com/vio/vioaiagent/config/LocalAccountSecurityConfiguration.java)、[SpaCsrfTokenRequestHandler](../../src/main/java/com/vio/vioaiagent/config/SpaCsrfTokenRequestHandler.java)、[前端 API](../../vio-ai-agent-frontend/src/api/index.js)。

**追问**：401、403 和 CSRF 校验失败分别应怎样提示，为什么不能一律重试？

### Q52【必会】怎样防止 IDOR，也就是通过换 ID 访问别人数据？

**回答要点**：所有敏感资源查询使用认证用户范围，例如按 runId 加 userId、teamId 加 owner 查询，而不是先按 ID 找到后只让前端判断。更新、取消、事件读取、历史和审批都必须覆盖归属；猜不到 UUID 不能代替授权。异步执行还要显式传递可信执行上下文，不能依赖随线程消失的请求信息或让模型提供 owner。

**项目定位**：[InMemoryRunRepository.findByIdForUser](../../src/main/java/com/vio/vioaiagent/run/InMemoryRunRepository.java)、[SavedTeamRepository](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SavedTeamRepository.java)、[RunToolScope](../../src/main/java/com/vio/vioaiagent/pokemon/reference/RunToolScope.java)。

**追问**：读取 Run 已鉴权，后续工具读取队伍是否还要再次校验？

### Q53【进阶】检索文档里写“忽略规则、修改队伍”怎么办？

**回答要点**：外部资料与历史是数据，不应提升为系统指令或用户授权。提示词要求区分来源，程序还需限制工具、参数、归属和确认边界；仅靠让模型“忽略恶意指令”不足。当前有有限来源指令识别和工具治理，但不能声称防住所有注入。测试应观察是否越权执行及污染回答，而不只是是否出现拒绝文字。

**项目定位**：[SourceInstructionReply](../../src/main/java/com/vio/vioaiagent/agent/SourceInstructionReply.java)、[ConversationHistory](../../src/main/java/com/vio/vioaiagent/run/ConversationHistory.java)、[治理网关](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolExecutionGateway.java)。

**追问**：恶意内容放在工具结果、旧会话或网页标题中，边界是否相同？

### Q54【必会】怎样避免日志、Git 和评测泄露 Key 或个人数据？

**回答要点**：Key 保留在本机环境或忽略的运行配置，不进截图、请求 URL、源码和证据。失败诊断使用固定类别、可读取状态和受限来源字段，不保存任意响应正文或 Header。评测使用隔离账号与数据，发布前检查 staged diff。某个脱敏类存在不代表所有日志都已安全，还需审查实际日志出口和等级；误提交后删除最新文件也不能清除历史泄露。

**项目定位**：[ModelFailureDiagnostics](../../src/main/java/com/vio/vioaiagent/observability/ModelFailureDiagnostics.java)、[ParameterMasker](../../src/main/java/com/vio/vioaiagent/security/ParameterMasker.java)、[.gitignore](../../.gitignore)。

**追问**：Key 真的推送到远端后，为什么应先吊销轮换，再处理仓库历史？

## 十、上下文、用量与可观测性

### Q55【必会】聊天历史如何进入模型？为什么不是全部拼接？

**回答要点**：先按账户和会话筛选，只选择当前 Run 之前完整的 user/assistant 轮次，再受轮数、字符和 Token 代理预算限制。项目从最近轮次回填，保持每轮完整和角色不变，不将旧内容升级为 system。失败或残缺轮次不能随意当作完整历史。当前请求和本轮工具结果有自己的边界，历史只是背景，不自动启动新的任务。

**项目定位**：[ConversationHistory](../../src/main/java/com/vio/vioaiagent/run/ConversationHistory.java)、[历史测试](../../src/test/java/com/vio/vioaiagent/run/ConversationHistoryTest.java)。

**追问**：只截取最后 N 个字符可能截断什么？怎样避免助手答复失去原问题？

### Q56【进阶】上下文超限时，为什么不能随便截掉工具结果？

**回答要点**：工具调用与结果有协议绑定，截断可能破坏参数、结果或当前任务的条件。项目预算计算系统消息、历史、工具定义、本轮消息和工具结果，优先按完整轮次移除旧历史，给出裁剪提示；当前任务不可再容纳时拒绝，而不是静默删关键事实。还要限制输出预算。当前估算有误差，不能当作供应商真实上下文计量。

**项目定位**：[ModelContextBudget](../../src/main/java/com/vio/vioaiagent/observability/ModelContextBudget.java)、[ContextBudgetProperties](../../src/main/java/com/vio/vioaiagent/config/ContextBudgetProperties.java)、[预算测试](../../src/test/java/com/vio/vioaiagent/observability/ModelContextBudgetTest.java)。

**追问**：工具 Schema 很大，即使用户只说“你好”，为什么仍可能占很多输入预算？

### Q57【必会】Token 估算、usage 缺失、零模型调用有什么区别？

**回答要点**：估算用于调用前准入，供应商 usage 用于调用后的计量；代理 tokenizer 不等于供应商账单 tokenizer。调用失败或流尾缺失时 usage 可能未知，不能填成零。只有明确的程序短路路径并实际记录未调用模型，才可认定零调用。没有观测到请求也不自动等于已证明没有请求。

**项目定位**：[ContextTokenEstimator](../../src/main/java/com/vio/vioaiagent/observability/ContextTokenEstimator.java)、[ModelUsageLedger](../../src/main/java/com/vio/vioaiagent/observability/ModelUsageLedger.java)、[DefaultRunExecutor](../../src/main/java/com/vio/vioaiagent/run/DefaultRunExecutor.java)。

**追问**：某条程序事实表回答能否纳入模型生成准确率与平均模型成本？

### Q58【必会】怎样控制一个 Agent 任务的模型成本？

**回答要点**：限制上下文、单次输出、模型调用轮次和任务累计预算，工具结果也要控制大小；相同资料可做明确范围的缓存。项目区分模型调用条目、供应商计量、代理估算和参考费用，价格展示默认关闭。不能从少量成功任务或程序短路推导整体降低多少成本，缺失 usage 也不能按零成本纳入平均值。

**项目定位**：[TaskModelBudget](../../src/main/java/com/vio/vioaiagent/observability/TaskModelBudget.java)、[ModelUsageLedger](../../src/main/java/com/vio/vioaiagent/observability/ModelUsageLedger.java)、[ModelPriceCatalog](../../src/main/java/com/vio/vioaiagent/observability/ModelPriceCatalog.java)。

**追问**：为什么 prompt cache 命中、输入 Token 和实际计费金额不能混成同一个指标？

### Q59【进阶】如何分析“回答很慢”？项目测到的是供应商 TTFT 吗？

**回答要点**：先分任务调度等待、工具排队/校验/执行、模型调用、首段可发布正文和浏览器收到正文。项目的 `firstAnswerReadyMs` 是从任务登记到服务端正文就绪的观测，明确 `deliveryMeasured=false`；浏览器另有首段收到时间，两者都不是供应商 TTFT。不能把并行或重叠阶段简单相加，也不能以一条记录代表 P95。

**项目定位**：[RunAttemptTiming](../../src/main/java/com/vio/vioaiagent/observability/RunAttemptTiming.java)、[ToolAttemptTiming](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolAttemptTiming.java)、[response-timing.js](../../vio-ai-agent-frontend/src/api/response-timing.js)。

**追问**：如果要测真正的用户感知首字延迟和 P95，你会怎样定义起止与样本？

### Q60【必会】怎样定位一次模型失败，又不泄露原始响应？

**回答要点**：用 Run/trace 关联实际调用条目，记录受限错误类别、可信解析出的 HTTP 状态和来源，再检查工具、预算及终态。认证、额度、超时、协议错误要分开；没有可读取状态就保留未知，不能从普通异常文字猜 401。后来的成功探测不能回填历史失败根因。诊断字段不保存任意异常正文、端点或凭据。

**项目定位**：[ModelFailureDiagnostics](../../src/main/java/com/vio/vioaiagent/observability/ModelFailureDiagnostics.java)、[ObservedChatModel](../../src/main/java/com/vio/vioaiagent/observability/ObservedChatModel.java)、[ModelUsageLedger](../../src/main/java/com/vio/vioaiagent/observability/ModelUsageLedger.java)。

**追问**：为什么“换了 Key 就成功”仍不足以证明历史每次失败都是 Key 错误？

## 十一、前端交互与流式协议

### Q61【必会】项目的流式输出到底怎样实现？

**回答要点**：模型最终正文可以经供应商流式 chunk 进入服务端，再转为 answer.delta 事件；前端通过 SSE 快照和 JSON 事件补读逐步呈现。Controller 当前发送已取得的事件后关闭连接，浏览器继续按游标取新事件，因此不是一个永不关闭的推送连接。程序来源节选和固定回复也可分段发布，必须与模型正文流区分。

**项目定位**：[ToolCallAgent.streamResponse](../../src/main/java/com/vio/vioaiagent/agent/ToolCallAgent.java)、[eventStream](../../src/main/java/com/vio/vioaiagent/controller/AgentRunController.java)、[useRunStream.consume](../../vio-ai-agent-frontend/src/composables/useRunStream.js)。

**追问**：模型已经输出，页面还没显示，可能卡在哪几层？

### Q62【必会】为什么用 reducer 处理事件，而不是页面里到处追加字符串？

**回答要点**：事件有类型、顺序、游标和终态规则，集中归约到 RunViewModel 更容易做重放、去重和测试。页面只显示投影，不根据自由文本猜“完成”。重复事件不能重复追加正文，迟到事件不能覆盖终态；未知事件应按契约处理而不是任意渲染 payload。最后快照与增量还需保证不把同一答案显示两遍。

**项目定位**：[run-contract.js](../../vio-ai-agent-frontend/src/api/run-contract.js)、[契约测试](../../vio-ai-agent-frontend/scripts/run-contract.test.mjs)、[ChatRoom](../../vio-ai-agent-frontend/src/components/ChatRoom.vue)。

**追问**：收到同一个 answer.delta 两次、终态后再收到旧增量，分别怎样处理？

### Q63【进阶】事件 ID 为什么用字符串，不直接用 JavaScript Number？

**回答要点**：后端 int64 可能超过 JavaScript 安全整数范围，先解析成 Number 就可能已经丢精度。前端把游标规范化为有边界的十进制字符串，并用精确比较处理；SSE 的 id 字段也保持文本。必须从协议输入到持久化一致保护，不能在损失精度之后再调用 toString 试图恢复。

**项目定位**：[normalizeCursorId/compareCursorIds](../../vio-ai-agent-frontend/src/api/run-contract.js)、[SSE 消费](../../vio-ai-agent-frontend/src/api/index.js)、[run-contract 测试](../../vio-ai-agent-frontend/scripts/run-contract.test.mjs)。

**追问**：字符串字典序会把 10 排在 9 前面，应当怎样比较？

### Q64【必会】断线为什么不能直接把 Run 标成失败或取消？

**回答要点**：断线是传输故障，后端可能继续执行。前端保存安全恢复指针，用最后游标有限退避重连，并检查服务端快照确认终态；真正取消需要后端取消接口。410 表示游标已过保留期，需要摘要与保留边界，不应无限从旧游标重试。组件卸载后还要清理订阅，拒绝旧回调写入新状态。

**项目定位**：[useRunStream](../../vio-ai-agent-frontend/src/composables/useRunStream.js)、[runPersistence](../../vio-ai-agent-frontend/src/composables/runPersistence.js)、[Controller 游标异常处理](../../src/main/java/com/vio/vioaiagent/controller/AgentRunController.java)。

### Q65【必会】点击图鉴卡片后 A 请求比 B 更晚返回，如何避免覆盖？

**回答要点**：用 AbortController 结束不再需要的请求，并核对当前查询/请求身份，只接受仍属于当前操作的结果；中止信号本身不能保证已经缓冲的回调不会返回。选中状态以成功结果和实际面板为准，不凭请求发出就高亮成功。组件卸载或账号切换也要使旧请求失效，避免资料和会话串线。

### Q66【进阶】前端怎样提升长回答阅读体验，而不隐藏关键业务操作？

**回答要点**：扩大正文空间，来源与反馈收进对应消息底部，模型用量和执行过程默认通过开发者模式查看；审批、错误、停止和重连仍保留。宽屏资料可调宽，窄屏按需抽屉，统一重复入口；键盘支持焦点限制、Escape 与焦点返回，减少嵌套滚动。布局改善通过实际浏览器尺寸和交互测试验证，不只看一张效果图。

| --- | --- | --- |
| J01 | `ConcurrentHashMap` 是否让整个业务流程线程安全？ | 单次操作安全不等于 get/check/execute/put 整体原子。分别检查 `compute`、锁和状态约束；同进程并发安全也不等于跨实例安全 |

| J07 | SQLite WAL 能解决所有并发写问题吗？ | WAL 改善读写并发，但单库同时只有一个 writer；仍需短事务、busy timeout 和冲突处理。本地多个数据库文件也不自然构成一个原子事务 |
| J08 | HTTP 和流协议怎样排错？ | 202 是已接受，401/403 区分身份与授权，409 是冲突，410 在此用于过期游标，429 是限流。SSE 文本分帧与 TCP/读取 chunk 边界不同，UTF-8 也可能跨读取分段 |

### BM25 的项目公式速记

下面是从当前检索代码整理的公式，不是新实现：

```text
对每个查询词 t：
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

贡献(t,d) = IDF(t) * tf(t,d) * 2.2
            / [tf(t,d) + 1.2 * (0.25 + 0.75 * len(d) / max(1, avgLen))]

分数(q,d) = 各查询词贡献之和
```

`N` 是通过适用范围筛选的候选片段数，`df` 是其中含该词的片段数，`tf` 是当前构造索引的词频，`len` 和 `avgLen` 来自同一词项统计。标题词频在构建时加权，物种范围还参与结果排序。因此理解公式以后，仍需阅读候选、索引构建和最终 comparator，不能只凭公式解释每个结果。

## 十六、场景排错：先给顺序，再给结论

| 场景 | 建议排查顺序 | 不应采取的捷径 |
| --- | --- | --- |
| 页面一直“确认登录状态” | Network 的 session/CSRF 请求 → Cookie/代理路径 → 后端认证配置 → 前端初始化收敛 | 直接绕过认证或把所有异常当未登录 |
| 卡片打开了错误图鉴 | 本条消息候选 → 主搜索值 → 旧编号条件 → 真实请求 → 过时响应 → 选中状态 | 从整段历史猜一个最近名字 |
| 搜索连续失败 | 是否配置独立搜索 Key → 状态与类别 → 队列/网络预算 → 引擎/来源 → 实际结果 | 不断换关键词重复认证失败请求 |
| Run 超时但仍有后台输出 | deadline 与终态 → 任务取消 → 执行租约 → 变更检查 → 残余资源清理 | 只隐藏前端消息或只 cancel Future |
| 有来源却回答不相关 | 实际问题 → 适用范围 → 命中片段 → 结论支持 → 未回答的请求 | 以“链接能打开”判整题通过 |
| 用户确认后没保存 | 审批绑定/有效期 → 当前原快照 → CAS 返回 → 回读与 UNKNOWN | 自动覆盖或不核对就重复保存 |

### Q73【全栈必会】为什么真实按钮、表单和语义标签比一堆 div 更合适？

**回答要点**：语义元素提供默认键盘、表单和可访问性行为，减少自己模拟点击/焦点的错误。图标按钮还需要可读名称，抽屉/弹窗需管理焦点、关闭和返回位置。视觉像按钮不代表键盘可用；aria也不能自动补齐所有行为。项目中复制、发送、资料开关和审批都需要同时考虑鼠标、键盘与触屏。

**项目定位**：[GameMaster](../../vio-ai-agent-frontend/src/views/GameMaster.vue)、[UiIcon](../../vio-ai-agent-frontend/src/components/UiIcon.vue)；L01/L02。

### Q74【全栈必会】为什么设置了 height:100% 仍不能让聊天区正确滚动？

**回答要点**：百分比高度依赖祖先的可计算高度，Flex/Grid子项的默认最小尺寸也可能把容器撑开。需要明确视口到内容区的尺寸链，检查 `min-height:0`、轨道最小值与overflow归属。正文列表通常承担一个主滚动区，输入与操作区保留空间；不能靠固定大高度或全页overflow:hidden遮住内容。

**项目定位**：[reading-workspace.css](../../vio-ai-agent-frontend/src/styles/reading-workspace.css)、[ChatRoom](../../vio-ai-agent-frontend/src/components/ChatRoom.vue)；L01。

### Q75【全栈必会】闭包、this、let/const怎样影响异步消息处理？

**回答要点**：闭包保留词法环境，旧回调可能持有旧Run或会话；this取决于调用方式，箭头函数捕获外层this。let/const是块级绑定，const不让变量重绑定，不使对象深度不可变。处理流式回调时，不能因为外部选中会话变了，就认为已经登记的旧回调会自动绑定新任务。

### Q76【全栈必会】原型、class与浅拷贝有什么关系？

**回答要点**：JS对象可沿原型链查找属性，class提供对象构造和方法语法，但不是Java式类型运行时。展开运算或Object.assign只复制一层，嵌套数组仍可能共享。事件reducer、队伍编辑草稿和原配置若共享嵌套引用，预览操作就可能提前污染原值。深拷贝也需考虑日期、Map、循环引用和业务对象，不能通用JSON往返解决所有情况。

**项目定位**：[run-contract.js](../../vio-ai-agent-frontend/src/api/run-contract.js)、[PokemonWorkbench](../../vio-ai-agent-frontend/src/views/PokemonWorkbench.vue)；L02。

### Q77【全栈必会】Promise、async/await与异常传播怎样工作？

**回答要点**：async函数返回Promise，await只暂停该异步函数的后续执行。try/catch需覆盖实际await，未等待或未返回的Promise可能让异常脱离当前调用链。finally适合释放预占或资源，但不能把异常覆盖为成功。网络层、协议解析和业务失败也应分开，不能所有catch都返回空数组。

**项目定位**：[useRunStream.startRun](../../vio-ai-agent-frontend/src/composables/useRunStream.js)、[API层](../../vio-ai-agent-frontend/src/api/index.js)；L01/L02。

### Q78【全栈必会】事件循环、任务和微任务如何影响渲染？

**回答要点**：同步JS先执行，Promise后续等微任务在相应检查点处理，定时器与事件属于其他任务来源；渲染机会不等于每条语句后都会发生。连续同步工作或不断排微任务都会阻塞交互。Vue更新还存在调度批处理，nextTick用于等待相应DOM更新，不是任意网络请求完成的保证。

**项目定位**：[ChatRoom](../../vio-ai-agent-frontend/src/components/ChatRoom.vue)、[GameMaster](../../vio-ai-agent-frontend/src/views/GameMaster.vue)；L03。

### Q79【全栈必会】浏览器布局、绘制、合成怎样影响聊天性能？

**回答要点**：DOM/CSS形成渲染所需结构，样式计算、布局、绘制和合成的成本不同。循环读取尺寸后再修改几何样式，可能触发频繁同步布局；大量长消息也会增加计算与绘制成本。优化前用Performance记录确定瓶颈，合并读写、控制渲染范围。不能笼统认为transform、虚拟DOM或GPU一定更快。

**项目定位**：[阅读布局样式](../../vio-ai-agent-frontend/src/styles/reading-workspace.css)、[ChatRoom](../../vio-ai-agent-frontend/src/components/ChatRoom.vue)；L03。

### Q80【全栈必会】事件冒泡、捕获和事件委托适合哪些地方？

**回答要点**：事件沿路径传播，委托可以在容器集中处理动态子项，但需正确识别目标和业务身份。stopPropagation不等于阻止默认行为，preventDefault也不等于停止传播。消息内有卡片、复制、链接和选择文本时，过宽的容器点击逻辑容易冲突。键盘和组合输入也不能只靠click覆盖。

### Q81【全栈必会】Promise.all是否等于无限并行？如何限制并发？

**回答要点**：Promise.all组合已有异步工作的结果，不负责建立线程或限制并发；批量创建请求仍可能压垮连接与后端。一个失败也不自动取消其他请求。需要队列、并发上限、独立AbortController和结果策略；allSettled适合逐个检查相互独立的结果。工具有依赖或共享写入时不能盲目并行。

### Q82【全栈必会】防抖、节流和取消分别解决什么？

**回答要点**：防抖合并密集输入，节流限制触发频率，取消结束不再需要的异步工作。它们都不能单独解决旧响应覆盖新响应，还需请求身份检查。搜索框可以防抖，拖拽/滚动可考虑节流或帧调度，正式发送与确认保存则要按任务和幂等契约处理，不能仅用一个定时器防重。

**项目定位**：[PokemonWorkbench](../../vio-ai-agent-frontend/src/views/PokemonWorkbench.vue)、[useRunStream](../../vio-ai-agent-frontend/src/composables/useRunStream.js)；L01/L03。

### Q83【全栈必会】模型回答和Markdown怎样防止XSS？

**回答要点**：模型与检索文本都不可信，优先作为文本或受限结构渲染，不直接送进innerHTML。若允许Markdown/HTML，需要清洗和安全链接策略；不同输出上下文有不同转义规则。URL还要限制协议与凭据。CSP可作附加防线，不能替代安全渲染。模型提示词说“不要输出脚本”不是前端防护。

### Q84【全栈必会】同源、CORS、Cookie、SameSite与CSRF如何区分？

**回答要点**：同源由协议、主机和端口决定；CORS决定浏览器脚本是否可以读取跨源响应，不是后端授权机制。Cookie发送还受域、路径、Secure、SameSite和credentials影响。CSRF针对自动携带凭据的操作请求，和XSS不同。生产同源代理可以减少跨源复杂度，但仍需正确认证与CSRF，不使用通配允许来源掩盖配置错误。

### Q85【全栈必会】Vue ref、reactive、computed、watch怎样选？

**回答要点**：ref可包装独立值，reactive通常代理对象；computed表达派生状态并跟踪依赖，watch用于有意的副作用。解构或绕过代理可能改变依赖跟踪方式，深度监听也有成本。不要把可计算状态再存一份并用多个watch相互同步，容易出现循环和不一致。实际以Vue版本与访问方式解释，而不是只背“对象用reactive”。

**项目定位**：[GameMaster](../../vio-ai-agent-frontend/src/views/GameMaster.vue)、[useRunStream](../../vio-ai-agent-frontend/src/composables/useRunStream.js)；L02。

### Q86【全栈必会】组件卸载时要清理哪些副作用？

**回答要点**：网络流、AbortController、定时器、手动事件监听和外部订阅都需明确生命周期。响应式监听的自动清理有创建范围条件，不能认为一切异步工作都会自动结束。还要防止已缓冲回调和晚返回的创建请求重新绑定流。释放订阅不等于取消后端任务，恢复指针应按业务契约保留或删除。

**回答要点**：先确认耗时来自锁、I/O、连接等待还是执行计划，再看扫描、过滤、排序、连接和估计/实际行数。执行统计与真实数据规模、参数分布相关，不能在空表上证明索引收益。减少无用字段和N+1，必要时调整索引或模型。EXPLAIN ANALYZE等可能实际执行，应只在合适隔离数据上使用。

### Q112【后端必会】ACID、MVCC与事务隔离怎样对应？

**回答要点**：ACID描述事务性质，隔离级别约束并发可见行为，MVCC是一类实现并发读取的机制，不表示完全不加锁。脏读、不可重复读、幻读及写偏差要结合引擎和具体读写方式解释。MySQL InnoDB、PG和SQLite的实现不同，普通快照读与锁定读也不同。不能笼统说可重复读就消除所有并发业务问题。

**项目定位**：[事务保存](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SqliteSavedTeamRepository.java)、[MySQL MVCC](https://dev.mysql.com/doc/refman/8.4/en/innodb-multi-versioning.html)；L05。

### Q113【后端必会】乐观锁、悲观锁与数据库死锁怎么选择？

**回答要点**：乐观更新根据旧版本判断是否冲突，悲观锁在事务中锁定适当资源，二者都需定义重试与失败语义。用户预览期间不适合一直持数据库锁，确认时CAS更合适。死锁可能由不同锁顺序导致，数据库可回滚牺牲事务，但应用不能无条件重试外部副作用。检查影响行数与提交结果。

**项目定位**：[Snapshot/CAS](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SavedTeamRepository.java)、[SQLite实现](../../src/main/java/com/vio/vioaiagent/pokemon/repository/SqliteSavedTeamRepository.java)；L05。

**回答要点**：锁需唯一持有标识、原子获取与安全释放，租期和续租也可能遇到暂停、网络或故障。超时后旧持有者仍可能运行，写端要有版本或fencing检查。进程内锁、Redis锁和数据库约束各保护不同边界；外部副作用仍需业务幂等及结果核对。不要用“加了锁”跳过未知结果处理。

### Q120【后端进阶】Outbox、Saga和分布式事务如何取舍？

**回答要点**：Outbox把业务变更和待投递记录放在同一数据库事务，之后异步投递，消费者仍需去重。Saga用步骤与补偿处理跨服务流程，但补偿未必是数学逆操作，也可能失败。强事务、最终一致与业务容忍度需要取舍。单库事务、消息事务和外部模型/工具计费不是同一个边界，不能轻率承诺端到端exactly-once。

**回答要点**：进程提供资源与地址空间边界，线程共享进程资源但有各自执行栈等状态，协程是用户态可挂起的执行抽象，具体调度取决于语言运行时。IPC可以通过管道、socket等实现。Java启动Node是跨进程调用，不是一次普通方法调用；需要处理输入输出协议、退出、超时和残留进程。

## 二十六、LLM原理 / 高级RAG / 模型专项（Q157～Q168）

对应D25/D27～D29/D35～D40。普通应用岗优先能解释和验证应用链，S06/S07/S10等专项岗位再深入训练、推理平台与研究。各题不表示主项目已经训练模型或启用向量检索。

### Q157【AI应用基础；算法岗深入】Transformer与Attention在做什么？

**回答要点**：Attention用Query、Key计算相关权重，再聚合Value；常见缩放点积形式为softmax(QKᵀ/√d)V。多头、位置机制和前馈网络共同形成模型，因果掩码限制自回归模型看到未来位置。应用开发至少理解Token、上下文与生成机制，算法岗再掌握张量维度、损失与反向传播。不要把所有模型结构当成原论文完全相同。

**项目定位**：[Transformer原论文](https://arxiv.org/abs/1706.03762)；L12算法分支，项目API调用不是训练实践。

**追问**：为什么Token数量不是中文字数，长上下文会带来哪些资源影响？

### Q158【AI应用基础】Prefill、Decode和KV Cache怎样影响延迟与内存？

**回答要点**：Prefill处理输入上下文，Decode逐步生成后续Token；缓存已算的Key/Value可减少重复计算，但消耗内存并受上下文长度等影响。供应商前缀缓存、应用结果缓存和历史裁剪是不同机制。TTFT、每Token时延、总耗时与吞吐要分开，不能用本项目firstAnswerReady当供应商TTFT，也不能假定多轮消息必然缓存命中。

**项目定位**：[RunAttemptTiming](../../src/main/java/com/vio/vioaiagent/observability/RunAttemptTiming.java)、[上下文预算](../../src/main/java/com/vio/vioaiagent/observability/ModelContextBudget.java)、[vLLM资料](https://docs.vllm.ai/en/latest/)；L08/L12。

**追问**：为什么缩短输入可能改善首字，但不一定减少输出阶段总耗时？

### Q159【AI应用必会】Prompt、Few-shot、结构化输出和温度怎样配合？

**回答要点**：说明任务、输入边界、来源、输出格式与缺条件处理，用少量一致示例帮助理解；程序仍验证Schema、身份和领域约束。结构化输出不等于事实正确，温度低或为零也不保证跨模型/后端完全可复现。Prompt与示例要版本化并做保留输入评估，不把无限补规则当作所有问题的解决方式。

**项目定位**：[VioManus提示](../../src/main/java/com/vio/vioaiagent/agent/VioManus.java)、[Schema处理](../../src/main/java/com/vio/vioaiagent/tools/governance/ToolSchemaReferences.java)；L08/L10。

**追问**：同一个Prompt在小批次变好，为什么仍需检查过拟合和新措辞？

### Q160【AI应用必会】Embedding、余弦相似度和向量索引怎样使用？

**回答要点**：Embedding将内容映射为向量，余弦衡量方向关系，点积/距离与归一化、模型训练方式有关。向量相近不证明事实正确、权限允许或规则适用。索引应绑定模型、维度、分块与资料版本；换模型后不能混用旧向量。近似检索还有召回与资源取舍。当前默认BM25不能写成已实现向量主链。

**项目定位**：[当前BM25](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[可选PGVector配置](../../src/main/java/com/vio/vioaiagent/rag/VersionedPgVectorStoreConfig.java)；L10。

**追问**：两个模型输出同维度向量，为什么仍不能直接混入同一个检索空间？

### Q161【AI应用进阶】混合检索、RRF与重排解决什么？

**回答要点**：词法与语义召回可互补，但分数量纲通常不同，不能不校准就直接相加。RRF按各结果集排名融合，重排器再结合查询与候选判断相关性；它们也有延迟与成本。先做适用范围和权限过滤，比较固定数据下的召回、排序及来源支持。加入向量或重排不保证每题都更好。

**项目定位**：[当前排序基线](../../src/main/java/com/vio/vioaiagent/pokemon/guides/SqliteGuideKnowledgeRetriever.java)、[Elasticsearch官方RRF说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)；L10。

**追问**：BM25在物种名上很好、语义检索在同义问题上更好，怎样公平比较？

### Q162【AI应用进阶】Query Rewrite、Multi-query与Agentic RAG如何避免跑偏？

**回答要点**：改写可补足表达与指代，多个查询可扩召回，但不能改变用户对象、否定要求、版本或访问范围。保留原问题和改写来源，控制查询数量、循环、Token与延迟，对各候选去重和核对。Agent自主检索仍要真实结果与停止条件，不能因多轮查找就编造缺失资料或不断扩大任务。

**项目定位**：[ProjectGuideRequest](../../src/main/java/com/vio/vioaiagent/agent/ProjectGuideRequest.java)、[GuideAnswerEvidence](../../src/main/java/com/vio/vioaiagent/agent/GuideAnswerEvidence.java)；L10对照实验。

**追问**：用户说“不要热门队伍，只查本地资料”，改写器该保留什么约束？

### Q163【AI应用进阶】PDF/OCR/表格入库、更新与ACL怎样做？

**回答要点**：接入前核对许可、身份、版本、语言和访问范围，提取正文时保留页码、表结构或必要位置；OCR和表格解析错误会污染后续检索。分块、摘要、索引与元数据更新需一致，删除/过期/权限变更要使旧内容失效。先过滤可访问资料再送给模型，历史引用与新版本关系要说明。当前图鉴/原创笔记适配不证明已支持通用文档摄取。

**项目定位**：[GuideProvenance](../../src/main/java/com/vio/vioaiagent/pokemon/guides/GuideProvenance.java)、[摄取专题](../../src/main/java/com/vio/vioaiagent/rag/ingestion)；L10。

**追问**：修改文档权限后，向量缓存与旧引用是否也要更新？

### Q164【算法专项】RAG、SFT、LoRA各解决什么，怎样评价？

**回答要点**：RAG提供推理时外部资料，SFT通过示例训练调整行为，LoRA是常用的参数高效适配方法，通常冻结基础权重并训练低秩更新。它们可组合，不是同一层替代。微调不天然保证知识最新或事实正确，仍需数据许可、训练/验证分离、基线、超参与效果/资源记录。当前项目未训练模型，不能写成LoRA成果。

**项目定位**：[Hugging Face LoRA概念](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)；L12算法分支。链接为main文档，实验需另锁稳定依赖。

**追问**：资料每天更新的问题与输出格式不稳定的问题，优先考虑的手段为何不同？

### Q165【算法专项】DPO、PPO、RLHF与规划算法有什么区别？

**回答要点**：RLHF是一类利用反馈对齐的流程，PPO是可用于策略优化的方法，经典对齐流程还涉及奖励与采样；DPO用偏好对直接构造策略训练目标，不能与PPO步骤混写。A*/MCTS等规划方法又是不同层的决策搜索工具。应用岗应知道作用和边界，算法岗要有推导或实验；Prompt反馈不等于已经实施强化学习。

**项目定位**：[DPO论文](https://arxiv.org/abs/2305.18290)、[PPO论文](https://arxiv.org/abs/1707.06347)；S10差异化要求与L12。

**追问**：偏好数据存在评审偏差时，训练后“更像好答案”是否等于事实更正确？

### Q166【平台/模型专项】部署开源模型、量化和推理框架要验证什么？

**回答要点**：核对模型许可、架构、Tokenizer/chat template、工具协议、上下文和硬件资源，再验证接口与质量。量化、批处理、缓存和调度可能影响精度、延迟与吞吐，不能只报峰值。vLLM/SGLang/TensorRT-LLM偏推理，DeepSpeed/Megatron等常见于训练体系，不因列过名称就有实践。小资源实验明确范围，不承诺万卡或生产调优经验。

**项目定位**：[vLLM官方资料](https://docs.vllm.ai/en/latest/)、[当前供应商适配](../../src/main/java/com/vio/vioaiagent/config/DeepSeekModelConfiguration.java)；L12模型服务分支。

**追问**：接口兼容却工具调用持续失败，为什么要检查模型模板而不只检查网络？

### Q167【AI应用必会；平台岗深入】怎样建立RAG/Agent的LLMOps与评测闭环？

**回答要点**：版本化模型、Prompt、工具、资料/索引和配置，固定任务及判据，分别观察工程、检索、内容、权限与真实业务结果。Recall@K看相关项召回，MRR看首个相关项排序，nDCG可考虑分级相关性；它们不是答案正确率。评审模型需与实际人工判据校准，保留未知、首次失败、消融和新输入。发布门禁与线上反馈分开记录，避免开发集反复优化后冒充泛化。

**项目定位**：[评测目录](../../evaluation/campus)、[审核说明](../../evaluation/campus/reviews/README.md)、[用量账本](../../src/main/java/com/vio/vioaiagent/observability/ModelUsageLedger.java)；L10/L11。

**追问**：RAG召回提高但回答质量下降，可能是哪一层造成的？

### Q168【双岗位必会】如何完成Take-home、作品讲解和真实的JD匹配？

**回答要点**：先核对学历/届别/类别和必需项，再拆最小范围、接口、数据与验收。展示可运行作品、实际个人贡献、AI方案、验证与一次关键迭代；AI辅助要保留审查、拒绝和修正的判断。全栈版重点端到端交付，AI应用版重点工具/RAG/质量与业务价值。记录协作、英文官方资料阅读和开源事实，不虚构工作年限、研究成果或已合并PR。

**项目定位**：[JD样本与自查模板](项目系统学习路线_2026-11-05.md)、[已有讲解稿](../秋招升级/最终交付/面试与项目讲解.md)；L11。

**追问**：给你一个从未做过的JD技术栈，你怎样说明已会、可迁移和仍缺的能力？
