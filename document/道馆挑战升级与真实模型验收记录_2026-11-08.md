# 朱／紫道馆挑战升级与验收

## 本轮实现

### 1. 初战与重赛分开

- 八位馆主初战共28位成员，主线后道馆视察重赛共40位成员。
- 两份独立随包快照：`sv-initial-v2.json`、`sv-rematch-v2.json`，分别有SHA-256校验文件。原v1快照保留，不覆盖历史来源。
- 补充实际阵容、等级、原属性、王牌太晶属性、特性、招式与持物；展示中文名称，并保留引擎所需的英文标识。
- 重赛分析要求8枚道馆徽章、主线通关和已接到也慈视察任务三个条件。不能只用8枚徽章推断已通关，也不把这轮重赛当作每日无限重赛或DLC教员战。
- 保留莱姆双打、梦妖魔电太晶后仍飘浮等事实。猪的女性形态和颤弦蝾螈低调形态使用对应引擎物种，不把全国编号当作形态编号。

来源：[Serebii初战](https://www.serebii.net/scarletviolet/gyms.shtml)、[Serebii视察重赛](https://www.serebii.net/scarletviolet/gymrematches.shtml)、[Pokémon Database阵容](https://pokemondb.net/scarlet-violet/gymleaders-elitefour)。以本次核对快照为准，不宣称实时联网更新。

### 2. 道馆伤害计算

复用固定版本`@smogon/calc 0.12.0`，新增独立的`tools/pokemon-engine/gym-battle.cjs`，不改变已有普通伤害接口的冻结语义。

支持：

- 己方攻击馆主，或使用馆主已核实招式计算反向伤害。
- 等级、性格、EV、IV、特性、持物、剩余HP、异常状态及五项能力阶段。
- 显式太晶化、要害、天气、地形、重力、单打/双打群攻。
- 双方反射壁、光墙、极光幕、帮助、友情防守、顺风、守住，以及特性触发开关、队友倒下数、连击次数等明确条件。
- 伤害上下界、以最大HP为分母的百分比、当前HP阈值及完整条件回显。

队伍中保存的太晶属性**不会自动激活**。NPC等级、特性、持物、招式来自快照；性格、EV、IV并没有被核实，因此表单显示可调整的中性性格／0EV／31IV假设，不能冒充NPC真实隐藏数值。己方特性与物种资料一致后才计算，并核对参考种族值与引擎种族值，拒绝混用形态。

服务固定调用本地脚本，不执行用户命令、不启动公网计算服务。进程有输入/输出大小限制、超时和取消后的清理，并核对引擎版本及输入摘要。未知战斗字段会被拒绝，不能静默忽略。

**这里完成的是明确条件下的单次伤害计算，不是整场战斗模拟。** 不自动推演AI选招、交换、命中、回合末结算、观众能力变化、捕获服从或胜率。当前桥接不支持星晶太晶的首用计数，激活星晶时明确拒绝；不能将其宣传为已覆盖所有世代、DLC及特殊机制的完整对战模拟器。

### 3. 资源获取条件

在自由文本条件之外，新增结构化进度：已击败馆主、主线通关、视察任务、待检查资源及玩家声明已有的资源。

首批规则覆盖八个道馆首胜TM奖励：TM021虫扑、TM020起草、TM048伏特替换、TM022泼冷水、TM025硬撑、TM114暗影球、TM120精神强念、TM124冰旋。逐项依赖对应馆主，不能把“2枚徽章”当作“已击败奇树”。

| 状态 | 含义 |
| --- | --- |
| `OWNED_DECLARED` | 玩家声明背包已有；不证明当前成员可学 |
| `ROUTE_UNLOCKED` | 已满足首胜奖励途径；不代表物品仍在背包或能够再次领取 |
| `ROUTE_NOT_CONFIRMED` | 未确认满足该途径；不能据此断言所有其他途径都不存在 |
| `UNKNOWN` | 未收录获取规则，不能声称可获得 |

来源：[朱紫TM及获取途径](https://pokemondb.net/scarlet-violet/tms)。这一规则表不是全游戏资源数据库：捕获地点与版本独占、坐骑移动能力、商店库存、DLC、LP与制作材料仍不能由徽章数量或自由文本自动推断。原项目的招式机地区/配方资料也不能未经核验提升为剧情解锁结论。

### 4. Agent路由与回答校验

- 道馆问题优先进入专用路由，避免被通用学习途径、队伍修改或攻略流程截走。
- 缺少队伍等级、未选“第一个道馆”的目标时先追问，禁止凭模型记忆创造馆主与阵容。
- 模型仅可选择道馆分析、道馆伤害、必要的物种身份查询和终止工具；缩小工具定义与无关调用开销。
- `GymAgentTools`提供紧凑的模型参数契约，转入原有类型化领域校验；不修改HTTP请求的严格字段要求。
- 馆主事实、属性覆盖候选和伤害范围由程序核对后展示；没有有效工具结果就不发布具体结论。失败后停止无意义的工具循环。
- 修复工具成功后结束任务却未写入`finalAnswer`的问题，保证流式片段、最终答案和Run完成状态一致。
- 计算对象按用户明确指定的馆主宝可梦名称与校验后的阶段快照绑定，不信任模型填写的数组序号。排除“不是某只”等否定提及；确有多个目标时要求分开计算。治理事件记录`PROGRAM_GYM_TARGET_IDENTITY`，例如勒克猫不会因模型错误序号而变成电肚蛙。

## 使用步骤

1. 进入资料区域的“道馆挑战”，选择朱／紫、初战或视察重赛及目标馆主。
2. 在队伍配置中录入自己已有的成员、实际等级、招式、特性及太晶属性。
3. 在剧情进度中填写实际已完成的馆主与任务，按需选择待检查TM。
4. 点击“分析当前队伍”，查看馆主资料、覆盖候选、资源条件和缺口。
5. 展开“单次伤害计算”，选择成员、对手、攻击方向和招式；明确是否已经太晶化，再设置实际状态及NPC数值假设。
6. 点击“计算本次伤害”；修改条件会使旧结果失效。需要解释时点击“让助手解释打法”，检查草稿后发送，不自动调用模型或保存队伍。

采集通过隔离的本地应用HTTP入口进行，记录Run事件、公开回答、工具调用、运行信息、题集/事件/应用包/计算脚本及快照摘要；模型Key只在进程内读取，不写入验收文档或Git。新题的自动完成状态、语义复核和是否实际调用模型分开统计；澄清类问题允许零模型调用，不能据此声称八题都做了模型推理。

### 本地依赖与启动

```powershell
npm --prefix tools/pokemon-engine ci --ignore-scripts
.\mvnw.cmd '-Dspring-boot.run.profiles=local,deepseek' spring-boot:run
```

需在本机进程中正确配置`JAVA_HOME`和`DEEPSEEK_API_KEY`；不要把Key写入公开配置、文档或Git。前端按现有Vite启动方式运行。资源规则当前仍只覆盖八个道馆首胜TM途径，全地图捕获、商店和制作材料的解锁数据需要后续逐项扩充，不能从本轮成绩推断它们已经完成。
