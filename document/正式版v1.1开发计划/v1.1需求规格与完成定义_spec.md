# VIO 正式版 v1.1 需求规格与完成定义

## 1. 文档状态

| 项目 | 内容 |
|---|---|
| 版本 | v1.1 GA 规格草案 |
| 依据 | v1.0 M2～M7 实施记录、当前源码与《正式版 v1.0 开发步骤手册》 |
| 当前状态 | `BLOCKED`：真实环境、质量、灾备和发布证据尚未全部签收 |
| 适用范围 | VIO 宝可梦朱/紫垂直智能体 |
| 证据根目录 | `artifacts/v1.1/` |
| 主手册 | [正式版 v1.1 开发步骤手册](./正式版v1.1开发步骤手册.md) |

本规格冻结“要达到什么”，不把类、配置、单元测试或文档占位符当作完成证据。每项能力必须同时有实现、测试、现场验证、原始输出、版本血缘和可执行回滚。

## 2. v1.1 目标

把 v1.0 候选构建提升为可以在 staging/受控生产环境验收的 GA 候选，重点解决：

1. 版本化事实、知识摄取和 PGVector 索引的可重建与原子发布；
2. Run、事件、审批和外部副作用的持久化、幂等、恢复与跨实例一致性；
3. OIDC/Redis/审计/HITL/MCP/记忆的安全边界和删除语义；
4. 结构化领域产品、前端实时体验、历史资源和 E2E；
5. 真实 Golden Set、首 delta TTFT、Token/成本、OTel 和反馈纠错闭环；
6. 镜像 digest、SBOM、签名、staging、灰度、备份恢复、RPO/RTO 和自动/受控回滚。

## 3. 首发支持矩阵

| 维度 | 冻结要求 |
|---|---|
| 游戏 | 宝可梦朱/紫；必须有 `game_release_id` 和官方补丁号 |
| DLC | 零之秘宝；篇章通过 `dlc_id` 显式选择 |
| 语言 | `zh-CN` 正式输出；其他语言仅作别名消歧 |
| 赛制 | 剧情/休闲单打、双打、一个已审核 VGC 规则集 |
| 数据 | `data_release_id`、`knowledge_release_id`、`index_release_id` 全部可追溯 |
| 时效资讯 | 只有 source、license、retrieved/effective 时间齐全时启用 |

当前 UI 值（如 `scarlet-violet`、`casual-singles`）只能登记为 alias，必须映射到领域负责人批准的 canonical ID。

## 4. 非目标

- 不跨世代自动猜测，不开放任意 Shell、终端、服务器文件读取和任意下载。
- 不把自研 MCP 协议栈直接作为生产主链；远程 MCP 必须经过唯一治理网关。
- 不在质量、恢复和安全门禁达标前引入多 Agent 平台。
- 不因“企业级”标签无证据引入 Kafka、Kubernetes、Elasticsearch 或 GraphRAG。

## 5. 功能与质量需求

### 5.1 数据与知识

- ingestion job/attempt/outbox/DLQ 可重试、可预约、可回放；毒数据隔离。
- candidate index 可重建，active 指针只能在 N6a 真实评测通过后原子切换。
- 每个引用包含 source URL、evidence text、document/chunk、data/knowledge/index release。
- PGVector 维度、Embedding 模型、预处理和索引 profile 一致，空库迁移和 EXPLAIN 有证据。

### 5.2 Run 与资源

- Run 状态迁移使用 CAS、唯一终态、事务 Outbox、checkpoint、lease/heartbeat 和 effect ledger。
- POST 创建返回 `202 + runId + eventsUrl`；事件 envelope、游标、410、429、cancel 和重启恢复可测试。
- conversation/team/favorite 资源按 user/tenant 授权，删除、分页和备份语义明确。

### 5.3 安全治理

- OIDC/PKCE/CSRF/Origin、Redis 全局配额和幂等；玩家/运营工具目录互斥。
- 高危工具持久审批、抢占、超时和审计；审计追加式或可检测篡改。
- SSRF/DNS pinning、路径/MIME/大小、命令策略、MCP 凭据隔离和断开 fail-closed。
- 记忆 user/tenant scoped、加密、key_version、TTL、撤回、导出、删除和缓存失效。

### 5.4 产品与评测

- Fact/Calculation/Team/RAG/Tool/Approval/Feedback/Error 卡片由同一 OpenAPI/JSON Schema 驱动。
- 前端支持表单、历史 Run、结构化卡片、断线重连、cancel、429/410 和 Playwright E2E。
- Golden Set、指标 dictionary、OTel schema/query 和 release report 不可变并绑定模型/Prompt/数据/索引/环境。
- N6a 的 correction 指标只允许 `not_applicable`；真实纠错指标由 N6b 产生，避免循环依赖。

## 6. 指标与候选门槛

最终数值以 N0 冻结的 metric dictionary 为唯一来源；下表是候选目标：

| 指标 | 候选值 |
|---|---:|
| 固定事实成功率 | ≥98% |
| 版本/规则约束成功率 | ≥98% |
| 确定性计算正确率 | 100% |
| RAG Recall@5 | ≥90% |
| 引用正确率 | ≥95% |
| Groundedness | ≥95% 或经 ADR 版本化调整 |
| 无答案处理率 | ≥90% |
| 工具参数正确率 | ≥95% |
| 首 delta TTFT P95 | ≤2.5s，按 scenario/model 分桶 |
| Run 完整耗时 P95 | ≤30s，按 scenario/model 分桶 |
| 取消生效 P95 | ≤2s |
| Token/成本 | 相对批准基线不超过 20% |

P50 必须输出并写入 dictionary；若暂作观测项，必须明确不参与自动回滚。每个指标含公式、分母、窗口、最小样本、query、thresholdVersion、owner 和回滚条件。

## 7. 阶段完成定义

| 阶段 | 必须达成 |
|---|---|
| N0 | 基线/支持矩阵/开关/依赖/Secret/fixture/evaluation schema 冻结，干净构建与环境状态可复查 |
| N1a | Job/Attempt/DLQ/PGVector candidate 可重建，active 未切换 |
| N2 | Run/事件/Outbox/Checkpoint/lease/幂等/重启恢复通过 |
| N3 | 持久 HITL、审计、OIDC/Redis、SSRF/MCP/记忆安全负例通过 |
| N4 | 事实/计算/队伍/收藏/活动和 answer lineage 产品 API 通过 |
| N5 | 前端表单/卡片/历史/可访问性/E2E 通过 |
| N6a | 真实 Golden Set、OTel/metric schema、质量 gate 生成不可变候选报告 |
| N1b | 只凭 N6a 报告执行原子 promotion |
| N6b | 至少一条反馈完成纠错、重索引、定向评测、重答通知和回读 |
| N7 | 双镜像/依赖供应链、staging、探针、迁移兼容、恢复、灰度和回滚证据通过 |
| N8 | 72h/500 请求 GA 观察、最终 gate、manifest、签收完成；否则保持 BLOCKED/DEMO_ONLY |

## 8. 证据与状态

证据必须包含环境、命令、UTC 时间、commit、样本量、exit code、路径和 SHA-256。发布 manifest 的所有路径相对 `artifactRoot=artifacts/v1.1`，并使用 `{path,sha256}`。状态仅允许：

- 评测 manifest：`draft|ready|blocked`；
- 发布 manifest：`BLOCKED|RC|DEMO_ONLY|GA`；
- 任一 P0 证据缺失、hash 不匹配、探针失败、RPO/RTO 超目标或安全负例失败，状态为 `BLOCKED`。

## 9. 回滚与恢复要求

回滚单元同时绑定上一镜像 digest、迁移兼容版本、data/knowledge/index release、模型/Prompt 和配置快照。GA 候选的 RPO/RTO 必须由三次独立演练测得，实际值分别不超过 N0 目标；dry-run、脚本存在或“容器重启成功”都不能替代恢复证据。

## 10. 变更控制

任何改变支持矩阵、阈值、状态枚举、canonical ID、迁移策略、transport、签名身份或数据保留期的变更，都必须新增 ADR、更新 schemaVersion、重跑受影响评测并保留旧 manifest。未决事项不得隐式写成完成。
