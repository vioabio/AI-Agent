# PokéAPI、队伍配置、伤害引擎与攻略检索

## 运行

项目本地运行，不需要 PostgreSQL、Redis、Docker 或独立服务器。模型问答仍需要在本机配置 DeepSeek Key；资料查询、配置保存、确定性伤害计算和本地攻略检索本身不需要模型 Key。

首次准备：

```powershell
cd "D:\ai-intern-cjt\ai-intern-folder\my\AI-Agent\tools\pokemon-engine"
npm ci
cd "..\.."
```

当前开发机已安装并验证引擎依赖。其他机器克隆后需要执行上面的 `npm ci`，不要提交 node_modules。使用 Java 21、Node.js 与项目锁文件中的版本；伤害引擎固定为 `@smogon/calc` 0.12.0。

后端使用 `local,deepseek` profiles 启动，前端保持原启动方式。新增接口需要重启后端。不要在 8123 端口已有后端时再启动第二个实例。

## 第一阶段：真实资料 → Java → 本地缓存 → 图鉴和 Agent

- `PokeApiClient` 只访问固定 PokéAPI 资源及其官方仓库的中文名称表；不跟随返回数据中的任意 URL、不跟随 HTTP 重定向。
- 支持中文名称、英文 slug、全国编号；形态 ID 使用 PokéAPI pokemon ID，物种 ID / 全国编号单独保存。
- 随包提供来源可追踪、摘要可校验的 2050 条简繁体名称索引（物种 1..1025）。中文查名不依赖实时访问 GitHub；维护者可运行 `tools/update-pokemon-names.ps1` 从官方仓库更新该名称表。
- 原始响应保存至 `.local-data/pokeapi/`，附 schemaVersion、原始 URL、SHA-256、抓取时间。文件原子写入，读取时验证摘要与来源，损坏缓存不会进入答案。
- 缓存命中时无需联网；未缓存资料首次查询需要网络。完整响应包含硬超时，避免只收到响应头后无限等待正文。
- 使用独立数据标识 `pokeapi-reference-v1`、状态 `LOCAL_REFERENCE`。这是参考缓存格式与资源范围标识，不是冻结的官方游戏补丁快照。
- 本地适配器只在 local 且非 prod/demo 时允许读取该参考状态；原候选、审核及生产发布门禁保持独立，没有把 fixture 改成 ACTIVE。
- 新会话自动选择启用的参考库；已有会话保留原版本。旧会话需要切换数据版本时，可在高级版本设置中明确选择，或新建对话。
- 图鉴支持直接加入队伍；Agent 暴露 `lookupPokemonReference`、`lookupPokemonResource`。
- 招式列表按 `scarlet-violet` 版本组筛选；名单不等于特定赛制、补丁或组合的完整合法性证明。

接口：

- `GET /pokemon/reference/status`
- `GET /pokemon/reference/pokemon/{query}?dataReleaseId=pokeapi-reference-v1`
- `GET /pokemon/reference/resources/{kind}/{slug}?dataReleaseId=pokeapi-reference-v1`
- 现有 `/pokemon/facts` 与 `/pokemon/facts/forms/{formId}` 通过同一适配器读取本地参考数据。

## 第二阶段：配招与培养配置

每个队伍成员保存：最多四个招式、特性、道具、性格、等级、六项 EV 与六项 IV。当前配置名称使用英文或上游 slug，界面有填写提示。

- EV 单项 0–252、总和不超过 510，IV 0–31，等级 1–100，性格使用 25 种英文名称。
- 配置为空时保持空招式、空道具；等级默认 50，性格 hardy，EV 全 0、IV 全 31。计算时特性未填会使用引擎默认特性，实际假设完整返回。
- 新老请求兼容：原来的 `formId + slot` 请求仍可使用。
- 本地队伍保存在 `.local-data/teams.sqlite`，重启后可回读，查询、更新、删除均按 owner 过滤。
- PostgreSQL 仓储增加 V30 `build_json` 迁移，生产库需要通过正式迁移验证后升级；不能只更新 Java 类就跳过迁移。
- 幂等指纹包含配置，避免同一幂等键下不同配招被当成相同请求。
- 保存配置不是合法性认证；当前未建立完整赛事合法组合库。

## 第三阶段：Java 调用本地伤害引擎

链路：资料核对 → Java `LocalDamageEngine` → 固定 Node 脚本 → `@smogon/calc` → 结构化结果 → AI 解释。

- 使用 ProcessBuilder 直接启动固定脚本，JSON 经 stdin/stdout 传输，不经过 shell，不执行用户命令，不需要开额外端口。
- 请求限制为显式第九世代和当前本地参考版本；支持单打/双打、天气和场地。
- 读取并核对攻防双方 PokéAPI 种族值与引擎数据；发现不一致则拒绝混用。
- 返回最小/最大伤害、目标 HP、百分比、引擎版本、双方来源摘要，以及真正采用的等级/性格/特性/道具/EV/IV 等计算条件。
- 当前桥接未表达强化、状态、墙、入场伤害和太晶等条件；结果明确注明，不把缺失条件当作已计算。
- 伤害范围不是胜率或合法性结论。状态招式不能当作直接伤害招式计算。
- 资料侧栏可从已保存队伍选攻击方/防御方，计算后“让 AI 解释结果”。Agent 也可调用 `calculateBattleDamage`。

接口：`POST /pokemon/calculations/engine-damage`。

## 第四阶段：本地攻略检索

- 默认资料位于 `src/main/resources/pokemon-guides/index.json`，当前为四篇项目原创笔记：配队角色、培养配置、伤害解读、资料与规则的区别。
- 每篇保留 ID、标题、游戏范围、作者、更新日期、可选参考链接与正文；检索结果附摘要校验和。
- 实现中文双字词和英文词的轻量关键词检索，不依赖向量数据库或 embedding API。没有匹配结果时返回空列表，不编造文章。
- 前端“攻略”可以检索并带着证据提问；Agent 使用 `searchPokemonGuides`。
- 本地参考攻略不会伪造 knowledge/index release，不会因此开放原本需要完整血缘的反馈权限。

扩充方式：在索引中新增自己的笔记，填写作者、日期、游戏范围和实际来源，重新构建/启动；或通过 `VIO_LOCAL_GUIDES_LOCATION` 指向符合相同结构的本地 JSON 文件。外部文章另行核对数据许可，不能把代码的 MIT 许可当成文章许可。

接口：`GET /pokemon/guides?query=努力值性格&gameReleaseId=pokemon-scarlet-violet`。

## 开关和路径

`local,deepseek` 默认启用以上模块。可以使用以下环境变量：

| 变量 | 用途 |
|---|---|
| `VIO_POKEMON_REFERENCE_ENABLED` | 是否启用本地参考库；关闭后伤害模块也不可用 |
| `VIO_DAMAGE_ENGINE_ENABLED` | 是否注册伤害接口和 Agent 工具 |
| `VIO_DAMAGE_NODE` | Node 可执行文件位置，默认 `node` |
| `VIO_LOCAL_GUIDES_ENABLED` | 是否启用本地攻略 |
| `VIO_LOCAL_GUIDES_LOCATION` | 索引位置，支持 `file:` 与 `classpath:` |
| `VIO_POKEMON_REFERENCE_PATH` | 参考缓存路径，默认 `.local-data/pokeapi` |
| `VIO_LOCAL_TEAMS_PATH` | 本地队伍数据库路径，默认 `.local-data/teams.sqlite` |
