# 绿白统一工作区前端改造

## 设计落地

按照确认的参考图，将 A 的浅色工作区、C 的图鉴卡片、B 的队伍编辑结构合并为一个前端工作区。

- 左侧固定品牌、新对话和服务端历史列表；收藏、版本与资料设置放在底部。手机通过菜单按钮展开历史。
- 对话视图：中间聊天、右侧图鉴与资料面板。图鉴包含形态插图、属性标签、六维种族值条、加入队伍和询问 AI，以及六人草稿预览。
- 队伍配置视图：左侧队伍草稿、六个成员卡片、当前成员的招式与培养表；并排展示伤害计算，右侧继续同一个 AI 对话。保存操作放到队伍名称旁。
- 共用游戏、语言和赛制选择；详细数据版本、来源、校验摘要和执行过程仍可展开查看，审批与停止操作继续可见。
- 对话和队伍视图只调整布局，不重建聊天与资料组件。切换、关闭资料侧栏再打开，均保留查询结果、聊天输入和未保存的队伍配置。
- 历史入口复用原有消息与 Run 快照恢复逻辑，继续携带会话的可恢复版本；读取失败不会伪造历史。
- 聊天双方都能复制消息，用户消息保留编辑、取消编辑、原消息不覆盖的行为；加载历史时不再额外插入欢迎消息。
- 本次没有增加模拟对战、胜率榜单、图片上传或自动付费模型调用。

## 主要实现

样式集中在 `vio-ai-agent-frontend/src/styles/workspace.css`，以颜色变量管理画布、边框、主色和文字色；移除已替换组件的旧深色样式，避免两套主题互相覆盖。

`GameMaster.vue` 负责共享场景和视图布局；`PokemonWorkbench.vue` 保留原有请求、版本验证、队伍 CRUD、伤害计算与攻略逻辑，补充成员卡片、草稿预览和历史列表联动。主体始终只有一个资料组件实例。

新增 `VioMark.vue`、`UiIcon.vue`、`PokemonPortrait.vue`。常用四张宝可梦插图保存在本地 `public/pokemon/`；其余合法形态 ID 使用固定 PokeAPI sprites 来源，加载失败显示中性占位。插图不作为数值事实或版本证明。来源与权利说明见 `public/pokemon/SOURCES.md`。

## 验证

- 前端 100 项契约测试通过。
- 42 项 Playwright 浏览器测试通过，覆盖登录门禁、身份切换、流式答案、消息编辑复制、资料错误与重试、队伍保存回读、伤害调用、攻略、历史、收藏，以及新增视图切换与草稿保留。
- 新增浏览器检查覆盖 1600×1000 桌面和 390×844 手机宽度，无横向页面溢出，无新增页面脚本异常。
- lint、Vue 类型检查和生产构建通过。
- 对桌面聊天、桌面队伍、手机聊天和手机队伍截图进行了人工视觉检查；截图使用测试 API 资料与消息，不代表真实模型策略输出。
- 本次只修改前端及前端测试、图片来源说明和本记录，没有为界面重跑全部后端测试。
