## 1. 本次交付

解决了 F03 的核心问题：**共享 API Key 不构成独立用户身份**。现在浏览器可以走标准
OIDC 登录，身份存放在 HttpOnly 会话中，每人一个主体；Bearer JWT 路径保留给服务账号。

| 组件 | 作用 |
|---|---|
| `OidcClientRegistrationFactory` | 由 `vio.security.oidc.*` 构造 `ClientRegistration`；只做授权码+PKCE，不做 OIDC Discovery（启动期不产生外部网络请求） |
| `OidcClientSecretResolver` | 把 `secret://` 引用解析成运行期值；缺失即拒绝启动，**不回退空密钥** |
| `OidcSecurityConfiguration`（改） | 过滤链加入 `oauth2Login`；会话策略从 `STATELESS` 改为 `IF_REQUIRED`；新增退出与 401/403 分流 |
| `application-oidc-login.yml`（测试） | 离线夹具 profile，指向本机 stub 授权端点 |
| `OidcBrowserLoginHttpTest` | 11 条离线回归 |

## 2. 三个必须说明的设计决定

### 2.1 会话策略必须是 IF_REQUIRED

原实现是 `STATELESS`。这对纯 Bearer 客户端正确，但 `oauth2Login` 需要会话来关联
「授权请求」与「回调」：`HttpSessionOAuth2AuthorizationRequestRepository` 把 state/verifier
写进会话，`STATELESS` 下回调阶段取不到，登录必然失败。
现改为 `IF_REQUIRED`，并启用 `changeSessionId()` 防会话固定攻击。
Bearer 客户端不受影响：无会话时不创建会话。

### 2.2 未认证分流：API 得 401，浏览器得跳转

Spring 默认把未认证请求 302 到 IdP。对浏览器正确，但前端用 fetch/EventSource 调
`/api/**`，拿到跨站重定向只会表现为 CORS 失败或"神秘空响应"，很难诊断。
因此按**明确信号**分流（SSE Accept / X-Requested-With / 无 Accept / 非 text/html），
不靠 URL 猜测——浏览器点击链接导航到 `/api/...` 仍应得到跳转。

### 2.3 退出必须显式豁免 CSRF

这是实施中发现并修复的真实缺陷：Spring Security 默认的 CSRF 忽略列表包含
`/logout`，但**一旦显式配置 `csrfTokenRepository`，默认忽略列表就不再自动生效**。
结果是 `POST /logout` 返回 403，用户被卡在已登录状态。
现在显式声明最小豁免（仅 `/logout`），其余状态变更仍要求 `X-CSRF-TOKEN`。

## 3. 测试发现的实现缺口（重要）

首次运行 `authorizeRequestCarriesPkceChallenge` 时**失败**，原因是：

> `OidcProperties.requirePkce` 只做配置校验（生产强制 true），
> 但我没有把 `requireProofKey` 接到 `ClientRegistration` 上。
> 于是「生产必须启用 PKCE」只是文档承诺——授权请求里根本不会出现 `code_challenge`。

这正是「配置存在 ≠ 能力生效」的典型例子，也说明断言必须落在**实际请求**上，
而不是断言配置对象。修复后测试才转为绿灯。

`OidcBrowserLoginHttpTest` 的 11 条覆盖：

| 断言 | 防的回归 |
|---|---|
| 重定向到配置授权端点、`response_type=code` | 退回 implicit/hybrid |
| 授权请求含 `code_challenge` + `method=S256`，形状为 43 字符 base64url | PKCE 只停在配置层（本轮实际命中） |
| 授权请求**不含** `code_verifier` | PKCE 被错误实现成明文 |
| 含 client_id / scope(openid) / state / 带 context-path 的回调地址 | 参数缺失或回调地址错配 |
| 重复进入生成新 state | 授权请求重放 |
| 回调匿名可达、不被重定向回登录入口 | 授权死循环 |
| 未认证 API → 401 JSON 且无 Location | 前端被 302 打断 |
| 无 Accept 头 → 401 JSON | 脚本客户端被当成浏览器 |
| 浏览器导航 → 到达授权端点 | 分流判断把浏览器当 API |
| `/health`、`/ready` 匿名可用 | 探针被登录拦死 |
| `/logout` → 204（非 403） | CSRF 豁免被配置覆盖（本轮实际命中） |
| 其余写请求在缺 CSRF token 时被拒 | 豁免面被放大 |

## 5. 未验证项（不得当成已通过）

**本机没有真实 IdP，以下全部未验证，属于 staging 验收项：**

1. **token 交换与回调失败路径**：真实 IdP 的 `code` 换 `id_token`/`access_token`、
   错误 `state` 的拒绝行为。本测试的 stub 只到授权请求阶段。
2. **id_token 验签**：`iss`/`aud`/`exp`/RS256 与 JWKS 拉取。JWKS 轮换未演练。
3. **浏览器 Cookie 的实际投递**：HttpOnly/SameSite/Secure 属性在真实浏览器与
   跨站场景下的行为；本测试用 MockMvc/同源请求，覆盖不到。
4. **会话超时**：`session-idle-timeout-seconds` / `session-absolute-timeout-seconds`
   目前**只是配置项，没有强制实现**。Spring 的 `server.servlet.session.timeout`
   与之尚未对齐，这是明确的遗留项。
5. **跨实例会话撤销**：多实例下退出/撤销只作用于单个实例。会话仍是容器内存态，
   共享会话存储（如 Spring Session + 持久化）未接入。
6. **角色不足 403 的端到端矩阵**：`OidcPrincipalPolicyAdapter` 的拒绝分支有单测，
   但未经真实 IdP claim 端到端验证。
7. **前端联调**：前端登录入口/退出按钮尚未接入 `/oauth2/authorization/vio` 与 `/api/logout`。

## 6. 接入方式（staging）

```bash
VIO_OIDC_ENABLED=true
VIO_OIDC_REQUIRED=true
VIO_OIDC_ISSUER_URI=https://<idp>/realms/<realm>
VIO_OIDC_JWKS_URI=https://<idp>/realms/<realm>/protocol/openid-connect/certs
VIO_OIDC_AUTHORIZATION_URI=https://<idp>/realms/<realm>/protocol/openid-connect/auth
VIO_OIDC_TOKEN_URI=https://<idp>/realms/<realm>/protocol/openid-connect/token
VIO_OIDC_AUDIENCE=vio-api
VIO_OIDC_CLIENT_ID=vio-web
VIO_OIDC_CLIENT_SECRET_REF=secret://oidc/client-secret
# 解析规则：secret://<name> → VIO_OIDC_SECRET_<NAME 大写>
VIO_OIDC_SECRET_OIDC_CLIENT_SECRET=<由 Secret Store 注入>
# 必须与 IdP 侧登记值完全一致；context-path /api 由容器加上
VIO_OIDC_REDIRECT_URIS=https://<host>/api/login/oauth2/code/vio
```

同时需要在 `vio.security.oidc.policy` 配置 `principal-tenants` / `tenant-roles` /
`role-tools`，否则主体会因缺少 tenant/role 映射被 fail-closed 拒绝（这是有意行为）。
