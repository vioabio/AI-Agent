# 统一工作区与资料队伍联动

日期：2026-10-20

## 已实现

- 主入口统一为“宝可梦助手”。旧 `/super-agent` 跳转至助手，保留旧入口会话作用域；旧 `/pokemon-workbench` 打开助手资料侧栏。
- 聊天与侧栏共用游戏、赛制、规则和数据版本；规则、数据版本放在高级设置中。侧栏按图鉴与计算、队伍、历史与收藏、活动分类。
- 图鉴卡“加入队伍”自动填写空槽位，拒绝重复、超过六人和混合数据版本。已有草稿可清空；隐藏侧栏不会销毁草稿。
- 资料卡“询问 AI”将来源、版本和事实放进聊天草稿，不自动调用付费模型。
- 已保存队伍“让 AI 分析”按成员形态 ID 逐一读取对应数据版本事实，再生成草稿。任何成员查询失败或版本不一致，均不生成分析草稿。
- 新增 `GET /pokemon/facts/forms/{formId}?dataReleaseId=...`，复用已有来源审核门禁，缺少事实、版本或审核未通过时拒绝返回。
- 历史会话可继续聊，沿用服务端会话 ID。若能读取原 Run，带回其版本与赛制；原 Run 已丢失时提示用户确认当前版本，不伪造历史上下文。
- 新对话和选中的历史会话更新当前标签页的会话指针。URL 仅携带会话标识和版本选择，问题与答案不放进 URL。
- 手机端以覆盖侧栏展示资料，询问 AI 后返回聊天；桌面端聊天、资料并排。
- 首页删除“全世代”和默认文件/PDF能力等超出当前开放范围的宣传。高级工具执行、权限审批和审计仍使用原 Run 链路。

## 使用流程

1. 进入宝可梦助手，选择游戏与赛制。
2. 打开“资料与队伍”，查询英文名称或全国编号，例如 `squirtle` / `7`。
3. 点击资料卡“加入队伍”，填写队伍名称后保存。
4. 点击已保存队伍“让 AI 分析”，确认聊天草稿、赛制和版本后发送。
5. 在“历史与收藏”选择会话，点击“继续这段对话”。

## 验证

- 后端资源服务/Controller：11 项通过，包括形态 ID 的 HTTP 路由绑定、必填版本、未知事实及候选版本拒绝。
- 前端契约：100 项通过。
- 浏览器：35 项通过，涵盖登录、权限、会话过期、两个旧入口兼容、流式消息、队伍分析、历史续聊及手机侧栏。
- OpenAPI 相关契约：19 项通过，生成器与仓库快照一致。
- 前端 lint、typecheck、生产构建通过。
- 浏览器业务数据使用测试接口；未将测试数据当作已上线资料，也未调用真实 DeepSeek 计费接口。

## 仍需推进

同日后续更新：下列第 1、3、4 项已完成本地首版，第 2 项中的队伍已接入 SQLite，收藏持久化仍待补充。新增攻略检索、真实资料与伤害引擎的范围和测试见 [四阶段落地记录](PokéAPI与队伍伤害攻略四阶段落地_2026-10-20.md)。以下保留当时的任务清单作为过程记录。

1. **真实资料接入**：本地事实仓储默认为空。建立 PokéAPI 等来源的数据导入、版本映射、校验、审核与发布流程；保持候选数据不进入正式读取链。只填一个数据版本名称不会自动下载图鉴。
2. **本地队伍与收藏持久化**：SQLite 聊天历史已存在，本次未将内存队伍/收藏仓储改为 SQLite。当前本地保存的队伍不应承诺重启后保留。
3. **完善队伍配置**：保存招式、特性、性格、道具、努力值等，目前成员名单只能支持有限的属性与角色分析。
4. **伤害引擎**：评估并封装 `@smogon/calc`，冻结引擎、数据和规则版本，加入标准用例对照，不把现有属性倍率计算描述成完整对战模拟。
5. **聊天自动关联资料**：本次支持手动查询与携带资料提问；尚未实现从每条回答自动识别实体并填充侧栏。后续通过结构化工具输出联动，不从自由文本猜事实。
