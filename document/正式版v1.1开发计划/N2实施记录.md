# N2：可恢复 Run、事件与 Outbox 实施记录

## 已落地

- `agent_checkpoint`、`agent_run_lease`、`agent_effect_ledger`、`model_invocation_cache`、`agent_event_outbox` 等持久化骨架已加入迁移脚本。
- `V25__model_invocation_cache_integrity.sql` 为模型缓存的 `request_hash` 和
  `response_digest` 增加 64 位十六进制摘要约束，并要求每条记录恰好携带
  `encrypted_response` 或受控 `artifact_uri` 之一；约束先以 `NOT VALID` 方式部署，
  待历史数据清理/回填后再由 staging DBA 执行 `VALIDATE CONSTRAINT`，避免把旧脏数据
  静默当作可重放结果。
- 新增 `ModelInvocationCacheService`：版本化 grounded prompt 生成 request hash，命中时
  先校验密文解码结果的摘要并跳过模型调用；未命中时仅在受控 codec 编码成功后落库。
  `VersionedKnowledgeRunFacade.answerReplayable(...)` 已接入该可选服务；普通
  `answer(...)`（包括可能触发工具副作用的 VioManus）不会自动进入缓存。缓存默认关闭，
  缺少 KMS/codec 或版本配置时按 `fail-closed` 策略拒绝伪装成可恢复调用。当前仓库没有
  默认明文 codec，真实 KMS/envelope 实现与跨实例原子 reservation 仍需 staging 验收。
- Run 事件写入 outbox，publisher 采用至少一次语义；`outbox_id` 作为消费者幂等键。
- outbox 领取增加 `claimed_by` 与 `claim_expires_at` 租约。过期 CLAIMED 消息可被其他 worker 回收，且只有原领取者可标记成功/失败。
- 新增可插拔 `RunOutboxSink` 与 `RunOutboxDispatcher`。`VIO_EVENT_BROKER_ENABLED=false`（默认）时不加载 dispatcher；启用但未提供 sink 时不会领取消息。
- 失败按退避重试，达到 10 次进入 DLQ；错误信息经过类型、长度和换行清洗。

### 事件保留清理（本次增量）

- `EventRetentionService` 增加定时 sweep 入口；`VIO_EVENT_RETENTION_CLEANUP_ENABLED=false`
  默认关闭，只有完成备份/恢复演练后才允许显式打开。
- `EventRepository.purgeExpired` 在内存和 JDBC 实现中均按批次处理：只清理已经产生终态的
  Run，保留 `run.completed/run.failed/run.cancelled/run.timed_out` 终态事件，并跳过仍有
  未发布 outbox 的事件。
- JDBC 清理结果写入 `agent_event_retention`（类别、保留起点、截止时间、清理时间、删除行数），
  同时新增 `V24__event_retention_cleanup_index.sql` 优化按时间扫描。清理异常只返回脱敏错误类型，
  不把数据库连接/SQL 内容写入日志。
- 新增 `EventRetentionServiceTest` 覆盖默认关闭、终态保留和活跃 Run 不清理；当前仍未在真实
  PostgreSQL/备份系统执行 Flyway、删除窗口、恢复和 RPO/RTO 演练，不能据此宣称 retention GA。

## 验证与边界

- `RunOutboxRepositoryTest` 覆盖 owner 隔离和过期租约重领。
- `RunOutboxDispatcherTest` 新增覆盖：sink 缺失时不领取消息、成功发布只完成当前 owner 的消息、失败回退重试并清洗敏感错误文本；与恢复策略回归合计 12/12 通过。
- 目前没有内置 Kafka/Redis 客户端，也未证明真实 broker、跨实例网络投递或端到端恢复指标；需在 staging 注入经评审的 `RunOutboxSink` 实现后再验收。
- 模型缓存的本地语义由 `ModelInvocationCacheServiceTest` 覆盖（命中跳过调用、配置不完整
  fail-closed、禁用旁路、摘要/载荷完整性校验）；生产必须提供 KMS/envelope
  `ModelInvocationCacheCodec`，并补充密钥轮换、TTL、跨实例竞争和成本不重复计费的现场证据。
- JDBC 迁移依赖 PostgreSQL/Flyway；本轮本地 `mvnw clean test` 已完成编译与单元/上下文回归，真实 PostgreSQL/Flyway、跨实例 broker 和恢复演练仍需 staging 现场证据。

## 接入真实 broker 的前置条件

1. 提供实现 `RunOutboxSink` 的 Spring Bean，并按 `outbox_id` 做消费幂等。
2. 在 staging 验证重启、租约过期、重复投递、DLQ 回放和监控告警。
3. 通过质量门禁后，才将 `VIO_EVENT_BROKER_ENABLED` 切换为 `true`。

## N2 6.2–6.7 契约审计与本地增量（2026-09-04）

### 已确认/已补齐

- `AgentRunController.parseCursor` 对 `Last-Event-ID` 和 `afterEventId` 的负数、非数字输入已返回结构化 400，
  不会静默回到游标 0。
- 事件游标过期现在返回结构化 HTTP 410：`EVENT_CURSOR_EXPIRED`、`retainedFromEventId` 和当前 Run
  快照入口 `latestRunUrl`。客户端可先读取 `/chat/runs/{runId}` 最新摘要，再以
  `afterEventId=retainedFromEventId-1` 重拉首个仍保留事件；旧的两字段
  `EventCursorError` 构造仍兼容程序化调用。
- `ResourceController` 已提供会话、队伍、收藏的 CRUD、owner 过滤、游标分页和创建幂等；资源游标也有
  400/410 处理。`PokemonAgentRunService.cancel` 已有状态 CAS 与 `Idempotency-Key` 重放语义。
- `/api/conversations/{conversationId}` 与兼容 `/chat/conversations/{conversationId}` 删除入口现已统一复用
  `PokemonAgentRunService.deleteConversation`：在同一生命周期锁内校验 owner、取消并移除当前进程 active Run、
  删除消息并删除/软删除会话。没有 Spring 容器的旧程序化构造器仍保留仓储级回退，不能代表生产路径。
- `WAITING_APPROVAL` 的重启恢复现在只接受事件中唯一的 `approvalId`，并要求持久仓储中存在同一
  `runId/userId`、未过期且状态为 `PENDING` 的审批；恢复只重建等待状态、重新挂起过期计时器和 Run 超时，
  不重放模型或工具副作用。缺少记录、审批已决定或已过期时统一以 `RECOVERY_UNSAFE` fail-closed。
- HITL 查询/决定接口区分未知审批与已过期审批：未知 ID 返回 **404**，已过期审批返回 **410**；决定与过期
  并发时仍以持久化 CAS 结果为准，不能把过期项写成批准或拒绝。
- Run 取消请求支持结构化 `reason`。原因经过脱敏、控制字符/长度清洗并纳入新幂等 hash；当旧客户端未提供
  原因时，兼容读取 v1.0 的旧 hash 记录，避免升级后重复提交产生孤儿 Run；显式新原因不会回退到旧 hash。
- JDBC 会话软删除/Run 终态竞态已收敛到同一可见性锁：先取得 `LOCK_VISIBLE_RUN` 再检查终态，避免删除或终态提交
  与非终态事件交错写入。软删除会话对普通读取不可见，但 owner/生命周期校验仍保持一致。

### 仍为 pending（不能以本地单测代替现场验收）

- `/events/stream` 当前是一次性事件页 snapshot；没有 Redis Streams/其他 broker 的跨实例 live fan-out、
  背压和断开连接指标。断线不取消 Run 的服务语义已有，但需 HTTP/多实例演练证据。
- `recoverInFlightRuns` 已增加显式 `RunRecoveryPolicy`：只有 `step_no=0` 且
  `next_action=dispatch`（尚未进入模型/工具执行）才允许重新提交 worker；
  `execute-answer`、`commit-answer`、`finished` 或上下文/执行器版本不一致的 checkpoint
  统一以 `RECOVERY_UNSAFE` 终态 fail-closed，并在事件中记录步骤/动作摘要，避免重启后
  重复模型计费、工具写入或 MCP 调用。新增 `RunRecoveryPolicyTest` 与
  `PokemonAgentRunServiceRecoveryTest` 覆盖允许/拒绝路径。
- 当前仍没有 checkpoint-aware executor、持久模型响应 artifact 到完成事件的安全提交协议，
  因此已进入执行阶段的 Run 会安全失败而不是恢复；跨进程 lease/CAS、真实 PostgreSQL
  重启和 RPO/RTO 仍待 staging，不能据此宣称 N2 checkpoint resume/GA 已闭环。
- cancel 与完成并发、双 worker 抢占、状态/事件/outbox 原子提交、retention 删除窗口/备份恢复以及资源
  删除后的缓存/事件语义，尚缺故障注入和数据库现场证据。
