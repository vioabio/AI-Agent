# PokéAPI 查询 500 与本地代理修复

## 现场根因

参考资料接口已注册，`/api/pokemon/reference/status` 返回 200；但中文“杰尼龟”和英文 `squirtle` 均在约 8 秒后返回 500。Java 真实网络测试复现了完整正文读取超时。

相同电脑的 PowerShell 请求 PokéAPI 返回 200。Windows 系统代理指向本机 HTTP 代理，Java 当前进程未使用该代理。Maven 启动器的代理配置也不能等同于 IDEA 或测试子 JVM 已配置代理。网络超时又被旧通用异常处理包装成“服务器内部错误”，造成前端无法提供有效提示。

## 本次改动

- 资料客户端支持专用配置 `vio.pokemon.reference.proxy`，由环境变量 `VIO_POKEAPI_PROXY` 提供；空值读取缓存目录同级的 `pokeapi-network.properties` 中的 `proxy`。
- `http://主机:端口` 使用 HTTP CONNECT 代理访问固定 HTTPS 来源，仍验证 TLS，仍不跟随上游重定向；`direct` 显式直连。没有专用配置时保留 JVM 默认 ProxySelector。
- 代理 URL 不接受用户名、密码、路径、查询参数或片段。该配置不影响模型 API 客户端，也不改变允许访问的资料来源。
- 上游超时、连接失败、非 200/404 状态转换为独立异常，HTTP 返回 503；不存在的资源仍为 404，缓存损坏等应用问题仍单独失败，不清空或静默替换资料。
- 前端区分资料服务不可达，提示检查网络或资料代理，并提供重试；不展示底层异常及代理细节。
- 修正实际上游返回 `zh-hans`、`zh-hant` 小写语言标识时的中文名称匹配与多语言资源筛选。
- 提供 `tools/warm-pokemon-reference.ps1`：用 PowerShell 系统代理下载固定官方来源，校验资源身份，生成与 Java 相同的摘要与来源缓存格式，并保留已有快照。
- OpenAPI 补充资料上游不可达的 503 响应。

## 当前电脑处理

已在忽略跟踪的 `.local-data/pokeapi-network.properties` 中保存当前本机代理设置；之后启动的新后端会读取，无需把代理配置写入含密钥的私有文件。

已通过系统代理预热杰尼龟的 Pokémon、species 原始官方响应缓存；当前运行的旧后端立即读取缓存，中文和英文查询均实测返回 HTTP 200，全国编号 7、HP 44，来源为官方 PokéAPI。没有调用模型 API，也没有改写原有缓存或重启用户服务。

现在刷新前端即可重试“杰尼龟”。重启后端后，专用代理与中文名称大小写修复生效。若本机代理端口以后变化，更新上述本地文件并重启；不使用代理时设 `VIO_POKEAPI_PROXY=direct`。
