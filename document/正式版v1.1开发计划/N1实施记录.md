# N1 知识摄取耐久核心实施记录

> 状态：代码已实现（candidate）；真实 PostgreSQL/PGVector、双实例和 staging 现场证据仍待验收。

## 已实现

- `V8__durable_knowledge_ingestion_jobs.sql`：`knowledge_ingestion_job`、`knowledge_ingestion_attempt`、`knowledge_ingestion_outbox`、`knowledge_ingestion_dlq` 和 `vector_build_job`，包含状态约束、幂等/预约唯一键、索引和外键。
- `KnowledgeIngestionJobService`：显式 submit、SHA-256 reservation、worker `reserveNext`、lease 续租、attempt、有限重试（指数退避 + 稳定 jitter）、毒数据 DLQ、operator replay、at-least-once outbox publisher。
- `KnowledgeIngestionWorker`：可配置、bounded 的定时 worker 适配器；只有
  `VIO_RAG_INGESTION_WORKER_ENABLED=true` 才创建，单次最多处理配置批量，领取/仓储异常不会杀死调度线程，缺少 outbox sink 时明确返回 `sinkMissing`，不把“无 broker”写成已投递。
- `InMemoryKnowledgeIngestionJobRepository`：开发/单测实现；`JdbcKnowledgeIngestionJobRepository`：prod profile 下的 PostgreSQL `FOR UPDATE SKIP LOCKED` 和事务实现。
- `KnowledgeLifecycleController` 新增异步 Job 提交、状态、attempt 和 DLQ replay HTTP 契约；原同步 `/knowledge/ingestions` 保留兼容。
- `KnowledgeIngestionJobServiceTest` 覆盖相同 checksum 幂等、并发 reservation、lease owner、retry/backoff、DLQ/replay 和 outbox 失败终态。
- `KnowledgeIngestionWorkerTest` 覆盖批量上限、缺少 sink 的显式状态和不安全配置值的边界收敛。
- `KnowledgeIngestionMigrationContractTest` 增加离线 schema 契约守护，确保五张耐久摄取/构建表、reservation 唯一性和 DLQ retention 字段不会被误删；真实 SQL 执行仍由 PostgreSQL 集成测试负责。

## 调用示例（不包含任何密钥）

```text
POST /api/knowledge/ingestion-jobs
{
  "stagedFile": "guide.md",
  "targetKnowledgeReleaseId": "knowledge-candidate-1",
  "ingestionContractVersion": "knowledge-ingestion-v1.1",
  "idempotencyKey": "guide-2026-09-03",
  "source": { ... },
  "document": { ... }
}
```

HTTP 提交只创建 `QUEUED` Job。后台 worker 调用 `runNext(workerId)`，成功后同事务写入 `SUCCEEDED` 和 outbox；可重试错误进入 `RETRY_WAIT`，不可重试或达到上限进入 `DLQ`。DLQ replay 必须提供 operator、原因和新的幂等键。
