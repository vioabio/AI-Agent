## 2. 服务端实现

### 2.1 匿名可读会话状态

新增 `AuthSessionController` 的 `GET /api/auth/session`，operationId 为 `getAuthSession`。返回直接 JSON，`Cache-Control: no-store`，无需 API Key。接口不创建匿名 HttpSession，不注册工具 TokenBinding，也不读取业务资源。

```json
{
  "mode": "oidc",
  "authenticated": false,
  "accessDenied": false,
  "principalId": null,
  "tenantId": null,
  "roles": [],
  "serverTime": "2026-10-12T00:00:00Z",
  "absoluteExpiresAt": null,
  "loginUrl": "/api/oauth2/authorization/vio",
  "logoutUrl": "/api/logout",
  "csrf": {
    "enabled": true,
    "available": true,
    "headerName": "X-CSRF-TOKEN",
    "cookieName": "CSRF-TOKEN"
  }
}
```

- 已登录且策略允许时，返回受信任的 principal、tenant、角色和绝对期限。
- 已认证但没有应用策略时，返回 `accessDenied=true`、`authenticated=false`，不回显被拒绝主体的 claims。
- `api_key` 和 `disabled` 模式返回空个人身份、空登录/退出 URL，前端显示模式标识。接口不会把共享 API Key 伪装成个人账号。
- API 客户端可主动携带有效 Bearer 查询受信任身份；浏览器 bootstrap 只发同源 cookie，完全不发送页面临时 API Key 或 Bearer。
- 所有声明为 nullable 的字段始终存在，避免全局 Jackson NON_NULL 设置破坏前端门禁。

### 2.2 绝对期限进入实际过滤链

`OidcLoginSuccessHandler` 在 Spring 已验证浏览器身份后，调用 `OidcSessionLifetime.start` 写入服务器持有的 LoginStamp。时间戳绑定 registration、issuer、subject 与 principalName。

登录成功清除 SavedRequest，并固定回到同源 `/`。前端只恢复预先允许的业务路径，不接受任意外部 return URL，也不保存 URL 的 query/hash。

`OidcAbsoluteSessionFilter` 在 Bearer 验证之后、业务授权之前核验时间戳。缺失、损坏、换主体、时间戳异常、恰好达到或超过 deadline 的会话均清理身份和 Session；公开状态接口返回匿名，业务接口按正常未认证路径拒绝。已有但没有可信时间戳的旧会话必须重新登录。

期限受 `VIO_OIDC_SESSION_ABSOLUTE_TIMEOUT_SECONDS` 控制，默认 28800 秒。请求活动只影响既有 idle timeout，不重写绝对登录时间；配置收紧可缩短已有期限，配置放宽不能延长已经记录的 deadline。

有效 Bearer JWT 独立于失效的浏览器 cookie，不因旧 cookie 而被误清理。浏览器 PrincipalPolicy/TokenBinding 取绑定 TTL 与 Session deadline 的较早者；JWT 另取 token exp 的较早者。期限边界包含等号。

### 2.3 退出与工具重试

`POST /api/logout` 恢复 CSRF 校验，返回空 204。浏览器 Origin 或 Referer 若存在，必须通过允许源校验；没有这些头的非浏览器调用沿用既有行为，但仍需合法 CSRF cookie/header。OIDC 关闭时显式禁用 Spring 默认 logout，路径返回 404。

工具入口授权之后可能经过审批、排队或重试。`ToolExecutionGateway` 在 executor 中每次真正启动 callback 前再检查策略与 TokenStore scope，防止入口通过后过期仍执行下一次工具调用。过期/撤销返回 REJECTED，不继续重试；这里不重复消费配额，也不承诺中断已经执行中的 callback。

## 3. 前端实现与隔离边界

`src/auth/session-state.js` 提供可注入 transport、clock 和 timer 的状态控制器；Vue composable 负责浏览器事件与缓存隔离，App 根据状态决定是否挂载业务视图。

| 状态/触发 | 页面行为 |
|---|---|
| 首次加载 | 确认会话完成后才挂载业务页面 |
| 匿名 | 显示“登录后继续”，点击登录才导航固定入口 |
| 策略拒绝 | 显示“当前账号未获授权”，切换账号先完成本地退出 |
| 登录有效 | 展示账号与租户，开放工作台/会话页面 |
| 绝对到期或当前身份业务 401 | 清身份与恢复缓存、卸载业务页面、显示重新登录提示 |
| 业务 403 | 保留身份，显示资源权限错误 |
| bootstrap 异常或响应损坏 | 关闭业务页面并提供重试 |
| 退出进行中 | 立即停止账号数据展示与业务读取 |
| 退出失败或返回非 204 | 显示“退出未完成”和“重试退出”；窗口 focus/visibility 不自动重开业务 |
| 退出成功 | 广播会话结束并重新确认匿名状态 |

客户端以 `absoluteExpiresAt - serverTime` 计算剩余时长，从请求开始计时，网络延迟不能延长会话。身份准备完成后再次检查期限，避免异步摘要计算跨过 deadline 时短暂开放页面。服务端仍是实际访问与工具授权边界。

### 3.1 旧账号不能影响新账号

- 会话 GET 使用 generation 与 AbortController；旧 GET 和旧身份准备不能覆盖新状态。
- 所有 fetch 请求捕获认证 epoch，响应通过 WeakMap 保留请求归属。旧账号的 HTTP 401 或迟到 JSON 中的业务 401 不会让新账号失效。
- 身份变化、退出、到期时推进 Run 恢复 epoch。旧 create/stream 回调不能重新写回旧 Run，也不能清除新账号指针。
- `router-view` 按 viewVersion 重挂载；现有业务组件在卸载时关闭订阅并取消流式读取。
- BroadcastChannel 只发送会话结束类型/原因；支持的同源标签页收到后关闭身份。它是浏览器同步机制，不能替代服务端多实例撤销。

### 3.2 恢复缓存的内容

只在 sessionStorage 中保存本页 Run/conversation/cursor 元数据及 mode/principal/tenant/roles 的 SHA-256 摘要。相同身份刷新保留指针；账号、租户或有效角色变化清理旧指针。摘要不是匿名化承诺，不作为服务端授权依据。

清理只作用于 `vio.agent.run-resume.v1`、`vio.agent.resume-owner.v1`、`vio.agent.conversation.v1.*`，保留其他应用的 Storage。WebCrypto 或 Storage 不可用时清除跨刷新指针并继续以内存运行。CSRF 值、API Key、Bearer、原始身份 claims、Prompt 与答案不进入这套持久化缓存。

## 4. 接入与复跑方式

### 4.1 同源开发与部署

前端统一使用 `/api`。Vite 代理到 `http://127.0.0.1:8123`，`changeOrigin=false`，保留浏览器 Origin 和前端 Host；开发服务器关闭通用 CORS。

真实本地接入应保持同一个前端 origin，例如 `http://localhost:3000`。在 IdP 和 `VIO_OIDC_REDIRECT_URIS` 中精确登记 `http://localhost:3000/api/login/oauth2/code/vio`，不要误登记后端 8123 端口或混用 localhost/127.0.0.1。相应允许源配置使用同一个 origin。

实际登录仍需要现有 issuer/JWKS/authorization/token URI、audience、clientId、secret 引用、租户角色与工具策略。沿用项目 secret resolver；本轮没有读取或改写 `.env`，没有持久化真实凭据。

生产按现有前端反向代理提供 HTTPS 同源 `/api`，保留 Secure、HttpOnly 会话 cookie。HTTP 本地开发的 cookie-secure=false 仅适用于受限开发配置，不能作为生产默认。真实代理、cookie 与 redirect URI 组合尚须 staging 验证。

## 7. 本轮模块学习路线

1. 从 `AuthSessionController` 和 OpenAPI 的 SessionStatus 阅读响应契约，区分认证、应用授权、兼容模式与 CSRF 元数据。
2. 阅读 `OidcSecurityConfiguration` → `OidcLoginSuccessHandler` → `OidcSessionLifetime` → `OidcAbsoluteSessionFilter`，追踪请求如何建立和失去可信身份。

4. 阅读前端 `session-state.js` → `useAuthSession.js` → `App.vue`，在开发者工具中观察匿名、403、401、退出失败与到期的门禁。

6. 复跑 `auth-session-contract.test.mjs`、`run-resume-isolation.test.mjs`、`auth-session.spec.js`，把旧请求迟到、异步 JSON、身份准备到期、窗口聚焦等场景对应到代码保护。
