# 秋招独立评测执行手册

本批新增30组候选任务，五类各6组：多轮指代、版本冲突、无答案、开放建议、依赖故障。题目和判据在 `evaluation/campus/independent-20261120/` 冻结。当前状态为**未执行、未人工复核**，不能写成通过30组。它们没有本批执行或据此修复的记录；场景仍与历史任务有语义重叠，不宣称完全盲测。首次用于修复后，保留原始首答并降为回归集，另补新题。

## 环境及采集

使用独立测试实例、测试账号和数据目录，不使用个人队伍。记录源码提交、构建摘要、模型、工具开关、索引和语料摘要。既有采集器创建单成员test1，并验证队伍及配置前后一致。通过运行时诊断核对当前配置，开关开启不等于实际走到对应路径。

在项目根目录执行，输出目录必须尚不存在：

```powershell
node tools/campus/campus-independent-20261120.mjs subset artifacts/i20-normal-suite normal
node tools/campus/answer-quality-collect.mjs artifacts/i20-normal-suite artifacts/i20-normal-first http://127.0.0.1:18141/api first-answer
node tools/campus/campus-independent-20261120.mjs report artifacts/i20-normal-suite artifacts/i20-normal-first/first-answers.json artifacts/i20-normal-pending.json
```

首次采集前将最终源码提交及配置摘要另存实验记录。采集不得重试后覆盖首答。输出目录的新名字不能使同一题重新成为首答；维护一次性执行登记。原始正文、事件、失败、采集器摘要必须保留。

采集器默认两组并发；如果分析时延，需记录并发条件，不能当作独占资源时延。仅做质量采集时沿用此设置。采集器遇到等待审批会取消；本批正常题不要求写入。真实确认保存由演示及既有HITL专题验证。

## 六组故障的操作方式

从 `cases.json` 读取各故障题的 `faultSetup`。每次只启用一种故障，在独立实例与受控回环代理上注入，保存代理访问证据、响应或断流记录及实际Run事件。不要在日常服务上修改代理或清缓存。

用 `subset artifacts/i20-fault-1-suite I20-dependency-fault-1` 生成单题套件，再用同一个采集器采集。依次覆盖模型超时、资料503、Embedding超时、精排非法分数、模型正文后断流。代理未命中、缓存掩盖故障、模型未调用、没有非空精排候选，都属于BLOCKED，不能算通过。故障前后分别做一次正常对照，记录恢复结果。

第6题浏览器断网必须实际操作浏览器：SSE建立后断网2秒再恢复，保存网络记录、原Run ID、断线前游标、补读事件及最终页面正文。通用HTTP采集器不能完成这一步，不可用其正常问候结果替代。可参考 `tools/campus/stream-fault-browser.mjs` 的浏览器断网及重复Run检查；该旧脚本使用受控模型断流场景，并非本题首答证据。

当前交付提供故障规格和执行判据，未自动创建故障代理或运行故障实验。需要对所选模型和资料适配地址配置代理后执行，缺少环境时明确登记BLOCKED及缺少的配置。

## 统计与人工复核

每轮依据事件中的实际模型用量分类：MODEL表示实际调用聊天模型；LOCAL要求完整且可观测的零调用；缺用量证据为UNKNOWN，不能按零调用推断为程序直答。组内任何一轮使用模型则整组为MODEL，全部完整零调用才为LOCAL。Embedding和精排调用不计作聊天模型调用，需另外记录服务故障与耗时。

报告保留30组分母，正常24组和故障6组分别报告PASS / FAIL / BLOCKED / PENDING。补充分桶的组数、成功数、逐轮模型调用、耗时与人工判据。故障题的预期失败终态可能是正确行为，因此终态FAILED本身不能自动判任务失败。整个任务判分由人工核对criteria及故障证据。

先生成pending报告，从rows复制observationSha256，建立review数组：

```json
[
  {
    "caseId": "I20-open-advice-1",
    "observationSha256": "复制该条实际观察摘要",
    "reviewerType": "human",
    "reviewer": "实际审核人",
    "reviewedAt": "实际ISO时间",
    "verdict": "PASS",
    "evidence": "逐项记录criteria判定、原文位置、实际来源与快照核对",
    "faultEvidence": "仅故障题填写实际代理或浏览器证据位置"
  }
]
```

用report命令第四个参数传review文件，输出新报告。脚本校验绑定摘要、实际人名、审核时间、证据、完整轮数、配置与队伍不变及故障证据。脚本无法证明审核人确实完成阅读，审核责任仍由实际签署人承担。关键抽查包括全部6组开放建议、全部故障题及版本冲突题；对外声称整批通过前，所有组均须审核。AI可辅助，不能冒签人工审核。

简历数字待执行后填写：`在30组候选任务上，完成X组独立首答评测，其中模型任务Y组、程序直答Z组、未知U组；人工审核通过P组，失败F组，阻塞B组。` 目前这些值均未产生。
