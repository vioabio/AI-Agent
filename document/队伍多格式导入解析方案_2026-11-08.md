# 队伍多格式导入解析方案

状态：首轮已实现 JSON v1/v2、Showdown TXT/粘贴、CSV、DOCX 和文本 PDF。Excel、图片 OCR、扫描 PDF 及多队伍批量选择尚未实现，不能作为已支持格式宣传。

太晶字段已接入队伍模型、编辑、存储回读、JSON v2、AI 修改保留逻辑与 API 契约。旧 v1 文件兼容读取；未指定太晶属性保留为空，不假定已经太晶化，现有伤害计算默认不激活太晶化。

本轮不支持的昵称、性别、闪光、亲密度等字段会报错阻止导入，不能静默丢弃；请用户明确移除不支持字段后重试。特殊形态若无法通过实际资料接口解析，也会阻止导入，而不是映射到错误形态。

CSV 第一行使用英文表头，示例：

```csv
species,ability,item,nature,level,teraType,move1,move2,hpEV,atkIV
Squirtle,torrent,leftovers,modest,50,water,surf,protect,252,0
```

允许表头：species 或 formId，以及 ability、item、nature、level、teraType、move1～move4、hpEV/atkEV/defEV/spaEV/spdEV/speEV 与对应的 IV 列。中英文性格、太晶属性支持名称匹配；中英文资源名称按候选解析。英文名称采用规范标识，尚不代表经过赛制合法性校验。

DOCX/PDF 应包含同样的 Showdown 配置文本或 CSV 内容，不支持任意攻略文章自动推测队伍。文件不超过 1 MB，PDF 最多50页、提取文本不超过20000字。XML 外部实体、宏、过大解压数据和过深嵌套被拒绝；文档不发给模型或OCR服务。

## 一、统一处理链路

文件选择 → 类型及大小检查 → 格式解析器 → 标准队伍草稿 → 版本及成员解析 → 字段校验 → 预览/修正 → 确认载入 → 保存为新队伍。

文件后缀只是提示，实际识别必须结合内容与文件签名。无法确认格式时返回明确原因，不把任意文本猜成队伍。解析不直接写库，也不覆盖已保存队伍。

## 二、支持顺序

| 阶段 | 格式 | 解析方式 | 验收重点 |
| --- | --- | --- | --- |
| 1 | 项目 JSON | 复用现有 schemaVersion 与校验模块 | 新旧版本兼容，完整往返一致 |
| 2 | Showdown TXT、粘贴文本 | 按六人分段、字段标签和招式行进行确定性解析 | 昵称/形态/性别、道具、特性、性格、EV/IV、等级、太晶属性 |
| 3 | CSV、Excel | 表头映射与成员行解析，复杂表格要求用户确认列映射 | 一行一成员，招式四列，避免错列和串队 |
| 4 | DOCX、文本 PDF | 提取段落/表格，再交给文本队伍解析器 | 文件内多队伍分离，页眉页脚不当作成员 |
| 5 | 图片、扫描 PDF | OCR 后进入同一文本解析流程 | 对低置信度名称和数字逐项确认 |

不建议第一版直接“上传任意文件让模型自动组队”。模型只能辅助候选字段提取，不得替代资料匹配、数值校验或用户确认。

## 三、统一结果结构

返回 `teams`、`warnings`、`errors`、`unresolvedFields` 和来源位置。每支队伍包含名称、游戏/赛制/数据版本和成员；成员包含槽位、形态、道具、特性、性格、等级、招式、EV/IV、太晶属性。

字段同时保留 `rawValue`、标准值、来源页码/行号及解析状态；OCR 另保留置信度。名称通过本地资料目录匹配为稳定标识。中文名与英文名、昵称与物种名必须区分；不能简单用全国编号当所有形态的 formId。

太晶字段现已扩展；完整 Showdown 往返仍受上文列明的昵称、性别等未建模字段限制。后续增加任何字段，都需要同步领域模型、存储、API、编辑页及文件 schema。

## 四、校验与界面

- 复用现有 1–6 位成员、重复槽位/形态、最多四招、性格枚举、等级及 EV/IV 范围校验。
- 文件缺少游戏或赛制时，要求用户选择，不能根据当前页面或描述静默认证合法性。
- Showdown 省略值可按格式规范推导，但必须标注“格式默认值”；不能把模型猜测当默认值。
- 无法解析的名称给出候选，由用户确认；不替换成“最相似”的宝可梦后自动保存。
- 导入预览显示六个成员图标、每位成员的解析结果及问题数量。多支队伍允许逐支选择；存在阻断错误时不允许载入。
- 格式正确、单项学习记录匹配和正式赛制合法性是不同层次，需要分别标记。

## 五、实现边界与安全

JSON、TXT 可先在浏览器处理。Office/PDF/OCR 需要独立的后端文件解析入口，采用当前登录鉴权；设置格式对应的大小、页数、超时与解压后体积限制。现有 JSON 上限为 1 MB，其他格式限额需要单独制定，不能盲目复用或无限放开。

文件及提取文本都是不可信数据。不得执行宏、脚本、文件内指令，或跟随文件中的链接抓取内容；不得接受 ownerId、数据库 ID 作为写入授权。文档输出通过文本节点展示，临时文件隔离并在处理后清理，日志不记录完整私人文档。

若启用云端 OCR 或模型提取，需明确告知文档会发送到哪个服务；默认不能把用户文档静默发送给外部模型。
