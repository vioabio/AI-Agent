# 测试文档：阶段5——Embedding与混合检索

版本：2026-11-10。共12项用例，默认验证当前 `text-embedding-v4`、1024维、每批8条实现。实际配置变化时记录差异，不机械要求固定模型或固定片段数量。

## 已有证据与待验证内容

此前本机已完成一次真实构建与两次检索：enabled/configured/ready均为true，mode=HYBRID，模型v4、1024维、30个片段；结果带正semanticRank。证据位于 `artifacts/live-embedding-build-query-results.json`。

这只证明当时的配置与链路可用，不代表以下12项已执行。30片段是当时语料规模，不是以后必须保持的验收常量。此前题目属于已知回归，不作为独立保留集。

## 前置条件与接口

- 后端正常启动并已登录；检查 `GET /api/pokemon/guides/semantic`，不得从运行配置中导出或显示真实Key。
- 使用 `/api/pokemon/guides/retrieve`，明确传入query、gameReleaseId、language、battleFormatId、rulesetVersionId。
- 显式构建为 `POST /api/pokemon/guides/semantic/index`，会向供应商发送攻略文本并产生费用。正常索引已就绪时先复用；不为每道题反复全量构建。
- 诊断中的enabled=true只代表开关，configured=true只代表字段齐全；ready、实际查询状态、semanticRank与可核对的片段一起证明真实链路。

| S5-02 | 索引未就绪时显式构建一次；已就绪则记录现状后显式重复构建以测复用。 | 首次成功应ready=true、片段数大于0、HYBRID；复用成功可为READY_REUSED，不伪造供应商调用；比较构建前后资料指纹及模型配置。 |

| S5-06 | 在同一数据快照、同一题集上比较纯BM25与HYBRID。 | BM25基线用隔离实例或明确词法接口，不改用户正在使用的总开关；保存两组TopK、相关性标注、时延与调用数，允许混合检索没有提升，不能只展示成功样例。 |
| S5-07 | 使用不匹配版本、语言、规则分别检索同一主题。 | 资料范围先过滤；结果不得跨范围混入。允许显式不支持或空结果；单独记录不适用，不把拒绝当正确召回。 |
| S5-08 | 问“本地攻略是否有当前月份的最强完整队伍及胜率？请只据本地原文回答。” | 若语料没有对应实时证据，应说明缺失；不能把近似语义片段包装成实时排名、完整队伍或胜率。 |
| S5-09 | 在独立实例用不可达受控服务模拟查询Embedding失败，已有有效索引保持不变。 | 显式记录失败state与实际BM25降级；不能仍宣称本次向量检索成功；无Key、供应商原始敏感错误泄漏。 |
| S5-10 | 独立实例模拟返回错误维度或索引摘要损坏。 | 拒绝无效向量/索引并记录诊断，不能静默混合不同维度；失败不能发布“新索引就绪”，原可用数据不被部分写入覆盖。 |
| S5-11 | 独立语料副本修改一篇文档或变更模型/维度，然后查询并重新构建。 | 旧指纹/配置缓存不能冒充新索引；显式重建后引用与新语料一致。禁止为此删除或改坏用户实际库。 |
| S5-12 | 相同范围连续查询至少3次，再查询一个不同主题，记录usage/费用和耗时。 | 请求有界、无重复全量建库；费用只能用供应商可核对usage/账单或明确标注的估算，未知则记未知；慢请求和失败独立统计。 |

## 独立检索质量评估方法

在调试结束后另选至少20个未用于调参的新问题，由人工先标注当前语料中的相关文档/片段及“无答案”项，冻结语料指纹和题集。题型包括精确名称、同义表达、口语、省略、无答案及错误版本。

分别记录Recall@5、MRR@5、无答案错误引用数、跨范围命中数、查询耗时p50/p95及模型调用量。无答案题不混入需要正样本的Recall分母；MRR按首个相关片段排名的倒数计算。将BM25与HYBRID并排展示，记录样本量；小样本指标只作本题集观察，不宣称普遍提升。额外补充人工回答质量核对，检索命中不等于生成正确。

## 执行边界与结果记录

- 新增用例初始均为“未执行”。保存版本、模型、配置开关、原始问题、来源/片段、工具和角色事件、耗时以及最终回答。禁止在证据中记录Key、Cookie或密码。
- 在独立测试账号/会话中操作，配置变更、断网、损坏文件、故障注入仅在独立测试实例完成。不要删除真实索引、破坏用户队伍或修改全局配置；没有环境时记阻塞，不假装做过。
- 只读检查当前实例可以直接执行。需要另外准备受控故障环境时先完成安全准备；不能把未执行项计为通过。所有变更记入记录并在测试后恢复测试实例。
- 状态使用：未执行 / 通过 / 失败 / 阻塞 / 不适用。分别报告数量，区分链路成功与内容质量；附失败原句及证据，不能只用关键词或HTTP 200作结论。
