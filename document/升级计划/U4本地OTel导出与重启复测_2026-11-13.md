# U4 本地 OTel 导出与重启复测

## 实现范围

新增 `AgentTracingConfiguration`，将已有 Micrometer 领域 Observation 连接到真实 OpenTelemetry SDK，经 OTLP HTTP 发到本机收集端。依赖版本由项目 Spring Boot 3.5.16 BOM 管理，不照搬 Boot 4 配置。

- 默认关闭；仅 `local & !prod & !demo` 生效。
- 不注册全局 SDK，不自动采集全部 HTTP、Spring AI Prompt 或外部客户端请求。只导出 `agent.run.execute`、`agent.model.call`、`agent.model.stream` 三种已有领域观测。
- 独立配置下禁用 Boot 自动 tracing，避免重复埋点；若同时启用两种 tracing，启动时明确拒绝。
- Run ID 为高基数关联字段，不作为指标标签。Run 与模型异常先转换为通用错误类别，原始错误仍交给业务处理，不把供应商报文传给导出器。
- 采样率限制 0～1；Span 属性最多16项、值最多256字符、事件最多4项。
- 异步队列256条，单批64条，500ms批次间隔；HTTP连接及请求超时500ms，批次导出超时1秒。收集器异常不重试业务或模型调用，队列满时允许丢失观测。
- 本阶段只允许回环 OTLP HTTP `/v1/traces`，拒绝远程地址、URL凭据、查询参数及片段，不接受任意公网收集服务。

## 本机开启

1. 确认 Docker Desktop 引擎运行。执行：

   ```powershell
   docker compose -f ops/local/compose-tracing.yml up -d
   ```

   文件固定 Jaeger 2.23.0，仅向本机开放4318和16686。默认临时内存存储，容器销毁会丢失记录；不是生产部署。

2. IDEA 重新加载 Maven，然后在现有运行环境变量中追加：

   ```text
   VIO_TRACING_ENABLED=true
   VIO_TRACING_OTLP_ENDPOINT=http://127.0.0.1:4318/v1/traces
   VIO_TRACING_SAMPLE_RATE=1.0
   ```

   不需要新增模型 Key，也不需要开启 Boot 的 `management.tracing.enabled`。保持现有模型配置即可。

3. 重新构建并重启后端，进行一次普通模型问答。打开 `http://127.0.0.1:16686`，按服务 `vio-agent-local` 搜索 `agent.run.execute`，查看模型子节点；可用 `agent.run.id` 关联原来的 Run。

   项目已有8位业务 Trace ID 与 OTel 32位 Trace ID 是两套标识，本轮不宣称它们相等。Run ID 是当前关联点。队列等待、答案持久化、独立工具线程尚未纳入这棵完整链路。

4. 故障演练：停止本地收集端后再次问答，确认仍能回答。恢复容器后发起新请求，确认新 Trace 可见。

5. 回退：设 `VIO_TRACING_ENABLED=false`，重新启动后端。可单独执行：

   ```powershell
   docker compose -f ops/local/compose-tracing.yml down
   ```
