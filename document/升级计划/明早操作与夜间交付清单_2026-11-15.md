### 3. 准备真实精排配置

已有混合检索可继续使用。要验证精排收益，需要你选择并配置支持当前请求协议的 rerank 服务。

当前 HTTP 适配器使用 Jina-style 协议，请求包含 `model`、`query`、`documents`、`top_n`，响应通过 `results[].index` 和有限相关性分数映射回原片段。请核对供应商文档和对应模型权限。

在 IDEA 环境变量里填写以下项目。

```text
VIO_GUIDE_RERANK_ENDPOINT=<服务的完整精排接口URL>
VIO_GUIDE_RERANK_MODEL=<精排模型ID>
VIO_GUIDE_RERANK_API_KEY=<仅在本机填写>
VIO_GUIDE_RERANK_ENABLED=true
```

其余参数可先沿用项目默认值。

| 参数 | 默认值 |
| --- | --- |
| `VIO_GUIDE_RERANK_TIMEOUT_MS` | 3000 |
| `VIO_GUIDE_RERANK_CANDIDATE_K` | 12 |
| `VIO_GUIDE_RERANK_ANSWER_TOP_K` | 4 |
| `VIO_GUIDE_RERANK_MAX_INPUT_TOKENS` | 12000 |

重启后先检查 `upgradeFeatures.rerank`，再运行一条本地攻略问题，查看执行事件中的 `retrieval.finished` 与 `rerankObservation`。`RERANKED` 表示实际完成重排，`RRF_FALLBACK` 表示本次回退，应按错误类别检查接口、协议或超时。

随后由开发侧在同一构建、语料、题集和模型下采集关闭/开启两组，比较 Recall、MRR、引用、回答完整性、延迟和 usage。当前已验证受控精排服务的接线及异常回退，真实服务效果仍待配置后测量。

## 配置和数据位置

- 本机凭证保留在你的运行配置或环境变量中，继续使用被忽略的 `.run` 与本地配置文件。

- MCP 接入仍按现有开关和工具白名单配置。正常使用网页助手可先沿用当前 MCP 配置。
