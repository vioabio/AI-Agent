## 推进U5的内容

原本地验证客户端`LocalMcpClient`会永久保存所有已回复ID；持续使用时集合随总请求数增长。本轮仅修改本地验证客户端与测试探针，不改变MCP服务器的领域授权或可用工具。

新增`McpResponseWindow`：

- 客户端使用递增正整数ID，最多保存最近4,096个ID槽位，固定32KiB数值数组。
- 窗口内乱序回复可以完成对应请求；重复回复拒绝并关闭连接。
- 超出窗口的历史回复、未发送的ID、字符串/非安全整数ID拒绝并关闭连接。历史回复不再声称能够无限期精确去重。
- 客户端待处理请求上限128；超限不发送，安全整数耗尽时要求重建连接。
- 窗口只约束ID追踪数组，不代表客户端或服务端整个进程内存不增长。

测试探针复用相同窗口，增加`endurance`模式：真实Java SDK/治理网关/仓储/计算引擎与离线上游下，单连接完成5,000次顺序ping，五轮暂停stdout消费、工具发现和恢复读取，穿插错误版本拒绝，最后继续进行确定性伤害计算。

错误请求被拒绝后必须能正常处理后续请求，重复/非法协议帧和未清理请求均不能计为通过。记录客户端RSS与窗口大小，但不设脱离环境依据的RSS阈值，未采集服务端堆数据。

### Java SDK关闭告警的含义

官方Java SDK测试仍可能显示`Process terminated with code 1`，但不能直接解释为服务器自然退出失败。已查本机锁定的`mcp-0.10.0-sources.jar`内`StdioClientTransport.closeGracefully()`：该方法完成消息sink后等待100ms，直接调用`process.destroy()`并等待进程退出；非零退出码会记WARN。Windows下该调用可能终止进程，因此该SDK测试只证明调用兼容与客户端关闭操作完成，不证明服务端EOF后自然退出。

本轮没有隐藏WARN、修改第三方SDK或把其关闭结果当作服务端自然退出证据。EOF与持续连接后的自然退出由独立Node探针验证；持续连接报告在进程退出后才输出PASS，强制回收会失败。

后端业务Java未修改，本轮MCP定向测试不能冒充重跑全部1,738项。
