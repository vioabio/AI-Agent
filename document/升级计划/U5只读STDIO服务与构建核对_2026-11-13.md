# U5 只读 STDIO 服务与构建核对

## 已实现

新增独立入口 `com.vio.vioaiagent.mcp.PokemonMcpServerMain`，不启动Spring网页服务、不加载模型或用户账号体系，复用现有公共资料服务与治理网关。

| 工具 | 接入实现 |
| --- | --- |
| lookupPokemonReference | LocalPokeApiRepository / PokeApiClient |
| checkPokemonBuild | LocalBuildCheckService / LocalLearnsetReferences |
| calculateBattleDamage | VerifiedLocalDamageEngine / 固定calculate-v2.cjs |

MCP协议按当前SDK 0.10.0支持的`2024-11-05`版本验证。只开放三项工具，不发布私有队伍、保存、文件、终端或任意URL能力；这是本地公开资料进程，不伪装成网页登录用户或OIDC身份。

### 执行边界

- 服务端生成固定进程身份及每次调用的随机ID，固定trainer角色；客户端不能提交userId/runId/roles等授权字段。
- 参数先过U5目录预检，再进入原治理网关的完整Schema、策略和超时流程；没有另开不经网关的调用路径。
- 两个准入名额，治理工作线程2个、排队容量0；繁忙时返回`MCP_BUSY`。不扩大调用方权限，不接收Node或脚本路径。
- 单帧24KB、参数16KB、结果64KB，按UTF-8字节计数。超大帧关闭本地连接，结果过大返回错误，不截断为成功结果。
- stdout只承载JSON-RPC；关闭SDK原始报文日志，仅向stderr输出工具名与审计结果摘要，不输出参数、结果或凭据。审计不持久化，不是生产审计交付。
- 关闭时释放SDK服务、治理执行器和审批调度器；不因启动失败或EOF留下长期本地服务。

正常网页入口仍为VioAiAgentApplication。Maven已显式指定原Spring Boot主类，新增main不会改变网页JAR启动入口。

## 本机使用

不需要新增模型API Key。网页功能不要求启动这个独立MCP进程。

1. 在项目目录构建独立MCP：

   ```powershell
   .\ops\local\build-mcp.ps1
   # 依赖已缓存时也可使用：
   .\ops\local\build-mcp.ps1 -Offline
   ```

2. 脚本输出 `.local-data/mcp-client-config.json`。将其中`vio-pokemon`条目添加到支持该协议和STDIO传输的本地MCP客户端；配置包含Java路径、独立构建classpath与项目/公共缓存路径，不包含模型Key或账号密码。
3. 重新连接客户端，确认只发现上述三项工具。先查询`query="7"`、`dataReleaseId="pokeapi-reference-v1"`，再测试配置核对和伤害计算。
4. 若需要伤害计算，先准备项目现有Node引擎依赖：在`tools/pokemon-engine`执行`npm ci --ignore-scripts`。未缓存的图鉴资料仍需访问PokéAPI；参考缓存可以复用。
5. 关闭客户端连接或移除该条目即可停止使用。服务不占用公网端口，不与网页端口冲突。

构建目录为 `.local-data/mcp-server-build`，不会改写运行中的`target/classes`。脚本已处理Windows PowerShell把JDK stderr警告误当成终止异常的问题，最终按Maven退出码判断成功。
