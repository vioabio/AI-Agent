## U5：补齐真实HTTP与MCP对照

新增 `tools/campus/mcp-http-equivalence.mjs` 和 `mcp-local-client.mjs`。在随机隔离的本地账号中调用真实HTTP接口，同时启动客户端配置中的正式MCP Main，不使用测试替身或模型回答代替接口输出。

| 输入类别 | 项数 | 检查 |
| --- | --- | --- |
| 图鉴 | 3 | 编号、英文名、中文名均返回杰尼龟；种族值及版本校验 |
| 培养核对 | 2 | 缺失配置及部分配置保留缺项，不能自行补成已核验完整配置 |
| 计算 | 4 | 普通攻击、雨天下水枪、Harsh Sunshine下零伤害、双打冲浪 |
| 非法参数 | 4 | 错误资料版本、错误游戏版本、错误世代和未知天气，两入口都拒绝 |

对成功响应做完整领域JSON比较，包含来源、摘要、时间、默认条件与计算结果，不通过删除差异字段强行判一致。另检查已知种族值、INCOMPLETE、VERIFIED、正伤害/零伤害等条件，避免“两边同样错误”仅凭相等通过。

拒绝项必须是HTTP 400和MCP错误；401/403、404、500不能当作非法参数正确拒绝。环境不可用保留BLOCKED，缺题或注销不完整不能报告全通过。

脚本不创建队伍、不调用模型。账号凭据/Cookie只在进程内使用，退出时注销；本地账号注册记录可能保留，不声称删除账号。MCP的stderr只统计字节数，不保存原文。报告保存公开请求/响应、运行配置白名单、脚本与矩阵摘要和逐入口耗时，不作性能提升结论。

用法（后端运行中即可，无需重启）：

```powershell
# 换设备先生成本机STDIO配置；该命令不需要模型Key。
.\ops\local\build-mcp.ps1 -Offline
node tools/campus/mcp-http-equivalence.mjs http://127.0.0.1:8123/api artifacts/u5-http-mcp-新的目录
```

新目录必须位于artifacts且不存在，拒绝覆盖旧证据。仅允许回环HTTP `/api`；如需在公网部署验收，应另行设计凭据与测试账号管理。

## U5：第二客户端与短时背压

新增 `SdkMcpCompatibilityTest`，实际使用项目固定的官方Java SDK 0.10.0客户端启动STDIO子进程，完成初始化、发现、三个正常工具调用、错误版本拒绝和ping。此前独立Node客户端继续验证取消与断连。

SDK客户端的关闭实现会调用 `Process.destroy()`；Windows日志可能显示子进程退出码1。这是SDK主动终止的路径，不等于服务端业务异常，也不作为服务端正常EOF退出码0的证据。正常EOF、活动任务中断与进程自行退出由独立Node测试分别验证。尚未宣称所有SDK版本、桌面客户端或SDK取消行为兼容。

慢消费者用例暂停读取stdout两秒，发送80个较大的tools/list请求，恢复读取后检查响应完整、无重复，再验证ping可用。它是短时背压与恢复测试，没有测量长期RSS、GC或长期吞吐，不替代长时间压力验收。

## U6：已开始证据完整性开发

新增 `tools/campus/upgrade-review-verify.mjs`：

- 对照冻结数据集及dev题目，检查20题和各轮覆盖、原问题、重复ID和统计。
- 检查评审绑定的baseline摘要、Run、正文摘要与事件文件摘要。
- 从原事件重建answer.delta正文，防止替换正文后沿用旧评审。
- 校验5个不同的关键构建类及其实际/预期摘要，不接受重复一个类凑足数量。
- 检查采集终态与清理；文件读取限制在artifacts内，事件文件名不能越界。
- 只输出 `DEVELOPMENT_REVIEW_INTEGRITY_ONLY` 与 `releaseDecision=NOT_EVALUATED`，不自动裁决事实正确性，不把AI复核写成人工审核，不把dev题当作独立封存验收。

```powershell
node tools/campus/upgrade-review-verify.mjs artifacts/已有dev记录目录 artifacts/新的证据校验报告.json
```

校验器不调用模型，也不改写旧回答或评审。摘要校验用于发现证据不一致，不是数字签名或防恶意伪造系统。
