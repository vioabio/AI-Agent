# U3 长历史裁剪诊断与 U6 重复采集校验

## 本轮进度

修复专用角色收到裁剪后的历史却仍报告 `CONTEXT_READY` 的问题，补齐长历史开发场景的采集与证据校验。两次独立会话各连续 15 轮，AI 辅助逐轮核对正文、来源和实际工具事件，共 30 轮通过。

后端整体执行 1,793 项测试，0 失败、0 错误、3 跳过。Java 定向测试 34 项通过。实际服务的 34 个组件摘要与整体测试产物一致。

## 问题及实现

`ConversationHistory` 先按窗口与 token 预算选取历史，`TaskContextAssembler` 随后装配专用角色请求。原实现仅检查装配阶段是否再次裁剪，漏掉了上游已经省略的回合。

`SpecialistAgentCoordinator` 现在从程序记录的历史来源摘要读取省略轮数。启用上下文装配时，上游或装配阶段发生裁剪均发出 `CONTEXT_HISTORY_TRIMMED`，同时提供下列受控字段。

| 字段 | 含义 |
| --- | --- |
| `sourceOmittedTurns` | 持久化历史窗口已省略的轮数 |
| `assemblyOmittedTurns` | 请求装配时进一步省略的轮数 |
| `selectedHistoryTurns` | 本次装配保留的完整历史轮数 |
| `estimatedTokens` | 装配器估算的输入 token 数 |

模型请求同时收到程序生成的历史省略提示，缺失条件需要继续核对。已解析的馆主目标仍走结构化对话状态与专用工具。模型只接收受限历史、当前问题和本次工具证据。

新增测试分别覆盖上游裁剪、二次裁剪及完整路由历史中私有旧文本未进入模型请求。共享运行组件清单升级到 `u6-runtime-components-v7`，共 34 个组件，包含协调器。公开配置指纹新增 `historyTurns` 和 `safetyPercent`，用于识别历史预算配置差异。

## 长历史场景

新增 `tools/campus/upgrade-long-history.mjs`，保存单个 15 轮开发场景。使用独立的 `LONG_HISTORY_DEVELOPMENT` 类型和题目摘要，既有冻结题集继续保持原版本。

| 回合 | 输入与检查 |
| --- | --- |
| 1 | 按参考等级列出八位馆主，说明可自由挑战 |
| 2 | 承接表格第 4 位海岱，核对初战队伍 |
| 3～10 | 八轮属性插话，交替检查 1 倍、4 倍、免疫 0 倍和 4 倍 |
| 11 | 追问“这个馆主”的太晶成员，核对好胜毛蟹 Lv.30、太晶水 |
| 12 | 通用组队角色问题，核对原创攻略引用及检索工具范围 |
| 13 | 明确切换奇树，核对四名初战成员 |
| 14 | 追问太晶成员，核对梦妖魔 Lv.24、太晶电 |
| 15 | 再次切换通用组队，核对攻略与裁剪记录 |

两次采集均使用新的隔离账号与会话，开启 Skills、上下文装配和领域追踪。服务监听 `18124`，使用独立构建和数据库，检索模式固定 BM25。测试结束后已核对进程身份并关闭本轮隔离后端。

第 12 轮保留 8 轮、上游省略 3 轮，第 15 轮保留 8 轮、上游省略 6 轮。两次记录均有真实 `CONTEXT_HISTORY_TRIMMED`，通用组队仅调用 `searchPokemonGuides`。第一次第 12 轮有 3 次检索，其他三处各 2 次，仍存在减少重复检索的优化空间。

## 采集与校验工具

`upgrade-collect.mjs` 增加 `long-history` 模式，复用隔离账号、事件采集、运行前后组件核对和清理逻辑。账号与 CSRF 处理提取至 `local-evaluation-session.mjs`，凭证仅保存在进程内。

```powershell
node tools/campus/upgrade-collect.mjs artifacts/新的长历史采集目录 http://127.0.0.1:18124/api 1 U3-LONG-HISTORY long-history
node tools/campus/upgrade-long-history-verify.mjs artifacts/新的长历史采集目录 artifacts/新的长历史证据报告.json
node tools/campus/upgrade-trace-link.mjs artifacts/新的长历史采集目录/baseline.json artifacts/新的长历史链路报告.json
```

执行前需使用 `ops/local/start-ablation-backend.ps1` 启动已验证产物的隔离服务，传入 `-Skills -ContextAssembly`。采集目录必须使用新目录，报告输出位于 `artifacts` 下。复测时重新创建账号与会话，保留每次首答和原始事件。

新增校验器检查题集身份、15 轮完整性、运行前后构建与配置、事件归属/顺序/摘要、正文拼接与唯一完成终态，以及第 12、15 轮的历史轮数、usage 和攻略工具范围。正文语义仍由单独的内容复核记录给出结论。校验器保持 `qualityReview=REQUIRED` 和 `releaseDecision=NOT_EVALUATED`。
