# U2进度与奖励前提核对及U6多轮验收

## 本轮补齐

培养路线此前只说明进度、重赛与资源尚未核验。本轮增加明确声明字段及确定性规则核对，复用既有`GymResourcePolicy`的8位馆主首胜学习器奖励规则，不新增未经核对的获取地点或配方。

核对区分：

- 条件缺失：只有8枚徽章，不推断已通关或接到视察任务。
- 前提不满足：明确主线未通关、未接任务或不足8枚徽章时，不将重赛目标当作可立即挑战。
- 声明齐备：8枚徽章、主线通关、视察任务均明确时，只说明按声明门槛齐备，不认定实际游戏已解锁。
- 声明矛盾：击败馆主数超过徽章数、通关却不足8徽章、主线未通关却有视察任务、视察任务却不足8徽章、明确未击败任何馆主却有徽章、进度文字与徽章字段不同，暂停该核对结论。
- 获取路线：区分已声明持有、已声明击败对应馆主、未确认该首胜前提，以及固定规则未收录的资源。

这不是游戏存档或背包接口，不会确认实际领取、剩余数量、重复领取、学习器制作解锁或成员可学习性。

## 新增可选字段

原游戏、目标、进度、练级、资源五类条件不变，新增字段不是所有请求都必须填写：

| 字段 | 允许的明确表达 |
| --- | --- |
| 徽章 | 0–8的整数，可带“枚” |
| 已击败馆主 | 中文名称或既有馆主ID，逗号/顿号分隔，最多8项，不重复；“无”表示明确空列表 |
| 主线通关 | 是/否 |
| 视察任务 | 是/否 |
| 所需学习器 | TM三位编号，逗号/顿号分隔，最多8项，不重复；“无”为空列表 |
| 已有学习器 | 同上；这里只记录用户声明，不记录或验证数量 |

既有`进度：8枚徽章`这种完整且明确的表达可提供徽章数；任意剧情描述不做猜测。两字段同时出现时检查一致性。击败馆主列表允许只列已确认的部分记录，不能用8枚徽章补造8个人名。

未知/待定等值沿用原规则清除；同字段不同声明须明确更新，Assistant、System和资料引用不作为用户进度来源。当前仍不是任意自然语言进度抽取器。

## 示例

将1替换成自己的真实队伍编号：

```text
请为我的队伍ID 1制定培养计划，不保存；目标：阿枫重赛；徽章：8；已击败馆主：阿枫,寇沙；主线通关：否；视察任务：否；所需学习器：tm048,tm007；已有学习器：tm007
```

预期：重赛声明前提未满足；未确认击败奇树，不能据此认定TM048首胜奖励前提符合；TM007仅为声明已有，数量、编号、成员可学性未核验。

后续更新：

```text
请为这个队伍制定培养计划；主线通关改为：是；视察任务改为：是；已击败馆主改为：阿枫,寇沙,奇树
```

预期：按声明重赛门槛齐备，实际进度仍未核验；TM048对应首胜奖励的声明前提符合，不等于已领取、可再次领取或能制作。未知编号只保留未知获取途径，不断言该编号存在或不存在。

已有学习器声明**不直接扣减条件式制作预算**：尚未说明数量、是否消耗、对应招式是否已学会及是否实际需要制作。目标馆主覆盖仍是只读理论评估，声明不改写保存配置或成为NPC数值。
