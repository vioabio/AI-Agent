## Worker 追踪范围

`PokemonAgentRunService` 在 Worker 执行入口创建 `agent.run.execute`，作用域持续到本次执行清理完成。默认执行器在同一 Run 作用域中复用该根节点。

根节点记录以下受限字段。

- `agent.run.id` 关联实际 Run。
- `agent.run.dispatch_wait_ms` 使用任务登记到 Worker 入场的单调时钟间隔。
- `agent.run.status` 使用固定状态集合记录本次执行结束时的状态。

取消记录为 `CANCELLED`。失败与超时记录固定错误标识。观测错误信息采用程序定义的类型，业务异常中的原始输入不进入追踪错误消息。

## 执行租约检查阶段

新增 `agent.run.authorize`，包含 Worker 获取执行租约和检查已捕获身份策略是否过期的过程。

HTTP 登录鉴权、Run 创建时的准入和授权快照生成位于此阶段之前，后续仍需补齐这些边界的关联。

## 答案提交阶段

新增 `agent.run.commit`，包括以下既有操作。

1. 保存提交检查点，并检查取消、超时和审批状态。
2. 生成答案血缘、保存不可变步骤输出。
3. 核对步骤输出与答案投影的一致性。
4. 在原有提交边界内保存投影、聊天记录、完成事件和 Run 状态。

提交实现提取为 `commitAnswer`，追踪包装在原业务操作之外。事务内执行的内容及租约隔离继续由原有方法负责。

提交失败时，阶段记录 `RUN_COMMIT_FAILED`，Run 记录失败状态。新增回归断言生成操作只执行一次、投影只尝试保存一次。

## 观测可靠性验证

新增服务级回归覆盖以下情况。

- 正常入口只有一个 Run 根节点，租约和提交阶段均关联该根节点。
- 投影保存失败时错误信息脱敏，生成操作没有重放。
- 取消后结束 Worker 作用域，保留取消状态。
- 观测处理器启动失败时，业务仍可完成且只执行一次。
- Worker 排队后记录实际等待时间，后续任务正确绑定自己的 Run。

OTel 桥接测试同时检查导出的父子关系、结束状态、等待时间和作用域清理。
