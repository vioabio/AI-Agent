# U6采集完成状态与单开关耗时对照

## 采集完成状态修复

`upgrade-collect.mjs`原先在初始化失败、部分用例失败和清理失败时仍可能以成功退出。现保存明确的collection状态，并设置对应退出码。

| 退出码 | 采集状态 |
| --- | --- |
| 0 | 所选用例全部完成，回答非空，运行配置与组件在前后核对中稳定，清理成功，等待内容评审 |
| 1 | 用例不完整、回答失败、配置或组件发生变化、清理失败 |
| 2 | 初始化失败，记录SETUP_BLOCKED及固定错误类别 |

采集开始前记录当前运行诊断中的28个组件摘要，结束后再次核对。组件清单来自共享manifest，缺少摘要时在创建问答Run前结束。报告只提取允许的摘要和公开配置字段。

## 单开关耗时对照

新增`upgrade-switch-compare.mjs`，接受两份完整采集文件与一个开关名称。支持skills、contextAssembly、domainTracing、answerBlocks和rerank。

比较前检查以下条件。

- 两侧所选用例、原问题及各轮覆盖相同，Run ID独立。
- 提交、源码差异摘要、数据集、语料及运行组件摘要相同。
- 每侧采集前后的公开配置和组件稳定，清理成功。
- 只有所指定的公开开关发生变化，模型、其他开关与预算保持一致。
- TTFT与总耗时有限、非负，TTFT不大于总耗时。

输出逐轮两侧耗时与差值，并给出各组中位数和P95。TTFT来自采集器轮询首次读到answer.delta的时间，包含轮询误差。报告标记qualityReview为REQUIRED，releaseDecision为NOT_EVALUATED。样本数和来源摘要随报告保留，内容评审继续使用原流程。

## 执行步骤

1. 完成代码修改后重建并启动后端，通过运行构建核对。
2. 将准备比较的开关关闭，保持相同代码和其他配置，采集第一组开发题。

```powershell
node tools/campus/upgrade-collect.mjs artifacts/skills-off http://127.0.0.1:8123/api 20
```

3. 停止后端，仅将`VIO_AGENT_SKILLS_ENABLED`改为true，再使用同一构建启动，采集第二组。

```powershell
node tools/campus/upgrade-collect.mjs artifacts/skills-on http://127.0.0.1:8123/api 20
```

4. 生成配对耗时报告。

```powershell
node tools/campus/upgrade-switch-compare.mjs artifacts/skills-off/baseline.json artifacts/skills-on/baseline.json skills artifacts/skills-timing.json
```

5. 复核原回答、事件及工具证据。追踪对照时还可运行`upgrade-trace-link.mjs`关联Trace。

使用既有三个预览开关时，单项对照仍需在两侧明确设置相同的其他开关。采集前先通过`/chat/runtime`确认实际公开配置。
