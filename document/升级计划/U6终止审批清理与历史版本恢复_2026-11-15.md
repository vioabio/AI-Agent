# U6 终止审批清理与历史版本恢复

本轮承接精排回退与浏览器组合验证，推进取消、超时、断连及刷新恢复的组合检查。真实精排的endpoint、model、API Key仍待本机配置。

## 已修复的问题

### 终态保留旧审批

前端事件归约器原先在取消、超时、失败及完成时保留`approval`对象，页面可能继续展示旧预览和确认按钮。新增回归用例先复现此问题，再补齐以下处理。

- 终态事件、终态快照恢复及不可恢复的传输失败清理审批对象。
- 历史事件和已有回答继续保留，重复回放与终态后的事件不能重新打开审批。
- `RunTimeline`仅在等待审批时展示操作区。
- 两个聊天入口复用`canSubmitRunApproval`，核对当前等待状态、审批ID及提交中状态。

### 刷新后资料版本变化

连续测试复现了刷新后从`pokeapi-reference-v1`回到默认资料版本，导致下一轮`readCurrentTeam`读取失败。历史记录显示，第一轮与刷新后第二轮的用户消息元数据分别携带了不同的资料版本。

新增`conversationContextFromHistory`，从最近一条用户消息的结构化元数据恢复游戏、语言、规则、资料版本与赛制。它忽略消息正文、助手元数据及非白名单字段，并兼容`battleFormatId`。明确的URL选择优先于恢复值，旧记录缺少元数据时继续使用已有默认流程。

### 等待审批期间收不到超时

实际服务器已产生`run.timed_out`，页面仍保持等待审批并禁用输入。原因是`useRunStream`收到`approval.required`后主动中止消费，只有用户审批或手动重连才继续读取。

等待审批时改为每2秒进行一次可中止的事件补读。网络异常继续使用原有的有限重连与退避。工具回执、来源和用量事件保持等待状态，审批解决事件与Run终态负责结束等待。页面卸载、账号切换和主动重连会中止旧控制器。

## 组合验证范围

两组保持相同的后端构建、资料缓存与Embedding向量。开启组同时启用Skills、上下文装配、回答卡片及领域追踪，关闭组同时关闭这四项。

| 场景 | 核对内容 |
| --- | --- |
| 待审批时停止 | 使用页面停止按钮，取消后移除审批，迟到确认返回409，队伍保持原值 |
| 待审批时超时 | 真实创建请求设置10秒期限，页面短暂离线后恢复，自动显示超时，过期确认返回410 |
| 刷新后继续操作 | 相同会话的下一轮仍使用原资料版本，刷新后没有旧审批按钮 |
| 正常审批回归 | 拒绝保持51级，确认只改为52级，回读与回执一致，再恢复测试基线 |
| 卡片回归 | 图鉴、伤害、参考队伍及未知名称四场景检查桌面与430px页面 |
| 运行中停止 | 断连、取消、恢复、重复取消及游标补读，队伍保持原值 |

等待超时的测试通过Playwright调整浏览器发出的创建请求期限，所有API响应均来自实际Spring服务。取消后的预览处于CANCELLED，超时后的预览处于EXPIRED，对应Run终态分别为CANCELLED和TIMED_OUT。

本轮运行中取消的实际采集位置记录在报告的`partialAnswerObserved`中。部分正文后的取消组合继续单独验证。

新增独立证据校验检查审批身份、唯一终态、终态后的附加事件、重复回放、迟到卡片、队伍回读、刷新状态及配置漂移。文件读取允许规范的`timed_out`名称，并拒绝目录穿越。

## 调试记录

首次浏览器检查保留了版本漂移和等待超时不收敛的失败报告。修复后选择新目录复测。

测试器初版对过期预览也要求409，实际接口依照有效期返回410。已按现有接口语义修正断言，并分别检查取消与过期状态。

测试器初版漏掉个人8123端口检查，一次测试注册请求返回403，未取得注册成功回执。端口检查已移至目录创建和所有网络请求之前，新增回归验证个人端口、远程目标、错误模式及越界目录均被拒绝。该失败报告保留在`artifacts/u6-termination-guard-first-20261115`。
