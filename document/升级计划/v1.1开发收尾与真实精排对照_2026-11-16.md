## 真实对照方法

- 使用已冻结的`stage5-retrieval-dev.json`，8道题，6道正例和2道负例。标签来自项目已有的来源关联开发种子。
- 同一构建和同一份14文档、30片段语料，比较BM25、HYBRID和HYBRID_RERANK。
- 各模式执行3轮，轮次交替改变模式执行顺序。每批72次检索，完成两批，共144次。
- 候选上限12，评估前5个片段，语义阈值0.55。该实验采用统一的评估TopK=5，日常配置模板的answerTopK默认值为4。
- 混合检索与精排组逐题逐轮核对完整候选ID及顺序，候选池一致；规范来源文本和摘要通过验证。
- 使用text-embedding-v4及本机已配置的Jina精排服务。记录模型名、构建摘要和降级状态，凭证只从本机环境或忽略的运行配置读取。
- 36次实际精排均为RERANKED，12次空候选为EMPTY，回退0次。

## 结果

两批的质量指标一致。

| 模式 | 文档Recall@5 | MRR@5 | 负例空结果正确率 |

| HYBRID | 0.8333 | 0.7500 | 1.0000 |
| HYBRID_RERANK | 0.8333 | 0.7500 | 1.0000 |

| 模式 | 首批P50 / P95，ms | 命令验证批P50 / P95，ms |
| --- | --- | --- |
| BM25 | 10.89 / 15.51 | 12.79 / 35.26 |
| HYBRID | 852.65 / 2061.47 | 794.95 / 1280.85 |
| HYBRID_RERANK | 1303.14 / 1756.57 | 1204.62 / 2207.71 |

混合检索的MRR高于BM25，精排与混合检索持平。项目继续采用精排默认关闭、按需配置启用的策略。本机两批精排组的P95差值方向相反，说明这组共享本机、少量开发题的采样存在波动。延迟分布作为运行参考记录，后续服务SLA需按目标部署环境测量。

S5-Q05在三种模式下均缺少其旧标签`damage-assumptions-v1`。现行GuideRevisionPolicy仅在明确指定calculateBattleDamage时发布这份旧修订，本题的通用胜负问题受到适用范围过滤。保留这一失分，后续扩展语料或标签时另建版本。

本轮对照评估检索排序与来源，生成式回答质量继续参考独立题首答、同题回归和人工审核记录。8道开发题的相关性标签和三轮重复采样只支持本节所列范围内的结论。

## 性能与使用量口径

| 指标 | 口径 |
| --- | --- |
| 检索耗时 | 调用实际retrieve前后使用单调时钟；包含Embedding/精排网络等待，来源定位验证在计时后执行 |
| P50/P95 | 各模式24个观测值排序后采用nearest-rank分位数；两批单列 |
| TTFT | 问答采集器从发起Run前计时，到首个非空answer.delta；沿用已有采集定义 |
| 总问答耗时 | 从发起Run前到终态事件边界满足，包含客户端补读等待；与单纯模型耗时分别记录 |
| 模型调用 | 本检索实验chatModelCallCount=0，Embedding与精排属于外部模型服务调用 |
| usage/费用 | 供应商计费usage和金额保留null；精排输入预算代理Token与供应商账单分别记录 |

本机功能验收依据沿用版本与权限边界、来源核对、参数预算、超时控制和已知回归。当前采样用于基线与开关选择；生产延迟承诺需独占资源及代表性负载验证。
