# U4真实Jaeger接收查询与流式验收

## 本轮进展

通过本机已有的`docker desktop start --detach --timeout 45`启动Docker引擎，再运行仓库已有的Jaeger 2.23.0本地Compose配置。容器的OTLP端口4318和查询端口16686绑定127.0.0.1。

新增显式启用的`JaegerCollectorTest`，向真实Jaeger容器导出项目OTel Span，再经查询API读取并逐项核对。测试使用固定业务返回值。

首次查询使用旧版`/api/traces`返回404。实际容器提供`/api/v3/traces`和`/api/v3/services`，查询需要明确起止时间，返回OTLP的resourceSpans。测试已适配固定镜像的接口，按唯一Run标识找到根Span并筛选同一traceId。

## 验证内容

- 同步链路包含Run、工具调度、worker回调、嵌套模型调用4个Span，父子Span ID与Trace ID一致。
- dispatch中的四项阶段耗时与同一次`ToolAttemptTiming`冻结快照一致。
- 异常链路保留`MODEL_CALL_FAILED`及`RUN_EXECUTION_FAILED`，供应商异常正文未出现在查询结果中。
- 跨线程流式订阅取首段后取消，检查源调用一次、模型Span停止一次、父关联和CANCEL状态，以及正文脱敏。
- Chrome浏览器实际打开Trace页面，检查4个操作名称可见、页面无异常，并保存截图。

## 复现

先运行本地容器。

```powershell
docker desktop start --detach --timeout 45
docker compose -f ops/local/compose-tracing.yml up -d
```

设置可用的JAVA_HOME，然后运行显式集成测试。

```powershell
.\mvnw.cmd -o -B -ntp '-Dvio.build.directory=artifacts/u4-jaeger-check' '-Dvio.jaeger.integration=true' '-Dtest=JaegerCollectorTest,AgentToolDispatchObservationTest,AgentTracingConfigurationTest,AgentModelObservationTest' test
```

真实Trace JSON保存在`artifacts/u4-jaeger-collector/run-jaeger-*.json`。对包含4个Span的成功Trace执行浏览器检查。

```powershell
node tools/campus/jaeger-browser-check.mjs artifacts/u4-jaeger-collector/对应成功Trace.json artifacts/u4-jaeger-collector/browser
```

Windows浏览器检查使用本机Chrome。首次使用Playwright默认浏览器路径时缺少下载的headless shell，随后沿用项目既有Chrome选择完成验证。

## 证据与剩余项

适配v3后的首轮Java13项通过，日志`artifacts/u4-jaeger-real-v3-20261114.log`。最终加入流式取消后的Java **20项通过，0失败、0错误、0跳过，BUILD SUCCESS**，日志`artifacts/u4-jaeger-final-20261114.log`。其中3项访问真实Jaeger，其余覆盖观测与导出容错。

浏览器检查通过，报告位于`artifacts/u4-jaeger-collector/browser/browser-result.json`，截图同目录`trace-browser.png`。冻结40题开发集摘要校验通过。

本轮启动的Docker Desktop和本地Jaeger仍在运行，可在`http://127.0.0.1:16686`查看记录。Jaeger使用内存存储，重建容器后需重新产生Trace。停止本次Jaeger可运行以下命令。

```powershell
docker compose -f ops/local/compose-tracing.yml stop
```

测试通过系统属性显式启用，默认测试流程会跳过这组依赖本地容器的检查。真实DeepSeek调用、完整Run排队/授权/提交链路和追踪开销对照仍需继续验收。个人后端构建保持运行中状态，本轮编译输出位于隔离目录。后续Git提交仍按用户指令执行。
