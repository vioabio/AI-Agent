# U4评测Run与Trace关联

## 本轮实现

新增`tools/campus/upgrade-trace-link.mjs`，读取既有`upgrade-baseline-v1`采集文件，将每题每轮的Run ID关联到本地Jaeger Trace。输出包含caseId、轮次、runId、traceId、查询链接及允许的领域Span名称、父ID和错误标记。

调用本地Jaeger v3查询最近60分钟的vio-agent-local服务记录，复用同一个查询快照完成本次关联。报告绑定原采集文件SHA-256，并写入新的制品文件。输入采集与输出报告保存在artifacts目录。

## 判定

| 状态 | 含义 |
| --- | --- |
| LINKED | 找到唯一Run根Span，返回的同Trace父链可回溯至该根 |
| NOT_FOUND | 本次查询快照没有对应Run根Span |
| AMBIGUOUS_RUN_ROOT | 同一Run出现多个根Span，需检查重复执行或数据 |
| INCOMPLETE_TRACE | 返回子Span缺少到根的父链 |
| INVALID_TRACE | Span ID、Trace ID、重复ID或循环存在异常 |
| QUERY_UNAVAILABLE | 查询失败或响应无法解析 |

LINKED覆盖本次返回的领域Span，查询窗口、采样和存储保留期限均影响可查范围。缺少记录会明确标记，质量和发布结论继续由原评审流程处理。脚本退出码0表示所有记录均已关联，存在缺失或错误时退出1。

## 修复实际收集器复测问题

本轮重新执行真实Jaeger测试，3项中1项首次失败。v3接口在当前窗口暂时无记录时返回HTTP404及`No traces found`，已有测试将其直接视为错误。现仅对该明确响应在原15秒时限内继续等待，其他HTTP错误继续失败。关联脚本将该响应解析为空查询结果。

原失败记录为`artifacts/u4-trace-link-collector-20261114.log`。修复后记录为`artifacts/u4-trace-link-collector-fixed-20261114.log`。

## 使用

先确保本地Jaeger已启动，并在采集真实应用回答时开启领域追踪。采集结束后尽快运行关联。

```powershell
node tools/campus/upgrade-trace-link.mjs artifacts/你的采集目录/baseline.json artifacts/新的Trace关联报告.json
```

缺失Trace时，核对运行构建、domainTracing开关、采样率、Run时间与Jaeger内存存储状态，再决定重新采集的范围。旧记录继续保留原始结果。
