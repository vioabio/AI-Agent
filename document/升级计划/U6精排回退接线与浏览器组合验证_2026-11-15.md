# U6 精排回退接线与浏览器组合验证

本文记录2026-11-15的后续开发。前一轮已修复的12个封存集失败题保留开发回归记录，原首次评分仍为8通过、12失败、0阻塞。本轮继续处理精排启用接线、浏览器组合与回答证据边界。

## 本轮修改

### 精排启用与隔离重启

`ops/local/start-ablation-backend.ps1`增加`-Rerank`，从当前进程或IDEA本机运行配置读取精排参数。超时未配置时默认3000ms，启用但缺少必需参数时明确报错。环境变量在启动后恢复，进程记录仅保留开关与实例身份。

`ops/local/restart-ablation-backend.ps1`保留精排开关及受控测试模式。重启前核对PID、启动时间、Java命令行、隔离构建和数据目录。新增`-RerankFixture`用于本机合成HTTP服务，需要同时提供`-Rerank`。

运行构建清单升级至v19、66个组件，新增精排HTTP适配器、响应体限制及排序管线的摘要核对。

构建核验测试原本将24次子进程检查放在同一个30秒期限内，整体测试并发时出现一次超时。现按组件拆成独立用例，每项保留自己的期限与失败名称，便于定位缺失组件。较早的超时日志保留。

### 浏览器组合证据

扩展三个真实浏览器脚本，采集相同构建下四项功能组合开启、关闭的两组结果。四个开关分别是Skills、上下文装配、回答卡片、领域追踪。Embedding在两组保持开启并复用已校验的v4向量缓存，精排在浏览器组保持关闭。

| 场景 | 每组检查 |
| --- | --- |
| 图鉴 | 胖丁属性和种族值、来源、右侧图鉴联动 |
| 伤害 | 杰尼龟撞击杰尼龟、输入假设、结果与计算证据一致 |
| 队伍 | 两位参考成员、基础属性关系、保存状态 |
| 未知名称 | 无图鉴卡片，缺少事实时保留资料缺口 |
| 拒绝与确认 | 预览不写入，拒绝保持原值，确认只将等级51改为52 |
| 旧预览冲突 | 先应用52级，再提交基于51级生成的53级预览，返回冲突并保留52级 |
| 账号切换 | 清除前账号页面内容，重新建立会话，仅显示当前账号队伍 |

四个卡片场景均检查1440px桌面与430px窄屏，审批分别覆盖窄屏拒绝与桌面确认。新增离线证据校验器核对20个独立Run、事件摘要、终态、审批身份、队伍回读、语料、公开配置以及前后端构建摘要。事件终态后的附加事件、跨Run或重复事件、错误队伍状态、开关外配置漂移均会阻止通过。

### 已核验事实请求的缺口提示

首次浏览器内容复核发现，未知名称请求未发生工具调用时，模型声称已经查询且没有匹配结果。扩展现有基础事实路径，覆盖“查询/读取属性和种族值，仅列已核验事实”等有明确边界的表达。

没有已验证图鉴时返回资料尚未取得的提示。工具明确返回未找到时保留资料源范围，超时或其他失败保留读取失败状态。混合培养、计算请求仍由对应证据路径处理。单元测试覆盖无工具结果、流式正文一致、明确未找到、超时与混合请求，浏览器脚本补充相应正文断言。

## 受控精排测试

本机服务接收Jina式请求，使用`model/query/documents/top_n`，返回`results/index/relevance_score`。服务只记录查询及候选文本的摘要。READY模式为后面的候选赋更高分，用于观察顺序变化。

| 模式 | 预期行为 |
| --- | --- |
| READY | 成功排序并选取高分候选 |
| FAIL | HTTP 503后回退 |
| DUPLICATE | 重复候选索引后回退 |
| MISSING | 缺少候选分数后回退 |
| OUT_OF_RANGE | 越界索引后回退 |
| MALFORMED | 无效JSON后回退 |
| TIMEOUT | 超过500ms测试超时后回退 |
| OVERSIZED | 超限响应体后回退 |
| REDIRECT | 302后回退，重定向目标收到0次请求 |
| READY | 故障后恢复排序 |

每轮通过真实Spring Run入口采集事件，对照实际候选原文摘要与排序观察记录，检查每轮单次HTTP调用、来源绑定和回退候选选择。空检索结果跳过精排服务。隔离服务重启后再次执行相同矩阵。

测试范围为合成HTTP传输、排序接线及异常回退。真实provider相关性、usage和回答质量收益继续等待配置后测量。

## 真实服务启用步骤

在本机IDEA环境变量中配置以下项目，Key仅保存在本机。

```dotenv
VIO_GUIDE_RERANK_ENABLED=true
VIO_GUIDE_RERANK_ENDPOINT=<兼容Jina协议的精排URL>
VIO_GUIDE_RERANK_MODEL=<精排模型ID>
VIO_GUIDE_RERANK_API_KEY=<本机精排Key>
VIO_GUIDE_RERANK_TIMEOUT_MS=3000
```

当前运行配置缺少endpoint、model、API Key。Embedding配置已有独立用途，精排服务还需提供兼容的排序接口。

1. 选择兼容当前请求与响应协议的服务，核对候选文本批量及响应限制。
2. 在IDEA中配置参数，重新构建并启动后端。
3. 读取诊断接口确认`upgradeFeatures.rerank=true`，再发起实际攻略查询，检查本次`retrieval.finished`中的`rerankObservation`。
4. 固定构建、语料、输入和Embedding配置，仅切换精排开关，保存首答、候选、选中来源、耗时及用量。
5. 对照相关性、来源覆盖与正文事实，再评审是否继续启用。

隔离测试可使用以下入口。端口需要为空，目录必须选择新的`artifacts`子目录。

```powershell
.\ops\local\start-ablation-backend.ps1 `
  -BuildDirectory artifacts/<已构建目录> `
  -OutputDirectory artifacts/<新实例目录> `
  -Port 18126 -Rerank
```

受控场景先执行`node tools/campus/stage6-rerank-fixture.mjs`，再为上方启动命令加上`-RerankFixture`。确认进程元数据为READY后执行`upgrade-stage6-rerank-controlled.mjs`。原始报告目录保留首次失败，复测选择新的目录。
