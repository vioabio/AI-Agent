# U2 真实模型卡片验收与伤害路由、来源修复

## 本轮实现

将 U2 从固定模型浏览器测试推进到已配置 DeepSeek 的隔离网页服务验证。实际执行中修复计算意图、参数结构、来源兼容与纯资料范围等问题，新增可复用的浏览器验收脚本。

## 计算请求未进入计算角色

原始问题为“按默认50级、Hardy、0 EV和31 IV，计算杰尼龟用撞击攻击杰尼龟，无道具、无天气及场地。”

专用角色选择只检查“伤害”“damage”“几击”等词，未识别这里的“计算……用……攻击……”，因而分给资料角色。该角色工具集合不含伤害计算，回答只展示了资料片段。

`SpecialistAgentCoordinator` 增加有限的招式攻击计算句式识别，进入 `DAMAGE_CALCULATION`，仍复用实际计算工具与证据核验。显式的“不要计算”“无需再计算”等表达会从新增句式识别中排除。种族值加总、能力值条件与攻击动画介绍继续走资料角色。

新增回归覆盖 Skills 开关两种状态，直接检查角色与可用工具集合。真实计算得到 13～16 HP、防御方最大 HP 119、约 10.92%～13.45%，正文保留实际等级、性格、EV/IV、特性与场地假设。

## 标准名称链接导致来源记录丢失

原计算卡片的来源校验只接受 `https://pokeapi.co/api/v2/pokemon/7/` 这类编号路径。实际资料也会通过 `https://pokeapi.co/api/v2/pokemon/squirtle/` 读取，计算数值核验虽通过，来源字段却被处理为空。

`EvidenceAnswerBlock.Source` 与前端 `parseDamageEvidence` 同步支持固定 HTTPS 主机及 Pokémon 资源下的编号、标准小写名称与连字符形态路径，URL 总长度限制为 128。来源原始 URL 与摘要一起保留。

回归覆盖 `squirtle`、`mr-mime`、`vulpix-alola`、`porygon2` 与数字形态编号，同时拒绝跨目录、编码路径、额外路径、参数、凭据及超长链接。来源仍由实际工具结果提供，继续核对请求、结果投影和目标卡片摘要绑定。

运行构建清单升级到 `u6-runtime-components-v8`，共 43 个组件。新增四种卡片、伤害输入 DTO 和 Schema、参考队伍证据策略及嵌套来源类的构建核对。运行诊断补齐嵌套类资源读取，避免主类匹配时漏掉来源校验器变动。

## 无道具别名与纯资料回答

模型曾将明确的“无道具”传成字符串 `none`，引擎将其作为道具名拒绝。只读计算 DTO 现在将大小写不同的 `none` 统一为空道具，并在工具 Schema 描述中说明该约定。归一化发生在计算输入构造阶段，测试核对其余配置字段与原输入一致。显式 JSON 计算请求遵循既有无损回读校验。

另一次正文复核发现，用户明确“只看这两位参考成员的资料”，模型仍生成了培养建议。新增有限的纯资料范围识别，完整成员证据已核对时直接发布程序摘要，减少一次无关的最终建议生成。明确要求培养、搭配或攻略的请求继续使用原建议流程。单元测试同时覆盖纯资料返回和其他回合请求建议。

还有一次模型参数多包了一层，成为 `request.request`。新增 `DamageToolSchema.unwrapRequest`，仅针对模型规划的只读伤害工具移除一层完全冗余的封装，所有字段值继续进入原网关校验。多余同级字段、重复 JSON 键、尾随内容与其他工具参数按原输入交给网关处理。实际工具历史和输入证据使用整理后的执行参数，显式用户计算输入优先绑定。

## 浏览器验收工具

新增 `tools/campus/upgrade-provider-cards-browser.mjs`，通过真实 Chrome、Vite 同源代理、独立本地账号与 Spring 服务发起请求，保存原始 Run 事件、正文和截图。

| 场景 | 检查 |
| --- | --- |
| 图鉴 | 胖丁的类型、六项种族值、单张卡片、点击右侧图鉴联动、430px 显示 |
| 伤害 | 原始自然语言计算请求、真实引擎数值、完整条件、来源摘要绑定与页面实际链接 |
| 参考队伍 | 明确提供成员 7、39，展示两名参考成员与未保存状态 |
| 未知成员 | 虚构物种查询保留缺失说明，页面与事件均无事实卡片 |

工具支持 `enabled` 与 `disabled` 两种模式，关闭时检查正文仍可显示且无结构化卡片事件。每次注册独立账号，凭证保留在内存，结束后注销；异常时取消尚未结束的 Run。脚本拒绝个人后端 `8123`、远程 API、未知模式与覆盖旧证据目录。

报告记录测试脚本、相关前端组件、配置和运行 class 的摘要，以及实际模型调用次数。事件校验复用既有 Run 身份、事件顺序、正文拼接与完成终态校验。页面 JavaScript 错误、队伍写入请求与各个断言分别检查，语义质量继续单独复核。

隔离启动器增加 `-AnswerBlocks` 和 `-FrontendPort`。后者为本次本机测试端口增加明确 CORS 来源，默认测试前端端口为 3000。

## 环境与原始失败

首次脚本将卡片定位在正文气泡内部，实际卡片位于同一消息下方，已修正为消息级定位。保留 `artifacts/u2-provider-cards-browser-first-20261115/` 的脚本失败记录。

后续真实运行出现 PokéAPI 正文读取超时，导致杰尼龟资料缺失。该次记录位于 `artifacts/u2-provider-cards-browser-second-20261115/`。随后从既有本机公开缓存复制杰尼龟及相关资源，逐个验证来源路径和 SHA-256，保存 `artifacts/u2-provider-cards-public-cache-20261115.json`。验证范围包括模型、工具、卡片和浏览器链路，外部实时网络稳定性继续独立评估。

路由修复后的第一次实际运行保留在 `artifacts/u2-provider-cards-browser-fixed-20261115/`。该记录已生成 13～16 的正确计算卡片，并暴露来源链接校验缺口。最终结果使用新的采集目录，原始记录继续保留。

`artifacts/u2-provenance-on-browser-20261115/` 保留 `none` 道具失败，`artifacts/u2-facts-on-browser-20261115/` 保留重复 `request` 封装的拒绝结果。`artifacts/u2-cards-visual-on-browser-20261115/` 与 `off` 同名目录保留纯资料范围修复前的内容复核，各记录 1 个正文失败，页面断言结果单独保留。最终复测继续使用新目录。

## 复现步骤

先构建并测试最新代码，使用新的 `artifacts` 构建目录。启动两个隔离实例，分别开启与关闭卡片。

```powershell
.\ops\local\start-ablation-backend.ps1 -BuildDirectory artifacts/已验证构建 -OutputDirectory artifacts/新的卡片开启服务 -Port 18124 -FrontendPort 4328 -Skills -ContextAssembly -AnswerBlocks -ReferenceCacheDirectory artifacts/已校验公开缓存
.\ops\local\start-ablation-backend.ps1 -BuildDirectory artifacts/已验证构建 -OutputDirectory artifacts/新的卡片关闭服务 -Port 18125 -FrontendPort 4328 -Skills -ContextAssembly -ReferenceCacheDirectory artifacts/已校验公开缓存
node tools/campus/upgrade-provider-cards-browser.mjs http://127.0.0.1:18124/api artifacts/新的卡片开启浏览器 enabled
node tools/campus/upgrade-provider-cards-browser.mjs http://127.0.0.1:18125/api artifacts/新的卡片关闭浏览器 disabled
```

浏览器脚本临时使用 `4328`，两次顺序执行。模型 Key 继续从本机既有配置读取。公开缓存需要在 `artifacts` 中，缺少资料时可单独准备并核对公开快照。完成后按进程元数据关闭本次创建的隔离服务。
