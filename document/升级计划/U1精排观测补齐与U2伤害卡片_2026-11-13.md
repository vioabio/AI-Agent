# U1精排观测补齐与U2伤害卡片

日期：2026-11-13；分支：`codex/v1.1-agent-upgrade`。默认功能开关保持关闭，未提交或推送。

## U1 本轮补齐

1. **索引溢出校验**：HTTP精排结果先检查整数是否能转换为Java int，再检查范围及重复索引。4294967296等值不能再溢出为0。非有限分数拒绝，统一安全错误不携带供应商响应原文。
2. **精排总输入预算**：复用CL100K代理估算器及125%余量，默认上限12,000代理Token，包含query、完整候选正文和估算封装开销。超限不发送供应商请求，不截断canonical片段，返回原RRF顺序并标记`RRF_BUDGET_FALLBACK`。
3. **请求级诊断**：记录原召回次序、词法/语义rank、精排rank、有限分数、选中状态、chunkId及文档版本，以及该次检索/精排总耗时。失败结果不伪造精排rank或分数。
4. **Run事件接线**：在已有`retrieval.finished`事件中保存`rerankObservation`和实际状态；缺少受控Run时不冒建身份。状态按请求返回并从当前执行上下文发出，没有共享的“上次请求结果”字段。

诊断只覆盖chunk精排阶段；`LocalGuideSearch.search`后续的文档去重和显式组队主题保留仍按原策略执行，不将其描述为供应商精排结果。记录不包含原问题、片段正文、Key或供应商错误体。

这不是供应商真实Tokenizer或账单口径，也不是质量提升证明。返回给模型的最终证据仍受原上下文预算保护。

公开配置新增：

```text
VIO_GUIDE_RERANK_MAX_INPUT_TOKENS=12000
```

允许256～32768。现有enabled/endpoint/model/api-key/timeout/candidate-k/answer-top-k配置继续使用；默认enabled=false。HTTP适配器要求已实现的Jina-style `query/documents/top_n`请求和`results[index,relevance_score]`响应，不能不经适配就当作兼容任意供应商。

## U2 下一批：确定性伤害结果卡片

新增服务端`DamageAnswerBlock`、`contracts/damage-answer-block-v1.schema.json`，前端严格解析器及`DamageAnswerBlock.vue`。

首批仅接`calculateBattleDamage`，不声称`calculateGymDamage`、队伍建议、培养计划等块已经全部完成。

链路：实际工具返回 → 按调用ID匹配实际参数 → 核对条件校验状态、typedRequestDigest及输出投影摘要 → 构建只读DTO → Run租约边界发布calculation.card → 前端Schema/版本检查 → 展示。

卡片保留：

- 原始整数伤害区间、目标HP、完整百分比；零伤害有效。
- 双方实际解析后的物种、等级、性格、特性、道具、六项EV与IV。
- 单/双打、天气、地形、游戏/数据版本和证据摘要。
- 稳定blockId，重放按块去重；错误Schema或版本仅丢弃卡片，保留正文。

页面用约一位小数显示百分比，原始数值仍保留在事件里；条件可展开查看，没有任意保存、执行或写队伍按钮。不把伤害百分比解释为胜率或赛制合法性。

构造来源是受信计算回调，不是模型自由文本。摘要仅用来绑定输入/输出，不单独作为信任凭证。错误参数、陈旧证明、改写数字不能发布本次卡片。

沿用`vio.agent.answer-blocks.enabled`开关。公开图鉴/确定性计算没有绑定知识库或索引时，仅省略这些未绑定维度；没有放宽引用卡片和完整答案的血缘契约。
