## 2. M2：版本化知识生命周期与可信 RAG

### 已完成（✅）

- 建立 `source → document → document_version → chunk → ingestion_batch → knowledge_release → index_release` 的 Flyway V1～V7 数据模型；稳定身份、版本事实、审核状态、checksum、有效期和 active 指针分离。
- 增加 Catalog 的 JDBC/内存实现、索引任务与 release/chunk 血缘绑定；生产配置下没有向量存储绑定时 fail-closed，避免静默使用本地向量库。
- `KnowledgeIngestionService` 提供显式、可重复的导入服务：校验来源与文档归属、拒绝空 chunk、失败进入 quarantine；索引任务记录结果/批次失败，active 指针回滚由 `catalog.publishIndex` 负责，索引作业状态持久化与编排仍待补齐。
- 索引任务在调用方提供 `vectorIndexReleaseId` 时强制回读目录候选版本，校验状态、Embedding 模型/维度和 `knowledgeReleaseId` 血缘；未知索引不会写入向量表（fail-closed）。
- 检索侧提供版本过滤、词法/语义检索与 RRF 融合，并将 `documentId/documentVersion/chunkId/sourceUrl/evidenceText/retrievalScore` 装配为 `AnswerContract` 引用；无证据时走拒答/澄清分支。
- `DefaultRunExecutor` 在启用 grounding 时调用版本化知识门面，Run 事件中记录检索和引用结果。

### 代码证据

- `src/main/java/com/vio/vioaiagent/rag/`
- `src/main/resources/db/migration/V1__init_pokemon_versioned_schema.sql` ～ `V7__*.sql`
- `src/main/java/com/vio/vioaiagent/run/DefaultRunExecutor.java`

### 尚待补齐（🟡/⏳）

- 当前导入仍是同步服务调用；已提供受 API-Key 保护的 `/knowledge/**` ingestion/review/release/index/publish HTTP 契约和批次状态查询，但持久化队列、重试/DLQ 和 outbox 仍待补齐。相同 source+幂等键在单 JVM 由锁保护，跨实例仍需数据库原子 reservation/事务验收。
- 文档内容的 MIME/magic/schema/语言及游戏元数据校验、冲突人工审核、发布前质量门禁仍需接入实际数据管线。
- JDBC 语义检索故障会降级到词法检索；已增加 embedding 模型/维度配置并在生产启动时校验其与 V2 向量表一致，仍需在真实 PGVector 上验证事务一致性、召回和引用正确率，并补充 degraded 指标。当前检索已按 `APPROVED`、`embedding_status=READY`、`effective_from/effective_to` 和 active release/index 血缘过滤；跨来源冲突检测、冲突人工审核和真实过期边界数据仍待补齐，不能宣称完整知识质量门禁。

## 3. M3：唯一 Run、事件、持久会话与可恢复执行

### 已完成（✅）

- 引入唯一 `AgentRun` 状态机（CREATED/RUNNING/WAITING_APPROVAL/终态）、CAS 状态迁移、唯一终态事件和 `runId + eventId` 单调游标。
- 提供创建、快照、事件流、cancel、conversation/message API；SSE 支持 `afterEventId`/`Last-Event-ID`，终态后禁止继续发送非终态事件。当前 `/events/stream` 读取事件页后发送一次性 SSE snapshot 并完成，前端以客户端轮询/有限重连补读，尚非 broker 驱动的长连接推送。
- JDBC 与内存 repository、事件 append、幂等键和 executor ownership 已接入；并发审批恢复增加单 worker 占用，避免重复副作用。
- 前端 Run 流使用 reducer、游标和有限重连；刷新时从 sessionStorage 恢复 runId/conversationId/lastEventId，不保存 prompt、answer 或 API key。
- 生产配置 `VIO_LEGACY_AI_ENABLED=false`、`VIO_LEGACY_MANUS_ENABLED=false` 时旧 `/api/ai/**` 兼容链统一返回 410；现代 `/api/chat/runs` 是推荐入口。

### 尚待补齐（🟡/⏳）

- conversation 创建与首个 Run 的跨表原子事务、事件 outbox、重启后 checkpoint resume/replay、事件保留期清理及 410 Gone 摘要语义仍需真实数据库验收。当前重启恢复会把未完成 Run 明确收敛为 `SERVICE_RESTARTED` 失败，避免假装继续执行；队伍/收藏尚未提供持久化读写/删除 API，不能把会话 API 泛化为完整用户资产管理。
- 审批拒绝已增加 `approval.resolved → run.failed` 顺序回归；状态写入与两条事件尚未由同一数据库事务/outbox 原子提交，现场仍需补证据。会话创建保存后增加按用户回读校验，冲突返回 409。
- 取消接口的 CSRF/Origin 策略、事件分页/背压、broker fan-out/长连接订阅、跨实例幂等锁和生产级队列尚未完成；当前生产路径依赖同源/可信代理 API-Key 与严格 CORS。

## 4. M4：工具治理、MCP、HITL 与安全边界

### 已完成（✅）

- 版本化 capability card/catalog/gateway，覆盖身份/白名单、Schema、路径/网络策略、HITL、幂等、超时/重试、脱敏和审计；当前网关实际先做注册表 fail-closed 与 Schema 校验，再做角色/策略/Token 检查，未知工具 fail-closed。
- 玩家工具与运营/管理员工具分开注册；`PathGuard` 处理 `..`、相对路径、符号链接和允许根；SSRF 对私网、IPv4-mapped IPv6 做拒绝。
- HITL 正式路径绑定 userId、runId、工具版本、参数摘要和过期时间；审批恢复采用 compare-and-set/单 worker 保护。审计参数支持递归脱敏。
- MCP 开关关闭时主应用可启动；开启时先经过治理网关包装。未显式映射能力卡的 MCP 工具会安全拒绝（当前默认行为），生产接入仍需为每个工具补卡并提供连接、凭据受众、超时和审计证据；配置模板和生产凭据不进入前端。
- 现代 `/chat/runs` 以认证主体建立 `trainer` 工具上下文；仅允许 `operator/admin` 的管理能力默认拒绝。`tools/tool-capabilities.yml` 是评审/契约参考，运行时能力卡仍由 Java Catalog 注册；不能据此宣称动态 RBAC 或管理工具已向玩家开放。
- API-Key 认证后的 `TokenBinding` 会沿 `RequestContext → ToolExecutionContext → ToolExecutionGateway` 传递；网关在真实工具执行前校验 `allowedTools`，并由 `TokenStore` 以进程内分钟窗口 CAS 计数 `maxRequestsPerMinute`。令牌撤销会清理窗口；绑定不进入 Run/事件持久化。

### 尚待补齐（🟡/⏳）

- ToolExecutionGateway 已支持递归 object/array Schema、required、additionalProperties、enum、长度/数值/数组边界与 pattern；结构化 artifact 引用和更完整 Draft 2020-12 语义仍需补齐。
- SSRF 已拒绝私网/IPv4-mapped IPv6，并关闭搜索/抓取/下载重定向、限制下载超时与 20 MB 大小、拒绝文件名穿越；DNS 重绑定防护、出网域名 allowlist、MIME/磁盘配额和持久化幂等仍需生产化。
- 旧版兼容 HITL 端点在默认配置下返回 410，正式 approvalId 路径保留；正式 HITL pending 状态当前仅保存在 JVM `ConcurrentHashMap`，重启丢失且不支持跨实例共享/抢占，尚未落库。`HitlAuditSink` 未配置时为 noop，工具审计由 `AuditLogger` 追加本地 JSONL，二者都不是集中式、事务绑定的审计记录。幂等缓存仍是 JVM 内存实现，需迁移到持久化实现。
- 自研 `src/main/java/com/vio/vioaiagent/mcp/**` 协议栈仍在主源码树，尚未迁移到 `mcp-lab`；它是实验/兼容代码，必须保持关闭且不得绕过 `ToolExecutionGateway`。MCP 真实服务、凭据受众、超时和审计仍待现场验证。
- 长期记忆仍写入全局 `user.dir/memory/long-term.json`，生产 profile 默认关闭；尚无按 user 隔离、授权、TTL、删除和备份恢复语义，不能作为多用户生产记忆。
- `readFile` 的 Java 运行时能力卡和 `resources/tools/tool-capabilities.yml` 均仅允许 `operator/admin`；它仍必须限制到允许根目录的只读报告，不能暴露通用服务器文件读取。
- 频率窗口当前为单 JVM 内存实现，不能作为多实例全局限流；生产应迁移 Redis/网关限流并补充跨实例、时钟漂移和配额告警验收。异步 Run 只在创建请求时暂存绑定引用，进程重启后的未完成 Run 会按 M3 策略失败收敛，不会无绑定恢复执行。

## 5. M5：场景化前端、流式交互与反馈

### 已完成（✅）

- Vue 前端接入现代 Run API/SSE：creating/running/waiting_approval/reconnecting/终态均有 reducer 状态；单飞、AbortController、游标和有限重连已实现。

### 尚待补齐（🟡/⏳）

## 6. M6：反馈纠错、评测门禁与可观测

### 已完成（✅）

- 反馈/纠错状态机、evaluation run 契约、七类数据集样例、指标字典和 `quality_gate.mjs` 已版本化；`ci` 与严格 `release` 模式分开。

- 已运行 CI 质量门禁：

  ```powershell
  node evaluation/quality_gate.mjs --mode=ci --report artifacts/v1.0/eval/ci-local-report.json
  ```

  该门禁检查 JSONL 结构、版本键、caseId 唯一性和红队期望值。

### 尚待补齐（🟡/⏳/❌）

- 当前数据集是脱敏 scaffold 样例，未达到规格中的 200/100/50 等生产规模，未产生真实模型推理、Recall@5、引用正确率、Groundedness、TTFT/P95、Token/成本报告；TTFT 当前是在完整答案返回时记录的近似值，`recordTokens`/SSE 计数尚未接入业务主链，真实请求分桶/成本采集仍待接入，因此严格 release 门禁应保持阻断。
- 反馈发布尚未触发完整 reindex/re-answer/outbox；当前反馈 UI/`CorrectionCase` 在上下文缺失时允许 `unknown` 占位，尚未建立 answer→release registry，不能宣称纠错链路可追溯；trace、指标按场景分桶和真实 OTel 链路需要接入运行环境。

## 9. 发布结论

本轮已把 M2～M7 的关键代码骨架、接口契约、安全边界、前端 Run 体验、评测/监控配置和运维 runbook 落入仓库；它足以作为秋招项目的工程化演示基线。由于真实数据规模、外部依赖和生产演练尚未完成，**当前结论为“v1.0 候选构建，发布状态 BLOCKED”**。完成上述环境验收并将命令输出、镜像 digest、评测报告和 RPO/RTO 回填到《v1.0 最终验收清单》后，才能将版本标记为正式发布。
