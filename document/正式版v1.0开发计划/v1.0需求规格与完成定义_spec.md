## 1. 目标

把当前“能聊天、能调用工具、能做简单 RAG”的工程原型，升级为一个面向训练家的、版本明确且可验证的宝可梦垂直智能体。v1.0 的完成不是增加最多组件，而是让每条核心链路都具备：明确输入、可追溯数据、确定性结果、结构化事件、失败兜底、质量评测和回滚路径。

### 1.1 目标用户

| 用户 | 需要解决的问题 | v1.0 交付 |
|---|---|---|
| 训练家 | 想知道某个事实、配招、队伍或攻略，并判断是否适用于自己的版本 | 版本选择、图鉴卡、计算卡、引用卡、队伍分析、反馈 |
| 知识运营者 | 修正错误知识并安全发布 | 数据导入、隔离、审核、发布候选、评测、回滚、通知 |
| 平台运维者 | 确认服务稳定、工具安全、成本可控 | Run 状态、Trace、指标、告警、备份、恢复和审计 |

### 1.2 三档读者

- **🐤 小白**：只了解基本编程，希望沿着类比、流程和源码链接完成第一次实现。
- **🦾 后端开发者**：熟悉 Java/Spring，希望在 60～90 分钟内掌握分层、契约、事务和测试边界。
- **⚡ 老手/面试官**：关注取舍、失败案例和量化证据，希望从架构图、设计决策和 Q&A 快速复盘。

## 2. 首发范围冻结

本节的执行记录见 [`v1.0首发范围冻结记录.md`](./v1.0首发范围冻结记录.md)。数据导入时必须把内部快照键映射到来源公布的官方补丁号，并保留发布证据。

下表在 M0 结束前必须填写最终值；没有冻结值时，Agent 只能追问，不得猜测。

| 维度 | v1.0 推荐范围 | 必须记录的键 |
|---|---|---|
| 主游戏 | 宝可梦朱/紫 | `game_release_id`、补丁号 |
| DLC | 零之秘宝；篇章显式选择 | `dlc_id`、数据截止时间 |
| 语言 | `zh-CN` 正式输出，英文/日文仅用于别名消歧 | `language`、别名版本 |
| 对战模式 | 剧情/休闲单打、双打、一个已审核 VGC 规则集 | `battle_format_id`、`ruleset_version_id` |
| 数据发布 | 主数据、文档、索引作为同一可追溯发布单元 | `data_release_id`、`knowledge_release_id`、`index_release_id` |
| 不支持 | 其他世代混答、实时天梯代打、账号/交易、未审核活动传闻 | `unsupported_reason` |

## 3. 功能需求

### P0（没有就不能称为 v1.0）

1. **事实问答**：查询图鉴、形态、属性、种族值、特性、招式、进化、版本可用性，并返回适用版本与来源。
2. **上下文澄清**：游戏、DLC、语言、赛制或规则缺失/冲突时先追问。
3. **确定性计算**：双属性克制、伤害、速度线和队伍合法性由 Java 领域服务计算，模型不能直接心算。
4. **引用式 RAG**：攻略和解释走 PostgreSQL 全文检索 + PGVector，输出文档版本、chunk 和证据；没有可靠证据时拒答。
5. **唯一 Agent Run**：创建、运行、等待审批、完成、失败、取消和超时状态可查询，事件可断线恢复。
6. **工具治理**：公网只开放宝可梦只读工具、确定性计算和受限检索；高风险工具默认关闭并审计。
7. **会话隔离**：重启后会话可恢复；不同用户不能读取彼此消息、队伍、反馈和工具记录。

### P1（有则达到成熟演示效果）

1. 六人队伍保存、导入、弱点矩阵和合法性导出。
2. 太晶团体战攻略与活动时效标记。
3. 点赞/点踩、纠错 case、运营审核、知识发布、定向评测、重答通知。
4. 场景化前端卡片、事件时间线、引用、错误态、取消和重连。
5. Micrometer/Actuator/Prometheus/Grafana 指标，CI 评测门禁和不可变镜像。

## 4. 非目标与保护边界

- 不开放任意 `cmd.exe`、Shell、文件读写、无约束下载或任意网页抓取。
- 不在同一个 Prompt 中混合没有版本键的多个世代和规则。
- 不同时维护自研 MCP 生产栈和 Spring AI MCP Provider；自研栈留在实验模块。
- 不以 README、类名、配置或单元测试数量替代真实主链、集成测试和运行证据。
- 不在单 Agent 质量未达标前建设多 Agent、Kafka、Elasticsearch、Neo4j 或 Kubernetes。

## 5. 领域与数据契约

### 5.1 必备实体

`game_release`、`data_release`、`pokemon_species`、`pokemon_form`、`form_fact_version`、`move_fact_version`、`learnset_version`、`ability`、`item`、`ruleset_version`、`pokemon_availability`、`saved_team`、`team_member`、`knowledge_source`、`document_version`、`document_chunk`、`knowledge_release`。

### 5.2 运行与治理实体

`user_account`、`conversation`、`chat_message`、`agent_run`、`agent_event`、`agent_checkpoint`、`tool_execution`、`hitl_approval`、`user_feedback`、`correction_case`、`evaluation_case`、`evaluation_run`、`evaluation_result`。

### 5.3 统一元信息

外部记录、文档和向量都必须保存：

```text
source_id / source_url / license / trust_level
language / game_version / battle_format / ruleset_version
effective_from / effective_to / retrieved_at / checksum
schema_version / content_version / owner / review_status / published_at
```

### 5.4 Run 与事件契约

```json
{
  "schemaVersion": "1",
  "eventId": "42",
  "type": "answer.delta",
  "sessionId": "session-id",
  "runId": "run-id",
  "traceId": "trace-id",
  "timestamp": "2026-09-01T10:00:00+08:00",
  "payload": {}
}
```

每个 Run 只能产生一个终态事件：`run.completed`、`run.failed`、`run.cancelled` 或 `run.timed_out`。浏览器断线不等于取消；客户端按 `eventId` 重连，超过保留期返回明确的 `410 Gone`。

## 6. 完成定义（Definition of Done）

一个里程碑只有同时满足以下条件才算完成：

1. 代码位于正确分层，Controller/组件没有吞入业务编排或协议细节。
2. 正常、边界、依赖失败和权限失败路径都有测试或可复查的运行记录。
3. 配置、数据、Prompt、模型和索引版本可追溯；敏感信息不进代码、URL 或日志。
4. 有明确的回滚点，回滚后旧版本数据/索引/镜像仍可工作。
5. 验收清单中的证据链接、命令、时间、环境和 commit 已填写。
