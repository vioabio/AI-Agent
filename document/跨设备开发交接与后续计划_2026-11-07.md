## 2. 本次 404 的诊断与处理

检查发现，原设备 8123 的 Java 进程在 **2026-11-04 15:38** 启动，而候选接口在 **2026-11-06** 才新增。正在运行的旧进程没有新接口；重新编译文件或刷新 Vite 页面不会让它自动加载新 Controller。

在 IDEA 停止原 `VioAiAgentApplication`，确认编译成功后重新 Run，保留原运行配置中的环境变量。避免另开第二个实例抢占 8123。不要直接复制旧设备 JDK 的绝对路径到新设备。

补充实测：2026-11-07 已用最新可执行 JAR 在备用端口验证三类真实接口，均返回 200（道具 356 项、形态 445 的特性 2 项、朱／紫招式 62 项），之后替换了原设备 8123 的旧进程。重启后原内存 Session 失效，需要重新登录，账户和队伍数据库保留。

后续也可在停止旧后端、正确设置 JAVA_HOME 后，从仓库根目录运行 `powershell -ExecutionPolicy Bypass -File tools/start-local-backend.ps1`。该脚本复用本机 `.run/VioAiAgentApplication.run.xml` 中的环境变量但不打印值，并经 Maven 编译后启动 local 后端；端口被占用时明确拒绝，不自动杀进程。

接口还要求 `local` profile 和 `vio.pokemon.reference.enabled=true`；`demo/prod` 当前没有开放本地参考资料模块。不要为规避 404 关闭鉴权或擅自放开生产入口。

新前端遇到 404 会提示重新编译、重启及检查代理配置，不再只有泛化的“读取失败”。如果重启后仍失败，在登录后的浏览器 Network 面板确认：

1. `/api/pokemon/reference/status` 返回 200，enabled 为 true。
2. `/api/pokemon/reference/build-options?kind=item&dataReleaseId=pokeapi-reference-v1&gameReleaseId=pokemon-scarlet-violet` 返回 200 和 items。
3. 特性、招式请求另外带当前成员的 `pokemonId`，kind 分别为 ability、move。
4. Vite 代理指向本次启动的 8123，未指向旧进程或其他设备。401/403 应检查登录和权限，不能当成没有数据。

## 3. 新设备准备与启动

安装 Git、JDK 21，以及满足前端 package.json engines 的 Node.js（建议 Node 22 LTS 的较新补丁版）。本地模式无需服务器和 PostgreSQL。

```powershell
git clone git@github.com:vioabio/AI-Agent.git
cd AI-Agent
git switch main
git pull --ff-only
java -version
node --version
```

如果 JAVA_HOME 无效，先设置为新设备实际安装的 JDK 根目录，再更新 Path；不要指向 bin 子目录。

在本机 IDEA 环境变量或当前 PowerShell 中配置 `DEEPSEEK_API_KEY`，不要粘贴进聊天、文档或 Git。其他本地配置按 README 和示例配置重新设置，不要覆盖现有真实配置。

```powershell
# 在仓库根目录；使用新的终端或 IDEA 运行配置保留本机模型变量。
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:VIO_POKEMON_REFERENCE_ENABLED = 'true'
.\mvnw.cmd spring-boot:run
```

另一个终端启动前端：

```powershell
cd AI-Agent\vio-ai-agent-frontend # 按实际克隆目录调整
npm ci
npm run dev
```

打开 http://localhost:3000，注册本机账户并登录。新设备没有默认用户名和密码。不要将 API Key 当成登录密码。

## 4. 迁移个人数据

- 仅迁移队伍：旧设备导出 JSON，新设备登录后导入并保存即可。
- 完整迁移：先停止旧设备后端，再安全复制 `.local-data` 到新设备对应仓库目录，包含账户数据库、缓存及可能的 SQLite WAL/SHM 文件；账户及对话等数据与实际配置路径有关，应核对运行配置后迁移。不要提交该目录到 Git。
- 密钥、`.run`、私有 application-local 配置均通过安全方式独立迁移或重建，不能依赖 git clone 自动获得。
- 若不迁移账号库，新设备需重新注册；模型 Key 不会恢复旧账户密码。

## 6. 后续开发顺序

以下是建议待办，并非已经完成的能力。

### P0：在新设备完成实际使用验收

先确认后端确实重启，再依次测试中文性格、特性、四招、道具的选择与保存回读；测试 JSON 导出导入后再保存；测试配置用于伤害计算。验收以登录后的真实请求为准，不能用 mock 浏览器测试代替网络和运行配置验收。

### P1：资料完整性与说明

补充特性和道具中文说明、学习方式及等级展示。当前上游固定 CSV 未收录朱／紫简体中文特性说明，下拉框明确提示缺失；不要伪造说明，也不要把旧版本机制直接当朱／紫机制。新来源必须附版本、来源及摘要，更新后审查数据差异。道具目录不等于当前版本可获得清单。

### P2：候选体验与约束

增加属性、招式分类和学习方式筛选；增强历史手动值的匹配提示。增加移动端、长列表、断网、成员快速切换和键盘操作的验收。明确区分单项候选、组合可得性及赛制合法性，不把三者混为“合法”。

### P3：文件格式拓展

JSON 稳定后再增加 Showdown 文本等格式。先写清字段映射、形态/名称解析、版本缺失和无法解析项的处理；导入必须预校验，不覆盖已保存队伍，不信任文件中的 ownerId、数据库 ID 或指令内容。

### P4：发布与持续集成

只有需要公网演示时再推进部署；当前本地运行不依赖云服务器。提交前运行下列检查，推送后查看实际 Actions 结果。新增后端接口必须同步启动或重启测试进程，避免再次出现前后端版本不一致。
