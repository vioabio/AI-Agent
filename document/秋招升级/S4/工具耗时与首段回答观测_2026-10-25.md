# S4 第五批：工具耗时与首段回答观测

本批把模型、工具和公开回答的计时分开，用于定位“排队慢、工具慢还是回答准备慢”。增加服务端单调时钟观测、成功历史保存、浏览器本次请求接收计时及默认折叠的详情展示。没有改变工具授权、审批、重试、副作用 UNKNOWN、租约提交或恢复策略。

## 三种首段时间

| 字段 | 起点 → 终点 | 边界 |
| --- | --- | --- |
| `calls[].firstTextDeltaMs` | 应用订阅 SDK stream → SDK 首个非空文字 | 包含规划调用，可能不是公开回答；不是供应商内部生成时间 |
| `responseTiming.firstAnswerReadyMs` | 本次执行任务注册 → 第一段可公开非空文字已准备 | 在事件提交、网络传输之前；包括调度、规划、工具及答案校验 |
| `clientTiming.firstAnswerReceivedMs` | 页面发起新请求之前 → reducer 首次接受公开回答内容 | 包含网络、事件补读、审批等待；不是 DOM 绘制时间 |

三种值不能合并成同一个 TTFT，也不能把审批前后执行尝试的首段延迟相加。`DELTA` 只说明公开答案分段准备，程序分块也属于此路径，不能据此证明模型 SDK 使用了流式调用。`BUFFERED` 表示完整答案就绪后才准备公开。

`response-timing-v1` 同时记录 `dispatchWaitMs`、`observedMs`、`origin=TASK_REGISTERED`、`deliveryMeasured=false`。调度等待是任务注册到 worker 入口，包含本地调度和注册开销，不等于纯线程池队列等待。未产生公开文字时首段值为 null；尚未进入 worker、未能创建账本的失败也保持未知。成功路径与审批尝试沿用已有 usage/终态快照机制，停止后冻结，迟到文字不能修改。

浏览器使用 `performance.now()`，只在当前页面新建请求时记录。刷新、恢复 Run 或读取历史不会用日期反推本机接收时间；其值不持久化进账号历史。没有可用单调时钟时保持未知。Node 回归采集器已有的 `firstAnswerDeltaMs` 是轮询观测值，也不能冒充浏览器测量。

## 每次工具执行拆分

`tool-timing-v1` 在原有有界执行器中观察每次物理尝试：

1. `queueWaitMs`：提交线程池前到 worker 进入；仍排队就超时/取消时只记录停止前等待。
2. `authorizationMs`：worker 进入到业务回调开始，包含原有 deadline、授权和启动门禁检查；未启动回调时记到停止边界。
3. `executionMs`：业务回调开始到结束；超时/取消且尚未结束时，只记录调用方停止之前的已观测部分。
4. `observedMs`：本次提交到调用方返回、失败或停止边界，包含调度与唤醒开销。

低风险幂等读重试时保留各次尝试，汇总只对已知值相加。未观测到回调开始时执行时间为 null，不补零。`callbackCompleted=false` 不代表外部副作用不存在；回调可能忽略中断，原副作用状态和人工核对要求继续生效。停止边界之后的回调返回不能重写已冻结计时。

缓存命中和已有副作用终态重放使用 `scope=BYPASS`，分别标明 `CACHED_RESULT`、`IDEMPOTENT_REPLAY`，本次没有调用回调，不制造“执行耗时 0”。业务回调之前就被治理层拒绝的路径可能没有分段观测。原 `durationMs` 保留兼容，其范围包括其他治理工作；缺少新字段的旧记录显示“处理…（未拆分）”，不伪装成执行时间。

逻辑调用按 governanceEventId 去重，每个执行尝试最多保存 64 条工具计时，截断显式标记。保存前只接收固定 schema、状态、名称和有界非负整数，不保留插件任意对象。明细中的 `observedMs` 不能当成整项 Run 耗时，多个工具/重试也不能无条件相加后宣称端到端延迟。

## 接线与存储

```text
BoundedToolExecutor → ToolAttemptTiming → ToolExecutionGateway tool.finished/timing
  → RunService 事件 + ModelUsageLedger.toolTimings
  → usage / 终态 modelUsage
  → 成功回答 metadata.modelUsageAttempts → 本地 SQLite 历史

ManagedRunTask → RunAttemptTiming → 公开文字准备位置
  → 同一个尝试账本与历史快照

页面新建请求 → performance.now → reducer 接受第一段回答
  → 页面内 clientTiming（刷新后不伪造）
```

本地成功回答沿用账号隔离的 history.sqlite，无需新增数据库表。默认本地模式中的失败/取消事件没有因此新增跨进程持久恢复保证。旧历史没有计时字段时继续未知，不回填估计。

Run 终态若早于在途工具结算，冻结的尝试快照可能尚无该工具的完整计时；不会等迟到回调再改写终态。工具自身超时的部分观测、指标与当前 Run 可接受的事件分别受各自边界限制，不承诺每个取消任务都有完整工具明细。

前端在已有“模型用量与耗时”折叠区显示调度、服务端就绪和工具分段；执行过程可直接看排队/校验/执行。回答正文和复制内容不混入这些元数据。本机接收时间在新请求产生后单独标明来源，桌面及窄屏均支持查看。

新增 Micrometer Timer：`vio_run_answer_ready`（path=delta/buffered）、`vio_tool_queue_wait`、`vio_tool_authorization`、`vio_tool_execution_observed`（callback_completed=true/false）。没有使用 run、账号、工具名等高基数标签。旧 `vio_agent_ttft` 为兼容保留，但 RunService 不再把完整答案或程序分块采样到该混合口径。
