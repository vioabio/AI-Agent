# S4 第七批：Token估算误差观测与校准报告

本批为每次模型调用保存基础代理估算、预算估算和供应商原生输入用量，并增加离线误差审计和网页折叠详情。默认25%余量、上下文窗口和累计额度均未改变，仍标记`PROXY_UNCALIBRATED`，没有根据小样本自动调低限制。

## 口径与接线

基础值使用既有CL100K代理计数，保留固定消息/工具开销；预算值继续逐段乘以配置余量并向上取整。两项在同一次分词过程中记录，避免重复分词。固定开销不按比例缩放，因此不能把旧预算估算除以1.25来恢复基础值。

`context-budget-v1`新增`estimateSchemaVersion=context-estimate-pair-v1`和`baseEstimate`。原`lastEstimate`仍为预算值，分别记录系统、历史、工具定义、工具结果和当前消息，原裁剪与准入逻辑不变。

每个`model-usage-v1.calls[]`新增`tokenEstimateComparison`：

- `PAIR_RECORDED`：保存基础/预算/原生输入数、两项有符号差值及预算是否覆盖报告值。
- `UNKNOWN`：原生用量缺失、旧记录没有基础估算、计数非法或输入为0时保持未知，不制造误差0。
- 只比较输入Token。输出、推理和缓存细分不额外加进输入；原生输入总量不因缓存命中而减掉。

这是同一个应用ChatModel调用边界的观测配对，不证明供应商精确分词、内部HTTP重试或部署模型版本。流式累计usage沿用最后报告值，失败/取消未取得完整用量时排除；终态后不能补写已冻结快照。

成功历史沿用SQLite metadata，无需新表。前端同时补齐了归一化时遗漏的逐次请求预算，并验证重复归一化后不丢失。旧历史没有新字段时不反推。网页默认折叠，仅展开“模型用量与耗时”才显示输入对比和低估提示；复制正文不混入这些数字。

## 固定采集与审计工具

计划文件为`evaluation/campus/s4-token/manifest.json`，3条development、3条validation，覆盖中文、英文、混合JSON/emoji、历史和确定性属性工具。它独立于S2保留集，未用验证组选择新策略。

```powershell
# 独立本地实例就绪后，使用新目录，不覆盖旧证据：
node tools/campus/s4-token-scenario.mjs http://127.0.0.1:18141/api artifacts/campus/s4-calibration/my-capture
node tools/campus/token-calibration.mjs artifacts/campus/s4-calibration/my-capture/capture.json artifacts/campus/s4-calibration/my-analysis
```

采集器只访问HTTP回环地址，创建专用本地账号，密码/Cookie仅在内存。使用独立accounts/history/teams/guides SQLite路径及18141端口，开启回答流式，保持报价关闭。启动方式沿用第六批，将目录改为s4-calibration。Maven测试和服务启动顺序执行，避免并发编译。

审计检查固定计划摘要、事件文件SHA、冻结用量快照、采集记录和成功历史。统计按开发/验证组、配置提供商、请求模型、响应模型（缺失保留null）、usage来源、CALL/STREAM和历史/工具形态分组。报告同时记录声明调用数、可比较数及排除原因，不把缺失用量算作0。

相对误差为`(估算输入-原生输入)/原生输入`，绝对相对误差取绝对值后按调用平均；不是合并Token后的加权比率。P50/P95使用nearest-rank。预算覆盖比例的分母仅为可比较调用，排除项另外列出；有缺失、未完成任务或预算低估时命令返回非0，报告仍保留。

工具生成JSON和Markdown，不自动修改配置，也不颁发“已校准”资格。调用共享Run和历史，不能视为独立样本计算未经论证的置信区间。

## 本轮结果

真实配置为DashScope/qwen-plus，6个Run全部完成，共13次模型调用，其中6次STREAM。13条均取得可比较原生用量，无排除，基础和预算估算均未低估本批输入。原生完整用量合计45229 Token；未配置报价，费用保持未知。

| 组别 | 调用数 | 基础估算平均绝对相对误差 | 预算估算平均绝对相对误差 | 预算低估次数 |
| --- | ---: | ---: | ---: | ---: |
| development | 6 | 24.73% | 54.77% | 0 |
| validation | 7 | 22.78% | 52.12% | 0 |
| 全部 | 13 | 23.68% | 53.35% | 0 |

本批误差均为高估。原生单次输入范围1466～6165，含历史的调用2条、暴露工具定义7条、携带工具结果2条，形成8个分组。远未覆盖窗口边界、大规模历史、所有工具、其他模型或多模态；因此保留125%预算策略。结果不是费用节省、准确率或响应提速结论。

工程检查：后端 **1026项，0失败、0错误、3跳过，BUILD SUCCESS**；前端契约137项、Node工具55项和Edge浏览器14项通过，lint/typecheck/build及安全契约通过。测试覆盖固定开销/逐段取整、CALL/STREAM配对、缺失/0值、篡改拒绝、冻结、历史保留和桌面/窄屏提示。

原始测试编译失败暴露错误的SDK测试类引用，已改用项目既有native usage fixture；日志保留。首次实测审计发现usage事件附加了外层版本血缘，直接比较整个对象会误报变化；六条记录的归一化用量均相等，现按已有usage审计口径比较受控投影，仍校验原始事件SHA和历史，新增回归确保真实用量变化仍拒绝。没有为此重跑模型或筛掉案例。

证据见[误差JSON](evidence/calibration-v1/calibration-report.json)、[误差表](evidence/calibration-v1/calibration-report.md)、[工程汇总](evidence/calibration-v1/verification-summary.json)及[运行身份](evidence/calibration-v1/runtime-identity.json)。完整采集与原始日志保留于`artifacts/campus/s4-calibration/`和`artifacts/s4-calibration-*.log`。浏览器截图使用模拟API，包含刻意构造的低估示例，不是真实模型低估证据。

469个Java/依赖/计划摘要、50个加载class与采集版本一致；S2冻结题集、S3语料和私有配置未改。独立验证服务已停止，没有提交、推送或部署。原Surefire退出等待和本地Bean Validation provider告警仍保留。

## 后续

首批误差测量链路已具备，可在换模型、SDK或工具后复测。扩大样本、接入供应商精确分词或调整余量，需要新的固定开发/验证计划，不能把本报告覆盖率推广到其他输入。低估提示是事后观测，不能撤回已发送的请求。

继续做模型约束遵守与S2/S3独立质量回归，再整理S5架构、演示和面试材料。账单核对及真实PostgreSQL集成仍待实际环境验证，S4整体验收未因本次测量自动完成。
