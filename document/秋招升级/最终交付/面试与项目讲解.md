# 面试与项目讲解

## 简历描述

**VIO宝可梦智能体｜Java 21 / Spring Boot / Spring AI / Vue 3 / SQLite / Node.js**

- 实现对话、图鉴和队伍配置统一工作区，接入PokéAPI参考缓存、SQLite/BM25攻略检索和本地Smogon伤害计算，支持正文增量展示与账号隔离的会话持久化。
- 设计Run生命周期、工具白名单、参数/归属检查、上下文与任务预算；队伍修改采用“预览—用户确认—保存回读”，冲突不静默覆盖。
- 建立真实任务采集与来源约束，记录实际工具输入、计算结果、供应商usage和脱敏失败线索；用固定开发/保留题分开评估，保留失败和未知结果。具体数字以本次验收报告为准，不填写整体准确率、QPS或降本比例。

## 一分钟讲解

“这是一个本地运行的宝可梦网页智能体。模型负责理解问题和选择工具，Java层负责账户归属、工具权限、预算、计算和保存边界。图鉴走真实参考数据和缓存，攻略用SQLite/BM25检索，伤害由本地Smogon引擎计算。涉及队伍修改先给预览，用户点击确认后再校验并保存。我重点解决的是：模型选择了工具不等于有权执行，工具成功不等于回答正确，所以把参数、结果、来源和质量评价分别记录。已知不支持的条件会说明，不能靠流畅文字补造。”

## 可展开的失败复盘

1. **普通问答被工具Schema连带拒绝。** 嵌套DTO存在局部定义与根相对引用，供应商会在选择工具前校验整组定义。展开可核对引用，保留字段约束和原回调；缺失、外部和循环引用拒绝注册。先用真实协议确认，再跑原题，不能只换Key或无限重试。
2. **看似合理的机制建议没有证据。** 单次计算不能证明换条件后伤害一定增加。保留原数值，增加有限断言校验，拒绝时展示程序核对的区间解释；明确这不是模型策略正确率提升的证明。
3. **失败原因被笼统错误掩盖。** 记录固定错误类别、可读取HTTP状态及来源，不保存原始正文、Header或Key。未知仍未知，历史错误不能凭后来的成功探测回填。
4. **安全拒绝显示用量未知。** 观察到零次调用不自动等于确认零调用。在明确短路路径上显式声明无模型，再用模型Mock及不可用Key场景核验；其他缺失usage不改成零。
5. **六项数值正确但合计错误。** 统一开发题复测发现杰尼龟44/48/65/50/64/43被模型加总成364，实际是314。将有限的基础资料查询改为按本次来源直接展示并计算合计；混合培养问题保留原链路。修复与回归不能反向把旧答案改成正确，也不能推广为所有数学/机制问题已解决。

每个复盘应能指出触发请求、失败记录、修改位置和回归范围。不要把程序拒绝、引用节选或计算模板当成模型自由生成样本。

## 常见追问

| 问题 | 回答要点 |
| --- | --- |
| 和普通聊天接口有什么区别？ | 有任务生命周期、工具规划、实际执行与证据、可取消/重连、审批和持久化；不是只有一个prompt |
| 为什么不用向量库？ | 当前知识规模和部署目标先用SQLite/BM25，依赖少、来源易核对；向量代码存在不等于默认启用或更准确 |
| 能消除幻觉吗？ | 不能。结构化事实、确定性计算和有限展示规则降低特定错误，仍须评价机制和策略语义 |
| 为什么确认后也可能保存失败？ | 预览期间原数据可能改变，必须再检查修订、身份和条件，拒绝覆盖 |
| 如何评价模型？ | 冻结题目与分组，先开发再冻结候选，保留题独立报告；工程、逐项AI复核、人审分别统计 |
| 全部测试通过意味着什么？ | 只说明对应范围通过。小型种子集、重复运行、Mock或程序模板不证明泛化准确率 |
| 为什么还要区分Token估算？ | 准入要先估算，计量要等供应商usage；流式尾段与失败可能缺失，参考价不是账单 |
| 是企业级生产Agent吗？ | 有治理和生产适配实践，但当前验收对象是本地网页应用，不承诺高可用、多实例或任意副作用恢复 |

## 关于实现与协作

这不是自研基础模型，领域资料和计算引擎也不是个人原创。应说明哪些是框架/上游提供、哪些是自己完成的适配、边界设计、问题复现和验证。若使用AI协助开发，应如实说明，并能独立解释核心代码、失败原因与设计取舍。
