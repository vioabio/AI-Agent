# 整队核对多成员与失败边界

日期：2026-10-27。接续[整队草稿原参数执行路径](整队草稿原参数执行路径_2026-10-27.md)。本批完善 S3 工程边界，不作为模型规划或人工质量验收。

## 修复

整队固定草稿请求及实际工具结果的绑定解析现在拒绝重复 JSON 字段。此前默认解析器采用同名字段的最后一个值，可能隐藏位置、成员编号或配置的歧义。新测试覆盖版本、位置、物种编号、等级、努力值和报告联合状态的重复字段。

直接路径遇到歧义输入时不选择程序执行，仍由原处理流程接管；这不等于整个聊天 API 对所有 JSON 文本统一返回 400。报告或实际参数存在重复字段时，不能通过整队答案绑定校验。

同时修复 16000 字符边界不一致：原路由接受正好 16000 字符，而答案原队伍保护条件要求小于 16000。现在两处均允许等于上限，超过上限均不识别为该整队固定请求。

## 新增开发验证

新增 `TeamBuildRouteMatrixTest`，共 13 项执行实例：

| 场景 | 验证内容 |
| --- | --- |
| 1、2、3、4、5、6 成员，6项 | 混合完整配置与 null；倒序位置保持；一次网关调用；输出摘要绑定完整报告；零模型推理调用 |
| 6 成员均完整 | 输出未截断、6位完整报告通过绑定，不宣称联合合法 |
| 一位资料不足 | 另一位参考匹配仍独立保留，不升级为全部匹配 |
| 版本与归属拒绝 | 不读取成员，不发布成功摘要，不调用模型补救 |
| 第二位执行异常 | 不继续后续成员，不展示部分报告为整队完成 |
| 成员间取消 | 第一位后取消，停止剩余读取，不封装成功报告 |
| 重复字段 | 直接路径不选择，实际参数与报告绑定拒绝歧义 |
| 字符长度边界 | 16000/16001处路由和原队伍保护判断一致 |

正常路径经过真实 `ToolExecutionGateway`、工具回调、参考服务、摘要展示和事件链；参考数据使用临时目录中的确定性合成 fixture，模型使用 mock。成员间取消直接验证聚合服务；JSON/长度直接验证解析及绑定。因此不能把13项称为13次真实模型测试、13只真实宝可梦或资料质量验证。

失败回调仍遵循原网关的一次只读重试策略。版本/归属拒绝两次检查均无成员读取；成员异常两次尝试均停在第二位，最终失败。未更改重试、权限、超时或写入策略。

首次运行的10项失败来自测试断言：框架初始化读取模型默认选项不等于模型推理调用；原网关已有一次重试，也不能按一次底层回调计数。修正测试分别检查 `call/stream` 未调用及原重试边界，生产策略保持不变。首次失败日志保留。
