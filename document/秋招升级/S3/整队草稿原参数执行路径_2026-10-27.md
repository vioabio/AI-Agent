# 整队草稿原参数执行路径

日期：2026-10-27。范围：S3 整队只读核对入口的参数保留；不代表 S3 整阶段完成。

## 解决的问题

上一批真实验证中，模型会将明确提供的两成员草稿拆成多次子集核对。最终展示已有原队伍保护，但严格的每次调用检查仍只有 1/2 通过。原始失败、采集器误判及重新审计记录保留在[上一批记录](整队Agent只读核对与原配置保护_2026-10-27.md)，本批使用独立计划和证据目录。

## 实现

- 新增 `TeamBuildRequestRoute`：仅匹配界面固定整队核对标题和一条严格 JSON 请求。完整保留成员位置、配置及 null；最多 16000 字符，具体成员约束继续由原解析器验证。
- 接受界面标题和既有开发采集标题两个明确模板；已保存队伍读取、混合写入/计算指令、引用、代码围栏、额外字段及尾随 JSON 不选择该路径，继续走原处理流程。
- `ToolCallAgent` 经原工具网关调用 `checkPokemonTeamBuild`，继续执行身份、Run 归属、版本、超时和只读约束。无权限时不能绕过，也不生成模型答案补救。
- 事件标记 `PROGRAM_SUPPLIED_TEAM_REQUEST`。报告经原参数与输出绑定校验后生成确定性摘要；该路径不调用大模型。已保存队伍仍由模型选择 `readCurrentTeam` 后核对。
- 本地运行状态暴露路由版本和触发来源，前端契约测试校验前后端固定标题一致。生产前端模板无需变更。

真实验证使用隔离本地端口 18229、独立账户与 SQLite/缓存目录。配置平台 DashScope、模型 qwen-plus；公共缓存使用已冻结的两物种参考包，未扩充资料来源。两条任务均检查实际工具输出与 HTTP 报告一致、历史消息一致、无审批或写入工具、前后保存队伍不变。515 个 Java 源文件摘要和运行类身份在采集中保持一致。采集后已停止隔离后端，未操作日常 8123/3000 服务。

上述是两种执行方式分别通过的工程验证，不能写成模型规划正确率从 1/2 提升到 2/2。普通自然语言草稿仍可能分拆；本批只解决固定明确请求的参数传递。浏览器回归未在本批重复执行，上一批两条受控浏览器记录仅为历史证据。

Surefire 仍有 fork JVM 退出超过 30 秒的既有告警，完整测试最终成功；本批未处理该告警。S2 正式题集仍 36 题，原 S3 攻略库摘要不变，独立人工审核 0，正式新增验收 0。
