# S3 第二批：来源登记与12篇本地笔记

本批新增8篇实际使用说明，默认资料从4篇扩充到12篇；接通来源登记、原文/代码身份校验和片段证据开发回归。原4篇文件、S2评测及S3首批13题均保留，不覆盖旧成绩。S3整体仍在进行中。

## 新增内容

| 主题 | 可回答的实际问题 |
| --- | --- |
| 物种与形态标识 | formId、speciesId与全国编号如何区分，同名或地区形态先确认什么 |
| 招式版本与名称 | 朱紫候选如何筛选，为什么英文slug和候选列表不能证明比赛合法性 |
| 种族值与默认配置 | 图鉴种族值与实际能力的区别，等级/性格/EV/IV缺省值的含义 |
| 伤害计算问诊 | 哪些攻防配置、对手与招式条件需要确认 |
| 天气、场地与能力边界 | 已接入哪些输入，太晶、墙、强化等为什么不能声称已经计算 |
| 变化招式与区间 | 为什么Status招式没有直接伤害结果，区间为什么不是胜率 |
| 特性与道具回读 | 候选、保存输入、资源查询和实际计算假设如何区分 |
| 建议到确认保存 | 预览与写入的区别，取消、过期与并发编辑如何处理 |

新增内容是结合当前项目实现撰写的原创说明，外部参考只涉及[PokéAPI资源字段](https://pokeapi.co/docs/v2)和[Smogon伤害引擎接口](https://github.com/smogon/damage-calc)，没有复制外部攻略全文，也不提供当前热门阵容或赛事合法性结论。不是12篇经过独立人工审稿的战术研究；每篇明确标记待人工复核。

## 来源身份与使用方式

默认文件为 `src/main/resources/pokemon-guides/expanded-v1.json`，schemaVersion为2，资料集ID为 `local-guides-expanded-v1`。原 `index.json` 仍为兼容基线，可通过 `VIO_LOCAL_GUIDES_LOCATION=classpath:pokemon-guides/index.json` 切回。

扩充版每篇登记 `provenance`：

- `PROJECT_NOTE` 与 `ORIGINAL_NO_UPSTREAM_COPY`：项目原创说明，外部链接只作接口参考；不从“有一个URL”推断外部文章转载授权。
- 获取/核对日期、适用游戏/语言/赛制/规则、待人工审核状态。
- 外部参考的标题、发布方、链接、核对日期和引用用途。
- 支撑项目行为说明的仓库路径与UTF-8/LF源码摘要，共涉及5个实际实现文件。

加载器拒绝扩充版缺失来源、未知或声明为外部转载的类别、未来日期、危险URL、越界路径及格式错误摘要。此阶段只接受项目原创且待人工复核的明确状态；这不能识别伪报原创或错误的实际内容，仍需人工审稿。不提供自动批准或任意文章导入。

运行时验证登记格式；构建/CI命令验证代码依据的真实文件摘要，两者分别承担不同责任。源码摘要一致只能证明文件身份，不能证明每句文字都正确。以后依据文件变化时，应复查说明并创建新资料/评测版本，不能只刷新摘要就宣称旧结论继续有效。

```powershell
node tools/campus/audit-s3-corpus.mjs
```

原文与来源元数据共同参与文档版本和chunk身份。即使正文摘要不变，作者、来源或核对信息变化，也不能复用旧引用。旧schema1没有新增来源字段时，不改变原文档版本计算，避免仅升级DTO就使旧引用失效。

`GET /api/pokemon/guides/catalog` 返回加载的资料集ID、schema、文档数与文件摘要。评测先核对这个身份；后端实际加载12篇时，旧4篇评测器会明确拒绝使用错误语料，而不是悄悄换一套分母。长摘要继续留在接口/证据中，回答只显示原文位置、作者、日期和资料性质。

## 评测口径

新建独立 `evaluation/campus/s3/retrieval-expanded-dev.json`，固定24条开发案例：16条主题问题、8条无资料或范围不符问题。问题和相关片段是本批编写的种子标注，没有当作独立用户样本或人工验收。

除了前五片段的文档召回与首个相关文档排名，新增**种子证据覆盖率**：前五片段是否含指定来源中的原文字句。这样命中文档标题但没有返回所需段落时不能得分。标注不是穷尽的相关性判断，所以不把这个值直接叫作完整chunk Recall@5。

```powershell
node tools/campus/s3-retrieval.mjs http://127.0.0.1:18133/api artifacts/campus/s3-expansion/my-retrieval evaluation/campus/s3/retrieval-expanded-dev.json
```

每次使用新输出目录，逐条保存原文、排名、定位、失败和固定分母。后端索引身份、来源元数据与冻结文件不一致时不给召回成绩。旧S2来源检查默认仍只认可旧冻结来源；扩充版的模型来源核对必须显式提供新来源，不修改旧期望来掩盖差异。
