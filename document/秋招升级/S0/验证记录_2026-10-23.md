## 结论与证据类型

已固定范围、配置清单、三条用例和采集脚本。实际完成了新目录安装启动、真实 HTTP 账号/资料/队伍/计算验证，以及现有本地服务上的三条真实模型任务。**这份记录证明链路可执行，也记录了回答质量缺陷，不代表模型质量已经达标。**

配置清单见 [baseline.json](baseline.json)，固定输入见 [cases.json](cases.json)，精简真实运行结果见 [observations.json](observations.json)。完整事件、原始回答、构建日志保存在本机忽略目录 `artifacts/campus/s0/`。

必须区分：

- **独立源码副本**：不复制本地密钥、数据库、资料缓存、依赖目录和构建输出，重新安装编译，用占位 Key 只验证应用启动与非模型 API，不调用模型。
- **现有服务的真实模型任务**：访问本机 8123 端口，新建专用演示账号并调用实际 Run 接口，没有注入模型桩。该服务运行包版本与模型 ID 无法从现有接口确认，因此记录为 `unverified-*`，不能反推其使用了当前工作树或 baseline.json 中声明的模型。
- **离线/模拟测试**：用于验证配置、超时和错误边界；不能作为真实问答效果成绩。

## 冷启动、安装与异常

- 第一轮独立源码副本：重新执行两个 npm ci、前端构建、后端打包；新建 SQLite 与空 PokéAPI 缓存，注册登录、图鉴拉取、保存/回读队伍、实际计算、退出并重新登录后的资源回读通过。Maven 使用用户级下载仓库，因此明确不算空 Maven 仓库验收。证据：`artifacts/campus/s0/clean-room/`。

- 修正：POM 显式将 Maven Central 排在 Milestones 前；保留原兼容回退，不自动升级依赖。再次进行空 npm/Maven 仓库验证，最终结果按独立目录的 environment.json、report.json 和构建日志登记。
