# 公开资料准备与演示复现手册

日期：2026-10-30。目标是把资料准备、环境检查和演示入口写成可执行步骤；本批不启动服务、不调用模型，不将准备检查算作端到端或空机器安装验收。

## 1. 安装依赖

在项目根目录打开PowerShell，按README准备JDK21和Node20.x（至少20.19）或22.12及以上版本，正确设置`JAVA_HOME`。Node21.x及22.0～22.11不符合当前前端engines要求。先核对：

```powershell
Test-Path "$env:JAVA_HOME\bin\java.exe"
& "$env:JAVA_HOME\bin\java.exe" -version
node --version
npm --prefix vio-ai-agent-frontend ci
npm --prefix tools/pokemon-engine ci
New-Item -ItemType Directory -Force artifacts | Out-Null
```

检查工具只验证指定的Java及javac，不执行Maven，因此仍需确保`JAVA_HOME`指向同一JDK目录。已有后端运行时先确认归属，编译完成后再启动用于演示的版本；不要在隔离服务运行期间重新编译。

## 2. 准备固定公开资料

联网模式只请求PokéAPI的杰尼龟、雪妖女及各自物种资料，共4个固定HTTPS地址。禁止重定向，每个响应最多2MB、15秒超时、无自动重试；全部验证通过后才写入6个规范化缓存别名文件及清单。

```powershell
node tools/campus/prepare-demo-reference.mjs artifacts/demo-reference-v1
```

输出目录必须不存在，重复演练改用新的编号；不要删除旧记录来制造首次成功。该工具不接受任意URL，不读取账户、模型配置或API Key。清单有源URL、读取时间与摘要，但不证明资料实时性、配招合法性或当前阵容强度。

默认并发4个请求。如需要减少并发连接，可显式改用串行模式，并为这次独立实验使用新目录：

```powershell
node tools/campus/prepare-demo-reference.mjs artifacts/demo-reference-serial-v2 --serial
```

串行模式最多一个请求在途，仍是每个请求15秒、2MB、无自动重试，整轮请求等待上限约60秒（不含本地解析/调度开销）。它不保证解决网络故障，也不会复用上次失败实验的响应。失败时输出JSON，逐个固定URL记录已验证但未落盘或失败状态；只暴露白名单连接错误码，不输出底层错误消息、响应正文或代理凭据。`UND_ERR_CONNECT_TIMEOUT`表示连接阶段超时，`PUBLIC_RESOURCE_TIMEOUT`表示本工具等待超时，不能据此判断服务端限流、API Key或模型配置问题。

后续增加显式预算选项 `--timeout-ms 60000`，允许1～60000毫秒的整数，默认仍为15000毫秒；串行模式最多等待4个预算。失败报告增加阶段与已读字节数。单纯延长预算在本机仍不能保证直连成功。

**本机已验证的代理方式：**浏览器系统代理不会自动传给Node。已配置本机HTTP代理时，先检查当前Node支持代理开关，再显式选择代理地址（下列7897为本次实测端口，应以自己的设置为准）：

```powershell
node -p 'process.allowedNodeEnvironmentFlags.has("--use-env-proxy")'
node tools/campus/download-demo-via-proxy.mjs artifacts/demo-reference-proxy-v1 --proxy http://127.0.0.1:7897 --serial
```

检查应返回true；本次实测Node24.19.0。代理入口只接受不含用户名密码、路径或查询参数的本机HTTP代理，启动带`--use-env-proxy`的独立Node进程。它只传入必要系统路径和显式代理环境，隔离继承的代理、NODE_OPTIONS、TLS绕过及模型Key环境；保留Node默认TLS证书校验，不改系统设置、不自动寻找端口、不自动切换网络或重试。支持相同的`--timeout-ms`有界选项；不支持该Node开关时直接拒绝。

本机已完成[代理下载、导入和离线读取验证](公开资料代理下载与离线链路验证_2026-10-30.md)。如需无网络复现，也可直接使用归档的[公开资料包](evidence/network-proxy-download-v1/public-reference-bundle/manifest.json)所在目录，明确标注读取日期为2026-10-30，不能当作以后重新下载的结果。

如果请求失败，命令返回非零状态，且不会生成可用的半成品资料包。可以明确选择事先准备并验证过的公开缓存：

```powershell
$publicCache = 'D:\public-pokemon-cache' # 替换为你的公开宝可梦缓存目录
node tools/reference-cache.mjs export --cache "$publicCache" --pokemon 7,478 --out artifacts/demo-reference-from-cache-v1
```

将后续命令中的资料包路径改为实际选用目录。该路径只应指向宝可梦公开资源缓存，不是账户、聊天或模型配置目录。缓存模式保留原读取日期，不把导出时间冒充重新联网取得资料。

## 3. 只读预检

```powershell
node tools/campus/demo-readiness.mjs --bundle artifacts/demo-reference-v1 --java "$env:JAVA_HOME\bin\java.exe" --out artifacts/demo-readiness-v1.json
```

报告必须为新文件。当前报告格式为demo-readiness-v2：Node同时匹配前端项目声明、锁文件中的项目与Vite要求，已安装Vite的engine元数据也须与锁文件一致；不再用“主版本至少22”判断。范围解析仅支持明确的三段版本、>=、^和||，不认识的表达式或预发布版本保持未知并阻止通过，不冒充通用semver解析器。

同时检查Java21/javac21、Maven包装器、Vite和伤害引擎安装版本是否符合各自lock文件，以及六个资料文件与清单是否一致。缺少依赖、JDK不符、清单篡改或资料不全时返回2，报告和控制台的issues包含逐项修复提示；参数错误及已有报告拒绝不等同于该退出码。预检不自动执行安装、构建、启动或模型请求。ready=true只代表这些公开输入检查通过，不代表新机器安装或实际运行通过。

`ready:true`仅表示这些公开输入可供后续手动构建和登录检查。报告固定标记模型配置未读取/未探测、未构建、未启动应用、模型调用0；不能据此声称API Key有效、服务已经启动或问答质量通过。

## 4. 导入独立演示目录

```powershell
if (Test-Path artifacts/demo-runtime-v1) { throw '演示目录已存在，请使用新编号' }
New-Item -ItemType Directory artifacts/demo-runtime-v1 | Out-Null
node tools/reference-cache.mjs import --bundle artifacts/demo-reference-v1 --out artifacts/demo-runtime-v1/pokeapi --output artifacts/demo-import-v1.json
if ($LASTEXITCODE -ne 0) { throw '资料导入未通过，请先处理报告' }
```

资料包有`manifest.json`；导入后的`pokeapi`是应用缓存目录，两者用途不同。不要将个人账户或旧数据库复制到演示目录。

## 5. 独立启动入口

先按README完成本机模型配置，不在终端、录屏或文档中输出Key。项目默认入口保持3000/8123；演示入口使用13059/18259，并配置独立账户、历史、队伍和攻略文件。

在项目根目录启动后端（以下为手动操作，本批未执行）：

```powershell
$demoArgs = @(
  '--spring.profiles.active=local', '--server.address=127.0.0.1', '--server.port=18259',
  '--vio.http.cors.allowed-origins[0]=http://127.0.0.1:13059',
  '--vio.local-accounts.path=artifacts/demo-runtime-v1/accounts.sqlite',
  '--vio.local-history.path=artifacts/demo-runtime-v1/history.sqlite',
  '--vio.local-teams.path=artifacts/demo-runtime-v1/teams.sqlite',
  '--vio.local-guides.path=artifacts/demo-runtime-v1/guides.sqlite',
  '--vio.pokemon.reference.path=artifacts/demo-runtime-v1/pokeapi',
  '--vio.pokemon.reference.proxy=http://127.0.0.1:9',
  '--vio.local-accounts.enabled=true', '--vio.local-history.enabled=true',
  '--vio.security.oidc.enabled=false', '--vio.security.oidc.required=false',
  '--spring.ai.mcp.client.enabled=false', '--vio.tools.high-risk.enabled=false',
  '--vio.tools.search.enabled=false', '--vio.agent.v1.enabled=false',
  '--vio.run.durable-resume=false', '--vio.run.model-cache.enabled=false'
)
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.arguments=$($demoArgs -join ' ')"
```

上述示例使用`local`。若你按README配置的是DeepSeek，将第一项改为`--spring.profiles.active=local,deepseek`，并在登录后确认实际平台；不能把另一平台的历史运行当成本次结果。

另一终端：

```powershell
cd vio-ai-agent-frontend
npm run dev:demo
```

打开`http://127.0.0.1:13059/game-master`，创建专用账号；登录后核对实际平台、模型与运行版本。演示前确认两个端口空闲，不随意终止别人的进程；新Vite配置启用`strictPort`，占用时直接失败。

如需查看已构建前端，可在该目录执行`npm run build -- --config vite.demo.config.js`后使用`npm run preview:demo`。日常`npm run dev`仍使用原配置。演示结束在自己的两个终端按Ctrl+C退出。

## 6. 分镜、解说及异常说明

参照[本地演示脚本](本地演示脚本.md)录制3～5分钟，先说明事实资料、模型规划、确定性核对与确认保存的职责，再演示固定问题。保存任务使用当前专用队伍的真实编号。旧失败单独标注日期与源码版本，不剪接成当前版本的一次连续成功。

遇到偏差保留首次结果、用量和终态：缺资料就说明缺失；预览未确认不保存；取消或版本冲突要展示未写入。没有实际执行故障注入时，只能称“历史失败复盘”或“机制说明”。录屏后核对敏感信息、来源、预览差异、保存回读与字幕。
