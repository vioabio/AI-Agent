# S5：请求参数校验依赖与错误状态修复

已修复公开构建启动时缺少 Jakarta Bean Validation provider 的提示，并补齐校验异常的 HTTP 状态处理。新 JAR 启动和限定范围的回归通过，S5 继续进行。

## 检查结论与实现

原项目只有传递引入的校验 API，没有实现。Spring MVC 启动时无法取得 provider；同时全局异常处理器处理请求体、表单绑定和 ConstraintViolationException 时，没有设置 HTTP 错误状态，虽然响应体 code 为 1001，HTTP 仍可能是 200。

本批修改：

1. pom 引入 `spring-boot-starter-validation`，版本由现有 Spring Boot 3.5.16 管理，本次实际解析为 Hibernate Validator 8.0.3.Final，不另行固定或升级 Spring Boot。
2. 三类已有校验异常返回 HTTP 400，保留原 Result 响应体和 code 1001。
3. 补充 Spring MVC 原生 HandlerMethodValidationException 处理：参数不满足约束返回 400；返回值约束失败返回 500，避免把服务端实现问题误判成用户输入问题。该分支使用固定错误消息，不返回校验的参数值。

代码检查未发现当前生产 DTO 使用 `@Valid` / `@Validated`，现有账户等入口主要手动校验。本批没有批量改 DTO、替换领域规则或宣称所有请求已经获得注解保护；provider 是可用的基础能力，具体接口仍需显式声明约束和触发校验。其余非校验类全局异常的 HTTP 状态不在本批改动范围。

## 测试结果

从新的过滤公开源码目录执行三组定向测试，**15 项通过，0 失败、0 错误、0 跳过**：

- RequestValidationHttpTest：7 项新增测试，验证真实 provider 不是空实现、嵌套字段及缺失字段在写入前被拒绝、合法请求只写一次、表单错误、约束异常、原生方法参数和返回值校验。
- LocalAccountHttpTest：4 项，其中新增非法注册测试。缺失字段、短密码、25 个“密”字构成的 75 字节密码被拒绝，不创建会话；同一用户名随后仍可正常注册登录。
- LocalAccountServiceTest：4 项，继续验证已有账户哈希、恢复、密码和本地凭据规则。

校验测试控制器只位于 test 源码中，未新增生产接口。它验证 MVC 和全局异常处理器，不代表对所有真实业务 DTO 的完整覆盖。表单校验在本次 Spring MVC 中走 MethodArgumentNotValidException；传统 BindException 分支补上状态声明，但没有单独构造该旧分支的独立 HTTP 用例。

本批新增测试合计 8 项。未重跑历史 1306 项全量后端测试、Node 或前端测试，不累计或替代历史测试结果。
