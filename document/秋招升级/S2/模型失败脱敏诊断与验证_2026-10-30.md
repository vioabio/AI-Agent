# 模型失败脱敏诊断与验证

已为 ChatModel 边界增加结构化失败诊断，最终定向37项、用量兼容12项通过；固定4道开发题各2次，真实工程检查8/8。本轮没有复现真实模型失败，因此不能据此判断或回填上轮暂时性异常的HTTP状态、限流或服务根因。

## 记录方式

`ModelUsageLedger.calls[]` 增加可选 `failure` 字段，沿用 `model-usage-v1`，没有更改计数、Token、计费、预算、工具执行或事件顺序。新诊断版本为 `model-failure-diagnostic-v1`，字段固定如下：

| 字段 | 内容 |
| --- | --- |
| schemaVersion / scope | 固定诊断版本、ChatModel边界 |
| category | 固定类别，不使用任意异常类名或文本 |
| httpStatus | 可读取的400～599状态码，否则null |
| statusSource | typed HTTP异常、Spring AI固定状态前缀或无来源 |
| causeChainTruncated | 异常链深度超过8、循环或读取受限时标记 |

优先使用 Spring HTTP/WebClient 异常的类型化状态。Spring AI RetryUtils 有时只保留 `NNN - body` 字符串，此时仅在其指定异常类型中读取固定的前三位数字及分隔符，不解析或保存正文。其他任意异常消息中的“503”等不当作HTTP状态。没有保留原消息、响应正文、请求文本、Header、端点、异常对象、类名或堆栈到新诊断字段。

可区分认证、访问拒绝、支付要求、请求拒绝、限流、上游服务错误及HTTP超时；也可标记可见的DNS、连接、TLS、超时、传输、响应解码和请求编码问题。402只标记支付要求，不推断具体余额；未知状态的AI异常仍保持未知。类别提供异常链线索，不是独立验证的根因结论。

同步调用、流式订阅后错误、创建流时同步抛错与取消均接入。原异常仍交给原流程，不重试、不改变输出或权限；冻结或已结束的调用不被晚到错误覆盖。返回后被预算阻断的调用、调用前预算检查、外层超时触发的取消继续遵循原生命周期语义，不强行改成供应商故障。

失败调用诊断随终态事件的 `modelUsage` 留存；失败终态后不会额外追加 `usage` 事件。成功任务的用量/历史路径保持原样。本轮未新增前端诊断展示，前端用量摘要仍可消费旧格式；新字段可从原始事件和采集记录查看。没有做历史失败记录回填、跨重启失败历史持久化扩展或全项目日志管线改造。
