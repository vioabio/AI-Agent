# 三种工具配置与问答对照

本批建立隔离的纯模型、攻略检索、只读工具增强对照入口。相同问题、配置模型、默认采样参数、预算和源码身份分别采集，输出工程核对、原文匹配、调用/Token与耗时，并生成待人工填写的语义复核模板。它是后续S2质量对比的基础，不提前宣称问答准确率提升或完成保留集验收。

## 执行方式

新增EvaluationToolPolicy，进程配置vio.evaluation.tool-mode默认OFF，日常助手行为保留。非OFF必须显式local,evaluation，启用本地账号，关闭版本化主链、持久恢复、MCP和高风险工具；未知模式或缺少必须的工具直接失败。请求体和模型文本不能切换工具配置。

| 模式 | 本轮Run提供的工具 |
| --- | --- |
| MODEL_ONLY | 无工具，不使用MCP或本地能力介绍的零模型快捷路径 |
| GUIDES_ONLY | 只提供现有受治理的searchPokemonGuides |
| READ_ONLY_TOOLS | 攻略、图鉴、资源、整队参考、属性和伤害七项明确白名单 |

三组仍使用同一VioManus、ObservedChatModel、上下文/输出预算、任务用量和Run事件/历史链。不提供预览、确认保存、外部搜索或运营工具，不注入队伍工作流；模型返回未开放的写工具也不能执行该回调。未配置ChatModel时不会切到旧问答实现冒充同一实验。

注册清单runtime.tools保持兼容，实际子集由runtime.evaluationPolicy.effectiveTools标明。运行接口新增有限的temperature/topP/maxTokens默认值快照，不暴露原始Options对象、提示词或凭据。默认值身份不是供应商请求、部署权重或确定性输出的完整证明。

## 固定计划和核对

[独立开发计划](../../../evaluation/campus/ablation/README.md)含两个问题：种族值与项目填写默认值、修改预览与确认保存的关系。三种配置各一次，共6条计划；每题新会话，测试脚本不确认任何审批或修改队伍。问题与标签是AI辅助编写的项目来源题，不是独立用户样本。

采集与比较工具分别执行以下核对：

- 模式、工具子集、配置模型、参数、预算、源码/class及资料身份一致，MCP不参与。
- 原始事件和历史保存摘要；比较时重新读取，核对问题、流式正文、历史回答、实际工具事件和模型用量。
- 失败或未完成题目留在固定分母；参数/源码不一致时拒绝生成可比结论。
- 引文逐字匹配冻结原文，另列指定文档原文是否出现；这不证明引用语义相关或建议正确。
- 只有全部供应商用量完整才合计Token，缺失/部分用量为unknown；不凭Token生成未经账单核对的费用或降本比例。

工具可用性也会启用不同的程序事实/引用保护，所以本批比较的是完整管线配置，不是单独BM25或RAG的因果增益。仅有每组两题，不报告总体准确率、显著性、吞吐量或稳定P95结论。

`review-template.json`按模式、案例、观测摘要绑定具体答案，审核人、日期、逐项判定和依据保持空。自动匹配与工程核对不会代替人工填写；原S2保留集、S3资料/题目/标签及五个引用源码身份保持原样。

## 工程验证与开发失败

配置DashScope/qwen-plus，三组temperature=0、topP=1、供应商默认maxTokens未提供、应用输出预算1024一致。两个问题各执行一次，固定分母6条，工程检查6/6，共12次真实模型调用。三份采集各483项源码/依赖/脚本摘要与63项runtime class摘要核对一致；比较重新读取原事件与历史，没有混用不同代码版本。

| 配置 | 默认值题指定原文出现 | 流程题指定原文出现 | 两题模型调用 | 两题输入/输出Token |
| --- | --- | --- | ---: | --- |
| MODEL_ONLY | 否，无引文 | 否，无引文 | 4 | 5264 / 1379 |
| GUIDES_ONLY | 是，4段引文逐字匹配 | 否，未调用检索 | 4 | 9637 / 1197 |
| READ_ONLY_TOOLS | 是，4段引文逐字匹配 | 否，未调用检索 | 4 | 15527 / 1308 |

这两题中，更大的只读工具集合没有增加指定原文覆盖，输入Token更多；不能推广为其他任务的收益/费用结论。流程题在两种提供检索的配置下都未触发检索，是本轮明确发现的检索触发缺口。它仍计入固定计划，来源出现记为否，不改写问题来掩盖差异。下一步应针对项目流程/来源请求完善检索触发，再用保留原始失败的新版采集复测。

该缺口后续已按[项目流程来源检索修复](项目流程来源检索修复_2026-10-26.md)实施并用原题重新采集。此处旧表格和`evidence/ablation-v1/`保持原样；新版结果单列于`evidence/project-guide-v1/`，不将不同源码版本混成同一批比较，也不将程序检索当作模型自主检索。

原文匹配不是引用相关性或语义正确性的结论，六条人工审核均保持待完成。耗时逐条保留在[对照报告](evidence/ablation-v1/report.md)，不据两题推导稳定延迟分位数。紧凑证据包括[比较数据](evidence/ablation-v1/comparison.json)、[回答与来源](evidence/ablation-v1/answers.json)、[空白审核模板](evidence/ablation-v1/review-template.json)、[工程汇总](evidence/ablation-v1/verification-summary.json)。完整原始记录位于被忽略的artifacts/campus/ablation和artifacts/ablation-*.log。

后端完整回归1080项，0失败、0错误、3跳过，BUILD SUCCESS；新增策略/执行器/容器测试单独证明默认OFF兼容、模式门禁、无MCP、无隐式写回调及预算/用量接线。前端契约139项、Node工具86项通过；本批没有修改前端界面或重跑浏览器。

首轮全量暴露新增配置类遗漏Autowired构造器标记，造成47项上下文加载错误；修复后增加真实容器接线测试，再通过完整回归。Node报告测试曾因可选字段未提供时直接哈希undefined而失败，已将缺失值明确按null处理，同时保留身份检查；原失败日志不覆盖。

隔离启动也复现当前DashScope SDK的maxTokens配置绑定限制：其setMaxTokens方法签名无法作为正常Bean setter接收该值。未修改SDK或忽略绑定失败，改用项目现有vio.run.context-budget.output-tokens统一输出预算；供应商默认maxTokens仍按实际值记录，不能补写1024冒充默认值。temperature=0、topP=1仍显式保持一致。

既有Surefire fork退出等待、Bean Validation provider缺失及SLF4J多provider告警保留；3个跳过不当作通过。没有执行PostgreSQL、多实例或远端CI验收。

## 复现

先完成Maven测试。下方命令只启动MODEL_ONLY隔离实例；每组结束后停止自己的实例，切换MODE、端口和全新数据库目录再启动，保持其余参数不变。不要操作日常8123服务，也不要同时执行另一个Maven编译。

```powershell
.\mvnw.cmd -o test
node --test tools/reference-cache.test.mjs tools/campus/*.test.mjs
.\mvnw.cmd -o spring-boot:run '-Dspring-boot.run.arguments=--spring.profiles.active=local,evaluation --server.address=127.0.0.1 --server.port=18151 --vio.evaluation.tool-mode=MODEL_ONLY --vio.local-accounts.enabled=true --spring.ai.mcp.client.enabled=false --vio.tools.high-risk.enabled=false --vio.agent.v1.enabled=false --vio.run.durable-resume=false --vio.run.answer-streaming-enabled=true --spring.ai.dashscope.chat.options.temperature=0.0 --spring.ai.dashscope.chat.options.top-p=1.0 --vio.run.context-budget.output-tokens=1024 --vio.local-accounts.path=./tmp/ablation-model/accounts.sqlite --vio.local-history.path=./tmp/ablation-model/history.sqlite --vio.local-teams.path=./tmp/ablation-model/teams.sqlite --vio.local-guides.path=./tmp/ablation-model/guides.sqlite --vio.pokemon.reference.path=./tmp/ablation-model/pokeapi'
# 另一终端；输出必须是新目录。仅沿用本机已有模型配置，不要将Key写入命令或报告。
node tools/campus/s2-tool-ablation.mjs run http://127.0.0.1:18151/api MODEL_ONLY artifacts/campus/ablation/my-model
# GUIDES_ONLY使用18152、新目录；READ_ONLY_TOOLS使用18153、新目录，同样采集
node tools/campus/s2-tool-ablation.mjs compare artifacts/campus/ablation/my-model/capture.json artifacts/campus/ablation/my-guides/capture.json artifacts/campus/ablation/my-tools/capture.json artifacts/campus/ablation/my-comparison
```

默认纯模型配置不使用参考缓存；本批问题只涉及项目文档。若扩展到物种或伤害题，应先冻结并校验各组一致的公开参考数据，不能把联网可用性差异当成模型质量差异。

本轮18151、18152、18153隔离服务均已结束，日常8123实例未操作；私有配置未查看/复制，未提交、推送或部署。日常模式仍为OFF，新对照功能只在显式隔离配置下启用。
