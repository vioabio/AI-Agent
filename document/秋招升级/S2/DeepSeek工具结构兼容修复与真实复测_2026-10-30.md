## 问题与修复

Spring AI 生成的嵌套 DTO Schema 在局部 `$defs` 内定义类型，却使用根相对引用。DeepSeek 校验整份工具列表时，依次报告 `previewTeamChanges` 缺少 `StatChange`、`checkPokemonBuild` 缺少 `Stats`。模型尚未选择工具，请求就被 HTTP 400 拒绝，因此普通图鉴查询也受影响。Key、无工具请求和简单属性工具请求本身可用。

新增 `ToolSchemaReferences`，在本地工具注册、接入治理网关之前，展开生成器的局部类型引用，移除已展开定义。保留属性、必填列表、描述、工具元数据和原执行上下文；不修改 DTO，不代填参数，不改变权限、审批、保存或恢复策略。无引用工具原样返回。无法解析、远程或循环引用直接拒绝注册，并限制展开深度。现有伤害默认容器适配仍先执行。

运行时源码身份包含该适配器，采集器核对加载的 class 与公开工作区。最终529项源码/公开输入摘要与当前仓库逐项一致，采集前后源码及冻结题集均未变化。全部16个工具随请求发送的诊断已得到一次有效工具调用。

另为 S2 采集补充 `preflightTeamReferences`：按所选题目及其他账号前置队伍去重读取所需成员资料，核对身份、数据/游戏版本和六项数值。缺失时在创建队伍和调用模型前停止，保留未运行分母。此前缓存只准备杰尼龟和雪妖女，漏带题目所需的小火龙；已通过公开包校验补齐，保留原始抓取日期，不伪装成新下载。

`.run/` 已加入 Git 忽略。Key 仅从用户明确指定的本机运行配置传入子进程，未写入源码、启动参数或报告。归档候选已扫描，无该 Key 的完整值；提交前另外排除本地测试数据库，并修正文件清单，未改动原始观察。这项检查不替代仓库历史或所有凭据类型审计。
