# 资料预热、离线包与读取失败恢复

本批处理上一轮无缓存伤害回归暴露的资料读取超时：增加缓存预检、公开资料包导出与导入，统一预热脚本的代理选择，并修正伤害回答的故障提示。已验证导入缓存后的图鉴查询、HTTP伤害计算和一次真实模型的资料失败恢复回答。新增资料联网获取、独立策略审核与保留集对照仍待验证。

## 问题与改动

日常资料缓存目录旁有本地代理配置；新建的隔离缓存目录没有自动继承该文件。检查时配置的本地代理端口未监听，因此不能把问题只归因于模型或工具超时。本批不修改个人网络配置，不宣称已经修复上游可达性。

`tools/warm-pokemon-reference.ps1`增加`-Proxy`，依次选择显式参数、缓存目录同级的`pokeapi-network.properties`、系统网络设置；`direct`表示直连。它只接受不含认证信息的HTTP代理地址。完整且有效的缓存直接复用，不下载；不完整缓存只补缺项，损坏或冲突缓存保留并报错。脚本与后端使用相同的本地代理配置格式；本批没有改动后端的既有代理优先级。

`tools/reference-cache.mjs`提供三个无需网络的操作：

| 操作 | 行为 |
| --- | --- |
| inspect | 检查所选物种的Pokemon、species和名称/编号别名是否齐备 |
| export | 校验后导出公开快照和清单，可从有效Pokemon快照补齐别名 |
| import | 先验证清单、摘要、来源、资源身份和配对闭包，再写入新目录 |

选择参数限1～6个英文slug或编号。只读取固定命名的Pokemon/species JSON，不扫描账号、聊天、队伍或模型配置。校验固定PokéAPI源、资源身份、六项种族值、属性、特性、世代、抓取日期和正文摘要；拒绝路径穿越、超限文件、根目录/文件符号链接及冲突别名。该工具不是用于对抗不可信多用户并发修改文件系统的沙箱。

导出/导入目录必须尚不存在，禁止覆盖已有目录。全部输入验证通过后才创建目标目录；如果磁盘写入中断，保留不完整目标供检查，下次使用新的目录。`inspect`返回码0表示就绪、2表示未就绪，参数/文件操作错误返回1；不要把命令成功输出一段JSON理解为资料必然齐备。

`DamageAnswerEvidence`现在区分资料不可达、缓存校验失败、工具超时、参数/策略拒绝和其他工具失败，使用固定提示，不把异常正文、代理地址或内部路径放进回答。需要伤害计算时，前置资料工具失败也能触发资料恢复提示；成功重试后清除旧失败状态。资料连接失败不会再要求用户重复补齐已提供的培养配置，缺失有效结果时也不生成伤害数字。

## 日常操作

以下命令在项目根目录、具备Node.js的PowerShell中执行。预热联网需要当前可用网络；模型仍使用本机已有配置，资料包不包含任何API Key。

```powershell
# 先检查；如果目录或物种不存在，会明确返回未就绪
node tools/reference-cache.mjs inspect --cache .local-data/pokeapi --pokemon squirtle,charmander

# 有可用网络时预热；已有完整有效缓存时不会下载
.\tools\warm-pokemon-reference.ps1 -Query squirtle
.\tools\warm-pokemon-reference.ps1 -Query charmander
# 如需明确选择网络，可附加 -Proxy direct 或 -Proxy http://127.0.0.1:实际端口

# 目标目录必须是新目录；父目录需要存在
New-Item -ItemType Directory -Path tmp -Force | Out-Null
node tools/reference-cache.mjs export --cache .local-data/pokeapi --pokemon squirtle,charmander --out ./tmp/pokemon-reference-pack
node tools/reference-cache.mjs import --bundle ./tmp/pokemon-reference-pack --out ./tmp/demo-pokeapi
node tools/reference-cache.mjs inspect --cache ./tmp/demo-pokeapi --pokemon squirtle,charmander

# 使用导入目录启动后端，保留原有模型配置；先确认默认8123没有其他实例
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.arguments=--vio.pokemon.reference.path=./tmp/demo-pokeapi'
```

缓存无效时先保留文件并检查原因；从可信来源取得校验通过的资料包后导入新目录，再切换后端路径。不要直接覆盖日常缓存或篡改摘要/日期来跳过失败。若`DESTINATION_EXISTS`，换一个新目录名。

## 资料范围

本批真实包选择杰尼龟和小火龙，包含6份Pokemon/species快照，保留原始字节、来源、抓取时间和正文SHA。杰尼龟Pokemon抓取时间为2026-10-21，小火龙为2026-10-23；2026-10-26只是打包日期。完整日期和摘要见[清单](evidence/reference-cache-v1/bundle-manifest.json)。

这不是全部图鉴资源包，不包含所有招式/道具/特性详情或图片。未缓存资源仍可能联网；生成模型回答仍需要配置好的模型服务连接，不能据此称为完全离线Agent。快照摘要用于完整性和一致性核对，不是来源签名，也不保证数据新鲜度、赛制合法性或当前热门阵容。

## 复现故障恢复

先按上方步骤导出到新包目录，并将其导入新runtime目录下的`pokeapi`。完成Maven测试后，再启动独立服务；不要与Maven编译/测试并发运行。以下仅供隔离故障测试，端口1须确认未监听，不要用于日常启动：

```powershell
.\mvnw.cmd -o test
node --test tools/reference-cache.test.mjs tools/campus/*.test.mjs
.\mvnw.cmd -o spring-boot:run '-Dspring-boot.run.arguments=--server.address=127.0.0.1 --server.port=18148 --vio.run.answer-streaming-enabled=true --vio.local-accounts.path=./tmp/reference-runtime/accounts.sqlite --vio.local-history.path=./tmp/reference-runtime/history.sqlite --vio.local-teams.path=./tmp/reference-runtime/teams.sqlite --vio.local-guides.path=./tmp/reference-runtime/guides.sqlite --vio.pokemon.reference.path=./tmp/reference-runtime/pokeapi --vio.pokemon.reference.proxy=http://127.0.0.1:1'
# 另一终端；结果目录必须尚不存在。此命令会调用本机配置的真实模型。
node tools/campus/s2-reference-cache-scenario.mjs http://127.0.0.1:18148/api ./tmp/pokemon-reference-pack ./tmp/reference-runtime-check
```

本轮18148隔离服务已停止，日常8123实例未操作。S2题集/保留集、S3语料及原始来源源码、个人模型配置与原有缓存不变；未提交、推送或部署。后端代码修复需重启日常服务后生效。
