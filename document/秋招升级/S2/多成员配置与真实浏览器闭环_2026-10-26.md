# 多成员配置与真实浏览器闭环

本批继续S2的多成员/多字段验证，补充浏览器连接真实本地账号、模型、Run、审批与SQLite的专项入口。预览和保存回执新增“第N位”标识，方便区分修改对象。它补充上一批API fixture浏览器测试，不将模型选择工具或保存成功视为培养策略正确。

## 显示与执行边界

前端预览使用服务端已有的slot字段显示成员位置。正文回执由独立TeamChangePresentation适配：仅在实际结果为APPLIED、存在保存队伍且匹配原程序表格时加入位置；其他状态或未知回执格式保持原内容。DefaultRunExecutor和队伍结果接口使用同一适配，保证流式正文、最终回答、历史及接口回执一致。

适配只在核心工作流返回后发布一次完整回执，仍使用原Run、写入边界、用量账本、历史和偏好快照。它不发起第二次写入或模型调用，不改变候选、审批摘要、版本/归属或SQLite修订比较。核心TeamWorkflowService被S3笔记按源码摘要引用，故保持原始文件身份，不改写已发布引用。

## 多字段验证范围

HTTP集成矩阵增加两个案例：

- 第1位成员调整等级、性格、整组EV与单项IV；第2位调整招式列表并清空道具。预览仅包含六项变化，确认前原快照不变，确认后未指定字段保留，整队修订只增加1；重新打开SQLite可回读。
- 第1位变更有效、第2位EV总和超限时，整个任务拒绝，无预览、成功回答或部分写入。

最初使用重复形态测试数据被既有资源校验拒绝，随后改为杰尼龟和小火龙；没有放宽禁止重复形态的规则。HTTP测试执行器与事实仍为受控fixture，验证参数/工作流行为，不验证招式合法性或实际模型策略。

TeamChangePresentation另有回执位置区分、非成功/未知格式保持原内容、一次发布与上下文边界保留测试。同名显示是呈现测试用的合成数据，不是允许重复形态入队的声明。

## 真实浏览器入口

独立配置位于前端playwright.workflow-live.config.js，测试位于e2e-live/team-workflow.spec.js；不会混入默认API fixture套件。需要显式提供前端与后端两个loopback HTTP地址，禁止默认3000/8123端口、相同端口、外部地址、认证信息、查询参数与不匹配路径。原日常Vite配置不变，专项代理通过单独配置选择后端。

固定两个开发场景：1440px桌面端确认多成员六项修改，并刷新页面回读历史；390px手机端对同一组预览取消修改，保持原配置。注册使用专用随机测试账号，实际通过登录界面输入凭证、聊天界面发送问题和按钮提交决定。队伍初始数据由同源真实接口创建；所有API响应来自真实后端，没有page.route或伪造响应。

每条核对服务端预览、实际渲染的成员位置、确认前/后的完整队伍、唯一终态、消息/回执、审批恢复模型调用数及成功历史用量。登录凭证、Cookie与恢复码不存入记录；关闭trace、HAR、视频和登录失败截图，仅在登录后的预览/结果阶段截图。模型及接口元数据、公开测试内容、源码摘要和有限API路径/状态会保留。

只有这两个开发任务的全链行为被验证；不涵盖所有多成员问法、浏览器类型、真实上游网络故障、跨重启候选恢复或生产多实例。缓存来自已有公开快照，不当作新抓取资料；模型仍使用本机已配置的服务网络。

## 验证与保留失败

最终后端1071项，0失败、0错误、3跳过，BUILD SUCCESS；其中HTTP集成11项、原工作流13项、接口5项、呈现3项为重叠子集。前端139项契约、lint/typecheck/build、API fixture浏览器11项通过；Node工具81项通过。两条真实浏览器任务均通过，配置DashScope/qwen-plus，每条2次模型调用，审批恢复无新增调用。两条分别核对519项源码/依赖/脚本摘要与62项runtime class摘要，均与采集版本一致。

真实首轮两条均在“按钮须在可视区域”断言失败，未提交审批，清理时取消Run。根因是全局审批卡的flex-wrap:wrap在纵向预览中继承，长内容将操作区挤到裁剪范围外；已对队伍审批卡设nowrap，明细内部滚动，操作区保留。未放宽视口断言，新增桌面/手机密集长预览回归后11项通过，第二轮真实任务2/2通过。首轮与修复后日志、报告分别保留。

最终结果和原始日志摘要见[验证汇总](evidence/team-multi-v1/verification-summary.json)，真实浏览器记录见[运行摘要](evidence/team-multi-v1/live-report.json)。受控HTTP、API fixture浏览器与真实浏览器的结果分别统计，不能相加成模型准确率。

另外保留了两类失败：新增两个HTTP用例最初因重复形态被拒绝，改用两个不同形态；早期直接修改核心工作流导致两项S3来源审计失败，现恢复原始源码、通过独立呈现层实现显示。没有修改S2题集/保留集、S3语料、引用摘要或跳过失败测试。

原有Surefire fork退出等待、Bean Validation provider缺失与SLF4J多provider告警仍需单独处理。PostgreSQL与多实例环境未在本批验收，跳过项单列。

## 复现

项目根目录先执行Maven测试；它结束后再启动隔离服务。先按[资料包步骤](资料预热与离线包_2026-10-26.md)准备公开Pokemon/species包，并导入新目录。不要覆盖日常缓存或既有测试证据。

```powershell
.\mvnw.cmd -o test
node --test tools/reference-cache.test.mjs tools/campus/*.test.mjs
New-Item -ItemType Directory -Path tmp/multi-runtime -Force | Out-Null
node tools/reference-cache.mjs import --bundle ./tmp/pokemon-reference-pack --out ./tmp/multi-runtime/pokeapi
.\mvnw.cmd -o spring-boot:run '-Dspring-boot.run.arguments=--server.address=127.0.0.1 --server.port=18150 --vio.run.answer-streaming-enabled=true --vio.http.cors.allowed-origins[0]=http://127.0.0.1:3191 --vio.local-accounts.path=./tmp/multi-runtime/accounts.sqlite --vio.local-history.path=./tmp/multi-runtime/history.sqlite --vio.local-teams.path=./tmp/multi-runtime/teams.sqlite --vio.local-guides.path=./tmp/multi-runtime/guides.sqlite --vio.pokemon.reference.path=./tmp/multi-runtime/pokeapi'
# 另一终端，使用新证据目录；会调用真实模型并确认新建测试队伍的修改
cd vio-ai-agent-frontend
$env:N5_E2E_BASE_URL='http://127.0.0.1:3191'
$env:VIO_WORKFLOW_LIVE_API='http://127.0.0.1:18150/api'
$env:VIO_WORKFLOW_LIVE_OUTPUT='../artifacts/campus/team-multi/my-live-capture'
$env:N5_E2E_BROWSER_CHANNEL='msedge'
npx playwright test --config=playwright.workflow-live.config.js
```

专项浏览器目录独立，默认测试无需模型/后端。实际运行前保证选定端口空闲、数据库为专用新目录，测试结束关闭自己启动的服务。当前默认local候选仍只保存在进程内，不能批准跨重启的旧预览。
