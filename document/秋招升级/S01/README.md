# S0.1：回答证据约束与依赖修复

日期：2026-10-23。本阶段处理 S0 暴露的机制解释错误、运行身份不明与前端依赖告警；不替代 S1 队伍确认写入闭环或 S2 正式模型质量评测。

## 实现内容

### 完整队伍证据

新增只读工具 `lookupPokemonTeamReference`，一次接收 1～6 个不同的物种 slug/编号，在当前 Run 的资料版本下读取所有成员。不同名称指向同一形态也会拒绝；任一成员失败不返回部分成功的完整队伍证据。该工具不读取其他账号的保存队伍，也不修改队伍。

队伍工作区生成的提问增加可读的 `参考成员：squirtle、charmander` 清单。队伍分析发布前核对实际聚合工具返回的成员覆盖与版本；单只查询、用户粘贴的 JSON、工具错误文本都不能替代这份证据。缺少成员时明确提示补齐，不再继续生成整队结论。未携带清单的自由提问仍依赖模型识别成员，不能声称已经独立验证自然语言中的全部成员。

基础属性关系由现有属性计算器重新计算，程序直接展示名称、属性、速度种族值与防御弱点表。它只覆盖基础属性，不包括特性、道具、天气、太晶等修正，也不证明招式合法性或当前环境排名。

### 伤害结果由程序展示

只从实际 `calculateBattleDamage` 工具响应接收计算证据，检查引擎、版本、第九世代、资料版本、数值范围、HP、百分比一致性和双方输入配置。后续失败响应使旧证据失效。

伤害范围、百分比、HP、攻防等级、性格、特性、道具、EV/IV、招式与场地假设由程序直接排版。模型只能补充条件性建议，不能修改已展示的计算数字。伤害超过最大 HP 也不直接等同于必定击倒，未模拟的存活机制和其他条件仍需另外确认。

### 建议发布检查

受保护的队伍/计算流程先发布已核对的事实，模型建议在缓冲区生成，通过已知错误模式检查后才发布。已登记的天气、特性、属性、速度分级、性格误译、胜率/伤害数字等断言会被保守拦截，并提示用户继续核实。

这是针对已知风险的有限检查：可能拦住正确的事实复述，也不能识别所有改写、英文或新机制错误。它不是通用事实裁判，不宣称“消除幻觉”。普通问答维持原正文增量输出；受保护流程的建议部分按检查完成后成段发布，不展示未检查的逐字片段。

固定检查数据位于 [team-advice-guard.json](../../../evaluation/campus/s01/team-advice-guard.json)，包含 20 条程序回归样例；它们不是 20 次真实模型回答，也不能计算模型准确率。[damage-reference.json](../../../evaluation/campus/s01/damage-reference.json) 来自本地固定计算引擎的确定性结果，不是模型评测输出。

### 可核对的本地运行身份

新增本地登录后可访问的 `GET /api/chat/runtime`：返回活动 profile、配置中的模型平台/模型 ID、提示词版本、当前加载的核心 class 摘要、工具清单与部分功能开关。仅白名单字段输出，不返回 Key、Cookie、任意环境变量或配置文件正文；不在 prod/demo 启用。

供应商实际返回的模型身份标记为未核实。配置 ID 与供应商返回 ID 是不同证据，不据此声称已核实底层服务路由。

class 摘要来自当前 classpath 的资源字节，不是 JVM 内存字节码取证或整个构建包的签名。复查时应启动确定的构建，并避免在记录期间重编译或热替换该目录。

HTTP 采集脚本增加 `--s01`，读取 [cases.json](cases.json)，记录运行元数据及工具的实际结束状态；只有开始事件不能记为工具成功。原 S0 用例与失败记录保留，S0.1 的队伍输入和要求工具已经改变，因此不能直接宣传为同输入、同模型的统计提升。

## 依赖变更与复现

前端升级到 Vite 8.3.5 / Vue 插件 6.0.10，按官方入口迁移到 `@unhead/vue`；锁文件更新包含修复版 Handlebars 4.7.10。没有执行 `npm audit fix --force`。运行环境要求 Node.js `^20.19.0 || >=22.12.0`，本次使用 24.19.0。

用户正在运行的旧 Vite 占用 esbuild 文件，未停止该服务。采用独立源码目录重新 `npm ci` 验证新锁文件，再验证当前目录的构建与浏览器行为。旧进程不会因为磁盘依赖更新而自动完成构建工具迁移；使用新版本前应停止自己的前端进程，重新 `npm ci` 并启动。保留的旧锁定文件会在停止进程后的干净安装中清理。

```powershell
# 在项目根目录；先停止自己正在运行的前端，再安装
npm --prefix vio-ai-agent-frontend ci
npm --prefix vio-ai-agent-frontend run dev
```

后端也需要重启以加载新增工具和证据检查。Key 仍留在原有本机配置/环境，不需要发到聊天中。可沿用 README 的启动方式。

官方迁移与修复资料：[Vite 迁移](https://vite.dev/guide/migration)、[Unhead Vue 安装](https://unhead.unjs.io/docs/vue/head/guides/get-started/installation)、[Handlebars 安全公告一](https://github.com/advisories/GHSA-8r5x-fm3f-whwj)、[安全公告二](https://github.com/advisories/GHSA-p8wg-vrv2-v86f)。审计是当次依赖树的快照，不等于未来或所有生态的零漏洞证明。
